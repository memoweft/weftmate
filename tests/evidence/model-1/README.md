# MODEL-1 · 模型服务与输入区换模

一个地址和密钥现在对应一个模型服务，服务会自动查询全部聊天模型。输入区的星芒按钮直接打开菜单，点选型号后用于当前对话的下一条消息，并保存为新对话默认。正在回复的那一条保持原型号。

旧配置按同一规范地址和同一密钥归组；原型号、模型标识、对话引用和后台选择保留。密钥只在进程内比较，仍由原加密保管库保存。提交服务元数据前保存私有 `model-services-v1.before.json`，重复迁移不会重复建服务，写失败保留旧数据继续可用。该私有备份和运行数据均不在此证据目录。

`live-acceptance.json` 保留真实 Electron（桌面程序框架）与固定 DSH（助手运行时）的完成记录，结果为 `passed`：旧两条模型配置启动、合成一个服务、切到 B、下一条实际使用 B、保存默认、重启后选择保留且原凭据仍可读取。随后用同一真实 MiMo 密钥查询到 5 个聊天型号，菜单选 `mimo-v2.6-pro`，下一条真实请求即用该型号，实际推理 1 次。旧配置迁移与 B 型号请求使用合成模型服务，真实推理范围是这 1 次 MiMo 请求。

真实密钥从机器环境变量读取，仅由验收进程内的随机本机转发服务使用。测试宿主保存的是进程内生成的合成凭据，原样经现有加密保管库处理；真实 MiMo 密钥没有进入宿主配置、参数、截图或证据。合成目录与对话服务均只监听程序自己申请的随机端口，非聊天向量型号被过滤。

## 视觉依据与证据

`electron-{1200,480}-{light,dark}-{menu,services,editor,presets-open,interfaces-open}.png` 来自真实程序；`web-{390,360}-…` 来自共用远程网页。每个菜单和编辑器均有打开状态。`phone-standalone/` 包含手机单独使用及电脑连接模式的服务列表、编辑器、菜单和预设打开状态。

视觉依据为用户提供的 `controls-spec/components/{ModelPicker,Menu,IconButton,ToolRow}/README.md`、`controls-spec/tokens.json` 与 `bundle.css`，分别约束 ModelPicker（模型选择器）、Menu（菜单）、IconButton（图标按钮）和 ToolRow（工具行）。`spec-preview.png`、`spec-*-menu.png` 由原 ModelPicker 预览源码、令牌与控件样式原样渲染。`spec-comparison-*.png` 并排放置规范与真实程序。在线预览无法读取，因此采用其本机规范源码。

规范要求星芒、电脑按钮盒 32px／图标 18px、手机按钮盒 44px／图标 22px、右侧项目勾、单服务无标题、无选中底色、支持时才出现深度思考、底部添加服务。带字控件和菜单项的电脑字号为 13px／行高 18px，手机字号为 15px／行高 20px；32／18 与 44／22 表示按钮盒和图标尺寸，不表示字号。长目录在同一菜单展开全部模型搜索。

本次为现有视觉体系的局部扩展，以四组件规范和现有 `docs/PRODUCT.md` 为边界。中性颜色采用 opt-in palette（按组件显式启用的调色板），由 `design/tokens/tokens.json` 母版生成，应用于模型菜单、服务列表和编辑器；其它已有界面颜色保持。SVG（可缩放矢量图形）资产改动仅涉及 `model` 图标。仓库没有 `DESIGN.md`，依照仓库约定不另建额外设计记录流程。

## 最终视觉复核范围

最终复核结论为 `ship`（在下述范围内可交付），覆盖原列四项实质修正及保存按钮回归：

1. 编辑器带字按钮和菜单项：电脑高度 32px、字号 13px；手机高度 44px、字号 15px。手机关闭按钮触达区为 44px、图标为 22px。
2. 预设和接口选择菜单的当前项在右侧只显示一个项目 SVG 勾，触发按钮保留 chevron（下拉箭头）；当前项不加选中底色。
3. 手机单独使用与电脑连接模式的浮层使用中性色和 `blur(20px)`，浮层背后的文字不可读。
4. caption（说明文字）使用 12px 字号／16px 行高，已复核浅深主题的文字对比度至少为 4.5:1。

保存按钮回归已单独复核：编辑器 primary（主按钮）使用中性灰色。`ship` 只表示上述修正及保存按钮回归通过，不代表全软件视觉验收或原生系统栏验收通过。
