# MODEL-1 · 模型服务与输入区换模

一个地址和密钥现在对应一个模型服务，服务会自动查询全部聊天模型。输入区的星芒按钮直接打开菜单，点选型号后用于当前对话的下一条消息，并保存为新对话默认。正在回复的那一条保持原型号。

旧配置按同一规范地址和同一密钥归组；原型号、模型标识、对话引用和后台选择保留。密钥只在进程内比较，仍由原加密保管库保存。提交服务元数据前保存私有 `model-services-v1.before.json`，重复迁移不会重复建服务，写失败保留旧数据继续可用。该私有备份和运行数据均不在此证据目录。

`live-acceptance.json` 是真实 Electron（桌面程序框架）与固定 DSH（助手运行时）的完成记录：旧两条模型配置启动、合成一个服务、切到 B、下一条实际使用 B、保存默认、重启后原凭据仍可读取。随后用同一真实 MiMo 密钥查询到5个聊天型号，菜单选 `mimo-v2.6-pro`，下一条真实请求即用该型号，实际推理1次。

真实密钥从机器环境变量读取，仅由验收进程内的随机本机转发服务使用。测试宿主保存的是进程内生成的合成凭据，原样经现有加密保管库处理；真实 MiMo 密钥没有进入宿主配置、参数、截图或证据。合成目录与对话服务均只监听程序自己申请的随机端口，非聊天向量型号被过滤。

## 视觉依据与证据

`electron-{1200,480}-{light,dark}-{menu,services,editor,presets-open,interfaces-open}.png` 来自真实程序；`web-{390,360}-…` 来自共用远程网页。每个菜单和编辑器均有打开状态。`phone-standalone/` 包含手机单独使用及电脑连接模式的服务列表、编辑器、菜单和预设打开状态。

`spec-preview.png`、`spec-*-menu.png` 由用户提供的 ModelPicker（模型选择器）预览源码、令牌与控件样式原样渲染。`spec-comparison-*.png` 并排放置规范与真实程序。在线预览无法读取，因此采用其本机规范源码；没有另画一份替代设计。

规范要求星芒、32／18的电脑按钮、44／22的手机按钮、右侧项目勾、单服务无标题、无选中底色、支持时才出现深度思考、底部添加服务。长目录在同一菜单展开全部模型搜索。新菜单与编辑器使用中性浮层，其它已有界面颜色保持。

网页截图为浏览器视口，不能证明安卓系统栏或真实手机浏览器栏已经验收。本包不实现安卓与 Apple（苹果平台）的原生菜单；原生接线清单写入工作包交付结果。

## 验证入口

- `tests/integration/model-1-services-electron.mjs`：隔离真实程序、旧配置、菜单、下一条请求、重启及可选真实 MiMo。真实模型部分只在进程环境中提供密钥时运行。
- `tests/integration/model-1-phone-web.mjs`：合成手机服务、过滤、切换后请求型号、独立及电脑连接模式的页面与菜单。
- `tests/integration/model-1-spec-reference.mjs <规范目录>`：渲染用户原规范并生成并排图。
- `tests/model-service-catalog.test.ts`、`personal-model-services.test.ts`、`anthropic-model-service.test.ts`、`model-services-ui.test.ts`、`phone-model-services.test.ts`：目录、能力依据、迁移、缓存、失败回退、旧接口、运行中与冷会话换模、原生 Claude（模型服务）的协议适配及界面身份隔离。新测试可以在没有固定运行时的环境中运行。

本地只运行相关测试、类型检查与公开卫生检查；全量由本包的云端检查承担。最终修正、检查计数、原生桥验证和清理结果见工作包结果与 PR。
