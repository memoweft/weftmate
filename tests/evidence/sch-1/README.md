# SCH-1 定时与提醒验收

本包在真实 Electron（桌面程序框架）主程序、固定 DSH（助手运行时）与云端 MiMo 下验收。账号、宿主目录、模型代理端口均为隔离合成数据；实际 MiMo key（密钥）只在验收进程内，宿主使用合成代理凭据，没有读取日用保管库或操作日用宿主。

## 实现与验证

DSH 原生 schedule 负责持久事件、计时、事务和最新一次派发；WeftMate 适配当地日历规则、暂停状态、原对话执行与通知，不维护另一套计时器。后台执行走既有命令与审批；已保存的任务在建立时登录凭据到期后仍可执行，设备撤销仍拒绝执行。

- `node --test tests/personal-schedules.test.ts`：9/9，实际固定 DSH 的时区、一次性/周期、错过补一次、暂停/恢复/删除、立即运行、星期规则跨夏令时与缺失时刻续期；真实访问服务的 Cookie（会话凭据）/CSRF（跨站请求伪造）/账号隔离、登录到期继续、设备撤销与审批模式。
- 共享功能/生成资产/审批分类定向批次：48/48（包含当时8项）；审批与提问兼容批次39/39（包含当时6项SCH测试）；成果/项目/浏览器批次16/16（包含当时6项SCH测试）。批次存在重叠，不相加为独立用例总数。
- 原生审批桥13/13；桌面/生成资产批次13/13，包含真实 Electron 的既有按名称/角色交互回归。
- 首轮 CI 的旧布局替身缺少新挂载方法，已补齐共享夹具；无拥有会话时不发恢复请求。相关 UI（界面）/记忆/宿主模型测试63/63通过，不增加排除项。
- `npm run typecheck` 通过；合并最新 main 后重新运行手机共享资产生成与48项定向验证。完整根测试由 PR（拉取请求）CI（持续集成）执行。

运行真实验收：先将 Machine（系统级）`MIMO_API_KEY` 注入当前进程，再执行 `node tests/integration/sch-1-reminders.mjs`。脚本使用实际时间（65秒），停机跨过目标一分钟后启动，并再次启动核对不重复。仅测试进程可见密钥；不得把它写入命令行参数、文件或截图。

最终场景结果与数值用量见 [verification.json](verification.json)。截图由实际程序窗口采集；Windows 原生桌面源枚举在其他应用合成器忙时会挂起，因此最终脚本通过 Electron `webContents.capturePage` 直接捕获程序内容，使用软件渲染，采集超时单独记录，不改变功能检查。最终五组场景均通过，四张窗口截图均成功，见 verification.json；最后一次完整场景15个已报告请求估算 ¥0.01741088。

## 费用与边界

用量仅记录数值，不存请求或回复正文；费用按仓库 MiMo 预置单价计算，包含诊断与失败重跑，属于估算而非账单。累计数值汇总见 [costs.json](costs.json)，并写入本包 Orchestrator（编排器）结果文件；被中断且没有返回 usage（用量）的请求无法精确计价。

初轮修正了账号归属对象接线、原生持久消息的 surfaceOp（时间线追加标记），运行中插话创建提醒的回执绑定，以及验收脚本旧登录/按钮名称；周期任务曾因模型不确定适配能力而读取源码，现工具说明明确已安装能力并实测直接建立。截图源枚举与后台窗口截图的偶发挂起已换为最简单的原生窗口捕获方式。

手机管理界面由下一包实现；当前提供 HTTP（网络接口）通知列表，远程推送交 S3。没有验证移动端推送、系统真实唤醒或长期浸泡。原生 DSH 的派发与模型完成分开，保持其崩溃边界，不宣称外部副作用严格恰好一次。CI 没有预构建 DSH 外部夹具时，原生夹具测试明确跳过；纯访问服务/授权测试仍必须执行，本机9项全部运行通过。
