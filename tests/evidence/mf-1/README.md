# MF-1：即时可用的近期记忆

全部运行使用合成账号、独立临时目录和随机回环端口。没有操作本人日用程序、18186、8081、计划任务或模型参数。LAN（局域网）只用 `local-quality`，按编排规则持有占用锁；地址与密钥不进入证据。Core（记忆核心）在独立工作树开发，主目录没有切换。

测量先于实现：`before-mimo/`、`before-lan/` 为各五条真实模型形成时间线，`before-synthetic-single-corrected/` 为真实宿主队列与假模型的单槽测量。`before-synthetic-single/` 的初始夹具误用 GET 请求租约，未实际持槽，保留为无效试跑，不用于单槽结论。

| 已接受到模型开始 | 无固定延迟 | 每条约 20 秒 |
| 模型请求 | 3.1–8.3 秒 | 8.2–50.4 秒 |
| 返回到观测到落库及召回 | 约 0.2–0.3 秒，含轮询间隔 | 约 0.2–0.3 秒，含轮询间隔 |
| 首轮形成失败 | 0/5 | 0/5 |

这个小样本不能推翻 PF-1b 已保留的间歇失败。分阶段 instrumentation（测量插桩）见 `mf1-core-phases.py` 和 `phases-*/core-phases.jsonl`：只计时编译与落库，不改变数据或模型结果。改前一次解析/校验 1.67ms、事务应用 18.27ms；改后一次分别 2.79ms、18.26ms。模型时延存在波动，不能把两轮差异都归因于代码。

实现选择：

- Core 每轮接受后立即唤醒形成，取消本地固定 20 秒等待。
- 从已接受的 Evidence（原始证据）只读提供近期原话，明确标为「近期原话，尚未整理」。它与正式 World（已形成记忆）分开，不伪造正式项或正式采用标签。沿用目标模型权限与遗忘路径，没有额外原话缓存。
- 只取相关原话及可确定的纠正前文；最近 24 小时、32 个已接受回合内，最多 4 组/800 字符，每组最多含一条纠正前文，宿主仍共用 6 项/1,200 字符总预算。整条放不下即省略，不截断事实。形成成功自动由正式项替换。
- 现有一次 rewrite（纠错重试）覆盖 `model_no_change`；错误原因和首轮响应保留在原有持久检查点。非法 JSON（结构化数据）或缺少关系端点反馈明确要求完整来源与 `target_entity`，不猜字段或无依据修补。
- 默认召回继续 0 等待。单槽形成尚未完成时可取消本次推理，让聊天先运行，空闲后用相同输入重新推理；只给 Core 完整结果。已取消推理的缺失用量不当作免费。云端与多槽路径保持并行。
- 主题/表达/称呼在同一个 Core 只读事务里取得，避免形成恰好完成时拼出混合版本。权限变更、遗忘和删除会话后，Core 的既有请求重放缓存同步失效；同一请求 ID 不能拿回已经撤回的原话。

`single-slot-preemption/` 中聊天到达至获槽 8ms；第一次形成被取消，聊天完成后 5ms 开始下一次形成，最终正式落库。单槽取消依赖服务响应客户端断开；真实 8081 未测、更未修改。持续繁忙时建议把形成模型配置到独立服务，但本包不修改本人配置。

原四题、C 三题均使用原运行器、原话与原语义判据，**没有开启 330 秒形成等待**。原 `memory_used` 与 C 的正式项来源核验仍保持原样：它们要求回复请求当时已有正式项，因此会把正确使用近期原话的回答记为失败。报告并列保留原检查与语义/实际模型输入证据，不能用后者覆盖前者。`default-matrix/` 是开发中首轮，其中 MiMo 数字比例纠正失败促成通用数值前文关联修复；所有失败原件保留。

PF-1b 的默认模式原四题行为两边均 0/4，原 330 秒等待协议的 C 成绩均 2/3。这里没有把近期原话伪装成正式对象，也没有事后用已形成的对象补写原回复的采用记录。实际请求里的桥接文本、原回复、原判据和旧检查失败见 `scorecard.json` 与各批原件。MiMo 最终 C 骑行/单车同义召回失败保留；LAN 该题在本轮采用桥接原话而通过，不宣称已补全正式召回的同义匹配。
