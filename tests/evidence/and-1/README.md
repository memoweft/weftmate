# AND-1：安卓系统栏沉浸与实际主题

使用独立包 `com.memoweft.weftmate.mobile.and1`、MuMu（安卓模拟器）Android 15、合成账户和随机端口。没有覆盖或卸载正式包，没有请求 8081 / 18186，没有复制本人截图。修复前和修复后都是本包重新产生的原始整屏 PNG（图片文件），包含系统栏。

**[带取样框、逐张数值的审阅页](index.html)** · **[完整色差表](color-table.md)** · [机器可读测量](measurements.json) · [原生备用界面测量](native-measurements.json)。标注叠在审阅页上，图像文件保留原始像素。

修复前的合成复现：[系统浅色／页面深色，白色状态栏](before-dark-page-light-native.png)，状态栏均值 `255 / 255 / 255`，页面表面 `38 / 39 / 35`，ΔRGB（红绿蓝均方根颜色差） **217.67**，自动检查失败。修复后 48 张原生整屏，ΔRGB **0.00–4.60**，阈值 18；图标跟随实际页面。取样使用真实 `WindowInsets`（窗口安全区）中的 31px 状态栏高度，中部 25%–75% 宽，避开左右的时间、信号、电量。

**根因与修复路径**

原生只按 `display-settings` 的账户偏好设置系统栏，`applyTheme()` 与运行中的 `theme.system` 路径直接改变页面；页面没有把实际呈现主题送回原生。旧壳把 WebView（网页视图）挤到系统栏下方，顶部内边距露出原生背景；`targetSdk 35`（目标安卓接口版本 35）又不能依赖 `statusBarColor`。这组真实壳的合成复现可稳定制造本人指出的白栏／深色错位；截图本身没有原生偏好元数据，不把具体原账户的存储值当作已取证事实。

现在页面绘制到透明系统栏之后，内容按安全区留白；真实 `settings.appearance.effectiveDark` 报告和偏好读写走界面线程，不排在连接请求后。账户进入／注销、运行中切换、系统变化与前台恢复统一读实际偏好。显式浅深与跟随系统的启动窗口／闪屏资源分别提供；31+ 跟随系统清除固定应用夜间覆盖。29+ 关闭自动 `Force Dark`（强制深色）。原生 `R.color.wm_web_surface_*` 与备用界面表面色从手机表面令牌生成，颜色一致性测试保护唯一来源。

原生壳的真实主题桥、真实偏好存储、两个合成账户、窗口和输入法均实际运行；对话、动态、目标等内容使用仓库既有合成宿主投影，不发送模型请求。资料读取的模拟不替代主题桥。文件预览使用合成文本；图片画廊使用真实共用组件和合成画布图片。
