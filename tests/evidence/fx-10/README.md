## 找到的延迟和修复

1. 新建回执和发送后运行状态分别等6秒完整刷新。完整刷新又串行读取宿主、模型、会话、任务和历史。停止原来只看会话列表running，即使已有真实turn.started，界面仍可能显示“尚无结束记录”。现在当前历史和未确认原请求回执独立刷新，采用原生回合事件显示停止，不把排队或仅已受理当成运行；新会话首条投递不等完整旧会话列表。
2. 快速链若连带读取所有任务/提问等诊断，后半段仍超过2秒。因此最终只读当前历史和未确认回执，诊断继续按原周期。回执查询替换旧pending命令快照，避免投递继续读取过时状态。
3. 会话列表反复为每个会话读取整份原生列表，绑定解析又重复读取一次。最终一次原生快照同时供描述及只读绑定解析，执行前仍读新鲜状态并走原授权。中间版本列表p95约11.89秒，最终完整压力列表p95 3.04秒、最大4.18秒；停止链已与它脱离。src/main.mjs仅增加可选快照参数，没有改账号执行归属或模型路由。GET /sessions增加可选snapshotAt服务端起读时刻，使新原生事件可领先旧快照，同时保留新快照确认空闲后的“尚无结束记录”语义；契约已登记。
4. 等待期间D35进展行保留已完成工具计数并显示真实阶段。审批/正在运行的步骤不冒充模型等待；秒数及详情更新复用摘要DOM（文档对象模型）节点，保留展开、焦点和滚动目标。
