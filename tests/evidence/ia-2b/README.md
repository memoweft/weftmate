## 2.5 D33 清理

复现：`node tests/integration/ia-2b-erasure.mjs`。真实 Electron（桌面程序框架）、固定 DSH（助手运行时）、真实 Core（记忆核心）与 MiMo；合成账户、系统临时目录及随机端口。Core 记忆是确定性植入夹具，原生消息和回复来自真实 MiMo，不声称验证模型形成。

`2.5-erasure.json`：默认保留原话，DSH 原生上下文替换屏蔽后仍能继续对话；勾选删除后主对话结果摘要、旁聊来源、交接资料、命令副本、搜索内容清除。新备份107文件的原始字节、全部 Zstandard（压缩格式）日志帧、SQLite（嵌入式数据库）36张表及字节块均0命中。真实重启后不复活。`2.5-electron.png` 为该宿主截图，主对话界面由 IA-3 接入，本包未修改布局。

`2.5-erasure-failure.json` 保留开发时未扩展来源清除字段校验导致的失败及该轮用量；之后补齐校验并复验成功。全部失败和成功请求另汇总至用量文件。

定向测试覆盖来源删除、混合摘要弃用、倒序原生摘要节点、在途索引读取失效、原生生命周期、Core 清理日志及 M3-A 离线代次。离线不可达设备需重连应用删除水位；过去备份及用户导出文件仍沿原契约边界。遗忘时混合派生资料无法精确确定来源则整份弃用；聊天原文是否删除仍由 D33 选项决定。

## 2.4 原生接力

复现：`node tests/integration/ia-2b-relay.mjs`。`2.4-relay.json` 记录真实程序中14轮长历史触发两次接力、三个原生段，使用现有原生研究压力压缩策略，没有修改阈值或模拟压缩结果。首段搜索可找到、主对话身份保持，重启后新输入沿当前段，原请求重放保持旧段回执。接着遗忘首段「蓝色纸船」，新备份108文件及7个解压帧0命中，三个段保留，清理后发送成功。该专项没有开启Core形成；真实Core删除与数据库全表取证见2.5。

`tests/ia-2b-relay.test.ts` 另覆盖真实HTTP（网络接口）命令与存储：首条逻辑附件暂存、并发同请求去重、接力期间持久待发、摘要失败继续旧段、创建响应丢失后关闭/重开宿主并复用已分配目标、忙碌边界延后。原生接缝夹具覆盖非单调surface（模型上下文视图）顺序、真实路由配置、未完成待办、隐藏块排除和一次性注入。实际压缩用固定DSH完成，没有修改vendor（运行时依赖）。

`2.4-failure.json` 保留开发失败：先修复重启后路由取值，再接入预设隔离作用域内的原生压缩引擎。早期超出旧请求字节上限的长消息夹具已缩小到契约内，不提高产品预算。所有试跑均计入 `usage.json`。主对话桌面/手机布局、虚拟滚动及客户端界面消费仍由IA-3/4/5负责。
