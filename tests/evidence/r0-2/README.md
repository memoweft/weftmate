# R0-2 系统状态与修复验收

复跑：`node tests/integration/r0-2-electron.mjs`。只更新浏览器手机截图可加 `--mobile-only`，仍会重跑组件与导出断言并保留已有桌面图片清单。运行器原子取得一个重活名额，结束或失败都释放；只启动隔离的 Electron（桌面程序）与 Chromium（浏览器），不控制本人桌面。

桌面截图来自生产 `createPersonalDesktop`、预加载桥接、设置组件、`createPersonalAccessService` 和 `createSystemStatusManager`。测试替身只替换组件拥有者与原生保存对话框；没有拦截页面状态响应或伪造页面数据。合成账号、随机端口、临时目录，真实模型请求 0。

五种故障先在组件侧制造，再读取实际状态，点击“修复”，确认只调用目标组件的恢复函数：

- 对话与工具、记忆、远程连接：各自独立的随机端口 HTTP 服务被停止，生产状态管理器的读取函数实际请求失败；各自恢复时只重新启动自己的服务。
- 回复模型：停掉合成模型入口，地址实际无法连接；修复仍失败，显示下一步并实际跳转模型设置。测试没有生成回复。
- 安全连接：临时目录换入一张签名正确、已过期的合成 X.509（数字证书）。生产 `certificateInfo` 解析它；修复换入有效的合成证书，其他组件保持不变。

这验证真实界面的状态、进度、恢复、跳转与隔离，不代表已连接真实 DSH（运行时）、真实记忆核心、真实远程隧道或真实证书签发机构。组件各自的原生自动恢复由既有机制负责。本夹具另验证记忆拥有者在读取前自动重连的展示行为；不把此夹具说成真实记忆子进程验收。

文件命名：`electron-{1200|480}-{light|dark}-{状态}.png`；包含正常、运行记录与指标、每个组件故障、恢复或下一步、诊断包包含内容预览。`acceptance.json` 记录检查结果与文件清单。原生保存对话框返回合成路径，导出通过真实桌面桥接并核对压缩包的六个固定文件。

隐私扫描在合成目录放入对话、记忆、密钥与登录凭据四个唯一标记，也把它们交给运行记录写入接口。导出后解压每一个文件，再逐个查找这些标记；`acceptance.json` 的 `sensitiveMarkerHits` 必须为 0。生产投影应丢弃这些字段，不把整个数据目录加入诊断包。

手机截图是实际手机界面在浏览器里的 `360×780` / `390×844` 视口：`mobile-browser-{360|390}-{light|dark}-{status|metrics}.png`。它们验证五项只读状态与三项指标，页面没有修复或诊断包导出控件。

以上浏览器图片没有系统栏，不作为 Android（安卓）/ Apple（苹果）原生整屏证据。Android 的真实整屏补验见下面的原生记录；Apple 的原生整屏与底部导航仍需补充。本包遵守不改原生壳、不控制本人桌面的边界。

崩溃记录复用 DIAG-1：本夹具用未写入正常退出的本地运行标记验证“上次没有正常退出”的入口与运行记录；原生崩溃转储保存在本地的验证见 `tests/evidence/diag-1/`，本包不复制转储。

截图仅包含合成账号与合成电脑名称。不复制私有产品参考截图，不公开临时目录绝对路径、本人机器名称或用户名。

## Android 原生整屏补验

复跑：`node tests/integration/r0-2-android.mjs`。复用现有 Android（安卓）壳及当前手机页面，用隔离包 `com.memoweft.weftmate.mobile.r02` 和临时目录中的 instrumentation（仪器测试）探针验收；没有修改原生源码或版本号。实测 Android 15，现有 APK（安卓安装包）版本 `0.8.28` / `41`，真实模型请求 0，仪器测试 1 项通过。原生登录连接随机端口的合成账号，状态与指标经生产状态管理器及既有 `/personal/v1/system` 读取；指标数值来自合成提供者。

12 张图片均为 `adb exec-out screencap -p` 得到的原始整屏图，已逐张查看。命名为 `android-native-{360|390}-{light|dark}-{status|metrics|model-unreachable}.png`，覆盖 `360×780` / `390×844` 浅深四组。`status` 显示正常状态与按意思查找，`metrics` 显示三项指标，`model-unreachable` 显示回复模型有问题及电脑上的下一步；手机没有修复、重启或诊断包导出按钮。截图与报告不含对话正文、记忆内容、密钥或登录凭据；测试密码只用于临时隔离登录，没有写入公开证据。

顶部是真实系统状态栏：12 张图片的系统栏背景与页面顶栏 RGB（红绿蓝颜色值）色差均为 **0**，没有横向溢出。逐图的系统版本、页面主题、原生深浅状态、系统安全区和色差见 `android-native-report.json`；运行时的系统夜间模式也单独记录。**底部导航区域尚未验收**：MuMu 的 `qemu.hw.mainkeys=1`，底部原生安全区为 0；已经检查没有沉浸模式隐藏规则，标准三按钮系统导航覆盖层本来就已启用。没有画虚假系统栏、修改硬件按键配置或重启模拟器；需真实设备，或另外安排模拟器硬件按键配置与重启后补验。因此报告保留 `nativeSystemBarsComplete:false`，不能把顶部通过称为上下系统栏全部通过。
