# AND-8 · 安卓原生健康

底部第三项「健康」进入 Jetpack Compose（安卓声明式界面）主页。日期前后／回今天、月历、刷新、今日解读及依据、恢复／睡眠／负荷、压力／电能／体能年龄、五项身体指标、睡眠分期、活动与运动记录、本月点阵、各项详情、指标趋势／7／14／30／60天、深夜使用叠加、提醒及按需 AI（人工智能）分析均由原生界面呈现。图形为 Compose Canvas（原生绘图），没有嵌入网页图表；公式、分数、基线、分期和趋势使用既有 `/personal/v1` 回执，没有在客户端另算健康分数。

无身体数据时，保留现有网页的「把身体的变化放在一起看看」、iPhone（苹果手机）接入说明与三张明确标为「示意」的卡片，不报故障。手机独立身份进入同一说明，不读取电脑健康接口。读失败与正常空状态分开，前者说明原因并提供重试，已有记录时继续显示上一次的内容；附属记录读失败不把缺测补成零。日期／账号变化丢弃旧回执，退出后清空原生展示；不新建本机健康数据库。

「接着问它」与各项的「问一问」将健康内容带到现有主对话草稿，保留原草稿，只引用、不发送。建议提醒沿原有鉴权与幂等请求，只有本人明确点按才创建；单项分析沿现有设置开关、按需生成、当日缓存和限额，不在读取主页时预生成。

指标与天数使用 AND-6 的 `NativeFilterRow.kt`，始终一排直接点，溢出横向滚动；没有下拉呈现开关。所有颜色来自 `DesignTokens.kt`。新增的健康色常量由共享 `design/tokens/tokens.json` 已存在的健康令牌生成；只在 `scripts/generate-tokens.mjs` 的 Kotlin（安卓语言）产物映射补两行，没有改网页或配色源。浅色以实际旧壳网页为准；深色页面、卡片、固定导航和工具面板取现有中性灰磨砂原生令牌。

时长统一写成「7 小时 46 分」「1 小时 30 分」，保留真实零值「0 分」和缺测「—」。这是任务指定的故意改进，并排图单独说明；没有改变睡眠条、趋势基线带或活动点阵的设计。

「原网页详情」为可选完整入口，打开当前日期、当前指标与详情／趋势模式；已迁移的内容不依赖它。设置仍由设置包迁移，真实 iPhone 健康采集与 Android（安卓）健康来源属于其他包。没有新增业务路由、系统权限、依赖或版本号；需要新壳版本，因为加入健康原生页面。

## 验证与证据

沿 AND-6 的 `native-run.mjs`／仪器化流程、`pairs.py` 和系统栏取样方法。全部账号、电脑、健康记录均为合成数据，健康分数来自生产计算函数。原网页对照通过实际 `HybridActivity`，同一账号、同样数据、同一主题。只安装 `com.memoweft.weftmate.mobile.and8qa` 与其测试包，保留已有默认调试包；从 `MuMuManager.exe info -v 0` 获取实际调试地址，使用本包随机端口的私有 ADB（安卓调试桥）服务与随机反向映射。

- `jvm-results.json`：33项／0失败；健康时长／日期／缺测／历史窗口／曲线路径与引用，以及业务路由与客户端路由自动比对。令牌生成与安卓路由的 Node（脚本运行时）测试另10项／0失败，类型与公开卫生检查通过。
- `native-report.json`：360／390浅深四组完整主路全部通过、实际操作与请求清单；日期、各项详情、趋势／叠加、提醒、分析缓存、准确原网页入口、引用不发送、空／加载／读失败／重试、旧日期回执丢弃与手机单独使用均有断言。每次持有模拟器锁和一个重活名额，结束或失败都卸载本包、撤销自己映射、断开私有服务并释放锁。
- `diagnostic-*.txt`：入口测试时钟／状态读取、字体测试的嵌套滚动定位与一次运行器中断诊断，不计入通过。
- `comparison-report.json`：最终样式的四组浅深、360／390对照取证；与完整主路分开记录。
- `font-scale-report.json`：仅本包应用配置的390深色字体1.3，对照取证流程通过；图表标注用原生文字测量与字号，另有趋势下方控件与分析依据的整屏图。此轮只验证对照流程，不算第五组完整主路；没有改变系统字体或模拟器设置，早期诊断不计入通过。
- `pairs.html`、`pairs/`：原网页左、原生右的关键状态浅深对照，每组写「一致／故意更好／还差」。
- `system-bars.json`：系统 Android 15、保持系统深色设置、页面浅深独立验证，185张整屏逐张状态栏与页顶背景取样，最大每通道差0。

物理整屏为720×1280，360／390是独立包的逻辑宽度，分别为360×640／390×693；没有改模拟器尺寸或设置，不当成360×780／390×844真机图。此实例底部系统手势区不可见；本人真机需确认底部手势区、字体放大、图表点选与横向指标筛选，以及真实健康来源接入后读取。完整云端测试在 PR（拉取请求）检查里记录，本地只跑本包相关测试。
