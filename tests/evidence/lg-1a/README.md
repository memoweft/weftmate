# LG-1a 登录与设备验收

复现命令：

```powershell
node tests/integration/lg-1a-login-devices.mjs --cloud-smoke
node tests/integration/lg-1a-login-devices.mjs
node tests/integration/lg-1a-login-devices.mjs --logout-recovery-smoke
node tests/integration/lg-1a-login-devices.mjs --visual-smoke
```

脚本使用真实 `services/cloud/src/main.mjs` 子进程、Playwright（界面自动化工具）`_electron.launch` 启动仓库入口 `.`，以及独立 Chromium（浏览器）上下文作为第二台设备。宿主端口随机分配，Electron（桌面程序框架）用户目录是系统临时目录；云 SQLite（嵌入式数据库）与 file transport（文件邮件传输）都位于另一个隔离临时目录。只使用随机生成的 `example.com` 合成账号，密码及令牌只留在进程内，没有模型操作。

Windows（视窗系统）使用 WSL（Windows 的 Linux 子系统）Ubuntu 的 Node 24.21.0。默认可执行文件为 `/tmp/weftmate-s1d-node/bin/node`，可用 `WEFTMATE_LG1_WSL_NODE` 指向已有 Node 24；发行版可用 `WEFTMATE_LG1_WSL_DISTRO` 覆盖。此机的 WSL 回环转发未启用，测试创建 Windows 随机回环端口到 Linux（操作系统）监听端口的字节桥，保持固定回环 issuer（身份发行者）和原始请求不变。file 邮件经 `\\wsl.localhost\Ubuntu\tmp\…` 读取。测试结束关闭本次进程并删除本次临时目录，不操作日用数据。

`cloud-smoke.json` 是真实云入口健康检查、注册发送验证码与文件邮件读取的结果。`verification.json` 是完整界面流程的结果；只有其中 `passed: true` 才表示完整验收通过。截图只含合成账号，名称中的 `desktop` 表示真实桌面程序页面，`web` 表示第二网页设备，`light` / `dark` 表示浅色 / 深色。

完整脚本验证注册与自动绑定本机、刷新后记住设备、第二网页登录及邮件确认、等待内容批准、电脑允许、两端设备列表与改名、换绑邮箱与重新登录、退出其他设备、找回密码与邮箱预填、注销后的本机离线登录。云授权请求直接走真实服务，脚本断言授权开始、登录、恢复、令牌、设备改名、换绑、退出其他设备和注销的成功响应；不替换产品请求或返回合成业务响应。元素按可见名称与角色查找。

补充覆盖包括 App（应用程序）内服务条款与隐私政策阅读、密码显示 / 隐藏、验证码重发倒计时、电脑「连接」的真实 `/hosts/connect` 请求、网页设备改名、第三台设备被拒绝后无法访问内容及从云目录移除、电脑退出后换新密钥重新确认并用本机独立离线密码批准。注销后的断言直接检查宿主 Cookie（会话凭据）已不存在，系统加密存储中的云凭据已删除，再用保留的本机应急密码登录。

配对二维码刷新使用真实组件和真实 `/cloud/pairings`（201）响应：安装 Playwright Clock（自动化时钟），等二维码完成并安装 120,000 毫秒计时器，再快进 120,100 毫秒，检查第二次请求成功且配对材料不同。快进期间把 UTC（世界协调时间）固定在实际时间以保持 DPoP（设备密钥持有证明）的 `iat` 有效，随后恢复实际时钟；云进程的时间始终是真实时间。这个验证覆盖客户端的两分钟刷新行为，服务端材料过期仍由服务端契约测试覆盖。

可信交付由真实桌面批准后显示的材料经进程内测试通道交给实际等待网页；接收端执行产品验签与身份 / 指纹检查。为了让交付动作先于网页自动进入，测试只短暂延后真实 `/auth/cloud-session` 请求，不伪造响应。交付码、配对码、验证码、密码、令牌都不写报告或截图；失败截图同样清空验证码、配对材料和可信交付材料并隐藏对应二维码。

早期把所有操作放在同一账号的连续流程发送了六封验证码邮件，达到云服务真实邮件限速；`desktop-login-rate-limit-light.png` 来自该真实 429 场景。测试等倒计时到期后成功提交密码继续，没有修改服务限速。最终将退出后重新批准放在独立隔离场景，默认完整流程发送五封验证码，通常约 90 秒；独立恢复流程通常约 50 秒。如果环境已有本次账号的限速状态，恢复步骤仍会按真实倒计时等到期再重试。

验收结果分别保存在以下文件：

- `verification.json`：完整 17 步，包含真实第二 / 第三网页设备、批准 / 拒绝 / 移除、换绑 / 找回、注销与离线保留。
- `logout-recovery-smoke.json`：独立 10 步，包含退出后换新密钥、邮箱确认、本机离线密码批准、设置保持超过 3 秒及注销清理。
- `visual-smoke.json`：短界面流程，重拍最新组件的 10 张浅色 / 深色登录、等待与设备页截图；不覆盖完整验收报告。
- `cloud-smoke.json`：云入口与文件邮件检查。

完整流程和独立恢复都直接检查注销后宿主 Cookie 与系统受保护的云凭据为空，并成功离线登录。本机没有发起模型推理、没有发真实邮件，没有操作日用数据。所有临时进程和目录在结束后清理。
