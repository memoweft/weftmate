`fixed-dsh.json`记录21项真实程序场景；`mobile.json`记录6项手机场景。相关调度 / 目标 / 动态 / 记忆摄取 / 原生命周期 / 手机资源一致性、原回复证据时间与类型检查通过；完整测试交本包PR（拉取请求）的CI（持续集成），不在本地重复跑全量。

MiMo两轮共12个真实请求，包括标题与工具轮次：输入33162 token（令牌）、缓存29056、输出721、合计33883。成功轮6请求、输入16834 / 输出372；首轮6请求、输入16328 / 输出349。首轮脚本误查未公开payload（负载）字段导致超时，且模型用after_seconds（延迟秒数）误算首次时间；已补明确的账户本地时钟指引，用同一句自然语言重验，原生首次时间与每日规则均正确。首轮失败用量完整保留在`mimo-attempt-1-usage.json`，没有当作成功闭环。

原动态快照用例在并行文件运行时一次未找到合成审批；按仓库串行测试方式重跑相关26项全部通过。扩展合成脚本也修正了原生PowerShell必填description（操作描述），及原审批停止可能返回“原任务已完成”的合法回执；未改原停止机制或放宽业务成功条件。

审稿页增加`goals`场景，桌面 / 手机夹具同时提供当前任务与定时安排。没有改变安卓版本号、发布界面包、部署、Apple（苹果端）原生源码或申请新权限；没有做长时间浸泡。

TB-4复用`src/ui-core/goals.js`、`components/goals-view.js`与`goals.css`，手机当前`page('goals')`菜单入口；底部选项卡收口时保持同一功能层、身份代次、原停止回执与写入重放。IA-5 / Apple需接CLIENT_API 9.9精确能力、任务状态 / 原来源与停止、账户时区 / 月历 / 间隔、原生目标CAS（比较后更新）与归档语义、请求重放、D33与临时标题边界，并补Swift（苹果客户端语言）和原生浅深截图。
