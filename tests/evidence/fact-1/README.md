# FACT-1 · 查资料成文的事实与出处

PR（拉取请求）：[#176](https://github.com/memoweft/weftmate/pull/176)，保留 **Draft（草稿）**。实现、真实对照和证据已交付，**未宣称全部验收通过**：性能目标未达，仍有模型范围错误与自查顺序不遵守。

## 实际行为与修改

- 关键断言以编号对应文末「出处」：标题链接、实际访问时间与短原文；没有依据时要求写「未在官方资料中确认」。
- 助手设置 `researchSelfCheck` 默认开启、按账户保存、下一回合生效。最终实现使用 DSH（助手运行时）原生 `todo_write`，核对草稿/原文主体、条件与例外、数字和判定；关闭只跳过额外核对，仍要求出处。没有答案后处理改写。
- 修复 PF-2 的实际桥接遗漏：`query` 未传到宿主，`sourcePath`、原文片段和预览截断字段也被丢弃。继续使用原生 `web_fetch` / `browser`、工具历史与压缩；压缩保存短证据及已完成状态。
- 网页 URL（网页地址）锚点可选择指定章节。RFC 9110 后段原来落在 256 KiB 捕获上限外；现在在不提高上限的情况下捕获目标章节。真实程序读取得到 13,770 字节的 RFC 15.4 和 888 字节的 Node-API（稳定扩展接口）兼容边界，见 [原生读取](anchor-reader.json)。
- 出处链接在既有「输出与来源」面板打开冻结原文，优先匹配具体章节，支持重定向后的来源；不展示内部存档路径/工具续读指令。开关、原文面板和窄窗标题栏修复均在真实程序验证，无新页面或新客户端权限。

行为约定：[GROUNDED_WRITING](../../../docs/GROUNDED_WRITING.md)。唯一外部契约增加是既有 `/settings/personalization` 的可选布尔字段；不需要新手机壳。

最终六题数据选取：`anchored/mimo-node/`、`anchored/mimo-http/`，以及 `inline/mimo-languages/` 与 `inline/mimo-web/` 中的 React 两轮。后三个主题无 URL 锚点，读取分支与提示未改；受锚点影响的三个主题重新跑了两次。模型稿从未人工改写。

## 原题性能、回归与 LAN

PF-2 同题基线中位数 **120.316 秒**，+40% 上限 **168.442 秒**。本包其他 MiMo 生成任务结束后，原 `action-02-web-document` 不改题、不改原检查，串行两轮 **278.428 / 327.747 秒**，中位 **303.087 秒（+151.9%）**，**未达目标**。每轮都出现一次约 90 秒有效流空闲取消/重试，完整计时，没有扣掉重试、压缩、加载或后台用量。见 [performance.json](performance.json)、[原题结果](serial-performance/mimo/results.json)。六主题完成样本中位数相对 PF-2 也为 +56.5%；题目复杂度不同，两个口径均列出，不混用。

QA-4 原文保留为负例，检出 ClangCL 范围错误；另保留 PF-2 原稿作为 ABI（应用二进制接口）134/137 数字负例。固定题基线这次没有直接写错数字，因此数字是 0→0，不虚构改善。见 [回归核对](regressions.json)。两份最终 MiMo Node 稿限定运行时本体、说明 Node-API 例外，ABI 为 137，出处可点开。

LAN（局域网）只用 `local-quality`，原子占锁，整批后释放。最终两题均交付：Node 24 **688.660 秒**、DEP0190 **825.426 秒**。Node 稿仍把 ClangCL 要求扩到相关原生构建/依赖；重复出现按一项无依据断言和一项范围错误计，数字正确。第二题按固定判据未发现四类错误。见 [LAN 原稿/结果](anchored/lan/results.json) 和评分。没有请求 8081，没有加载/切换其他局域网模型。
