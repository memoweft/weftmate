U02（正文一次性出现）已修复。U01（灰色补全）已有真实正向证据，延迟目标**仍未通过**：MiMo（小米模型服务）10次仅6次非空，0次在1.5秒内给出。这里没有把缩短提示、读取流式响应或完整单测通过等同于达到云端延迟目标。

## 分层证据与持久化

- 原始QA-7（质量验收）基线见 `qa7-before.json`：8004帧、12→1508两种正文长度、0帧呼吸点、1条完整 `assistant.message`。
- `layers-before.json`：可控模型每300毫秒发一段，主回合4条原生 `text-delta`（文字增量），公开投影只有最后1条完整消息。模型另发了4段自动标题数据，不能把8段都算成主回复。`layers-after.json` 中原生主回复仍4段，网关读取期间得到16次累计快照。
- `mimo/results.json` 的 `wire`（传输记录）分别记录云端SSE（服务端推送事件）到达与原生事件时间；首块的原生转交约3毫秒。修复初期MiMo首块只有 `#`，之后657毫秒才发下一个块；空标题渲染造成额外等待，已补未完成标记的暂态显示。
- `mimo-long-final/results.json`：真实Electron（桌面程序）、固定DSH（助手运行时）、直接MiMo云端，以及390×844真实手机网页；同一回合有1252／1255个可见正文长度。云端首块到首字151／147毫秒，结束后呼吸点均0。
- `liveEvents` 是完整累计快照集合，`data.text` 不能再拼接。会话 `liveSeq`、逻辑 `liveRevision` 独立于正式历史游标；最终消息用 `data.streamSeq` 替换原展示节点。迟到低水位快照不能倒退正文，最终消息不能被旧快照复活。
- 固定DSH原来就持久保存原始分块，本包复用其序号与时间重建快照。公开快照不写历史SQLite（本地数据库）、搜索、记忆、导出、离线副本或安卓历史缓存。正式完整消息仍是历史正文的权威；停止／失败的未完成片段只在最新回合暂态显示，不保证成为历史消息。
- D33（删除与遗忘边界）会清空逻辑暂态集合并核对来源。勾选擦除原话时，原生打包分块 `texts` 与工具参数 `args` 也被清空；跨三个分块的原话擦除、物理文件零残留、缓存失效均有测试。没有新增另一个持久增量库。
