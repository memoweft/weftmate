## 修复与实际请求

个人入口实际使用 `weftmate-personal-memory.mjs`，兼容入口是 `weftmate-memory.mjs`。两条路径都曾在当前问题后追加记忆；原生运行时与宿主指引也会追加用户角色上下文。实际修复前请求的最后一条用户消息不是游泳问题，不能只凭会话中存在正确原话或一次正确回复判断顺序安全。

继续使用 DSH 原生 snapshot（快照）、sections（上下文分区）和 plugin（插件）来源；背景明确标注“背景记忆，不是用户的新请求”，置于当前真实输入之前。个人入口在最终请求投影中也处理工具续步，当前问题保持为最后一条用户消息，不复制或重新提交原话。宿主提示只在当前用户提出偏好／纠正时确认；建议问题按用户请求给建议，不扩展成无关软件项目。实际最终请求核对见 verification.json，仅保存位置和布尔检查，不保存提示全文。

Core [PR #89](https://github.com/memoweft/memoweft/pull/89) 区分持续答复偏好／持续安排与愿望、一次性情绪，要求完整选择相关相邻原话片段。省略主题的短句通过已有正式取代链关联主题；后续形成输入的 `predecessor_context` 使用相同来源与生命周期检查，并采用形成权限面。周五原话保持原样，锻炼主题来自正式前项，不把旧日期作为当前值，也不把上下文冒充新 Evidence（原话证据）。关系样例说明用户朋友放在 `target_entity`，代词属性需要同时选择可核对姓名的相邻原话。

同一纠正的改口信号、新值、旧值否定与主题合成一条认知，选择全部相关相邻原话，避免把游泳改口拆成对另一个锻炼安排的更改。

本地输出还曾漏掉认知 ID（标识）的 `cognition-` 前缀。解析只在完整64位摘要能精确对应当前账号已有权威记录时还原标准 ID；不接受截断、未知或跨账号摘要，不做模糊匹配。原生来源权限、当前状态与原子取代校验仍执行，撤销来源的目标不能被格式兼容绕过。

形成请求沿用现有 JSON（结构化数据）输出机制和一次编译反馈。解析仅额外接受完整单个 JSON 代码围栏；夹杂解释、多个对象、缺少目标、无效字段和越界来源仍拒写。没有新存储、白名单、重试限次或审计层。
