# UX-8 回复动效验收

`ux-8-motion.mjs` 启动真实 Electron（桌面程序框架）的 `createPersonalDesktop` 主窗、390×844 手机网页，以及实际 Android（安卓）界面包加合成原生桥。宿主使用随机端口、系统临时目录和合成账号；没有读取日用数据、请求 8081、覆盖日用应用或使用安卓模拟器。Android 截图是界面包的 Chromium（浏览器引擎）运行结果，不能代表原生设备性能。

最终数据在 [verification.json](verification.json) 和 [performance.json](performance.json)。336 张短序列截图覆盖 7 类效果 × 浅深两色 × 3 个界面；每个序列 8 帧。文件名包含界面、主题、效果与动画时间。最后为真实性能发现重录 `status-shimmer`、为手机颜色令牌回退修复重录 `indicator-breathe`，并为外观控件补录打开状态；其余已通过场景保留。手机圆点背景另有实际非透明断言，减少动态触发器实际高度、物理边线与表面背景也有断言。

## 动效与令牌

| 文件名中的效果 | 做法 | 时长与令牌 |
|---|---|---|
| `status-shimmer` | 5 个静态渐变遮罩的文字高光段只改变透明度，跨段交叉扫过；原文字不移动。深色高光比浅色弱 | `--wm-duration-working: 1.8s`；`--wm-easing-replySweep: steps(7,end)`，按关键帧区间约 29Hz；帧点 0/240/480/720/960/1200/1440/1800ms |
| `status-switch` | 状态立即成为最新文字；最多保留一份隐藏于读屏的旧视觉层，2px 上移交叉过渡。30 次连续更新合并，不排队 | `--wm-duration-replyChange: 150ms`、`--wm-space-2`、`--wm-easing-desktop` |
| `stream-fragments` | 新短片段、段落和列表淡入；代码按新增行处理，旧代码与颜色保留。文字到达即存在、可读、可复制 | `--wm-duration-replyFragment: 120ms`；透明度 .72→1 |
| `indicator-breathe` | 布局外的小圆点放在末尾文字位置；无新字时持续柔和呼吸 | `--wm-space-4`、`--wm-duration-working: 1.8s`、`--wm-easing-smooth` |
| `message-arrival` | 用户气泡从输入方向 8px 上移、助手首行 2px 上移，均轻微淡入 | `--wm-duration-replyChange: 150ms`、`--wm-space-8` / `--wm-space-2` |
| `completion` | 圆点 120ms 淡出并移除；消息操作行 150ms 淡入 | `--wm-duration-replyFragment` / `--wm-duration-replyChange` |
| `stop-error` | 状态平滑成为「已停止」；错误提示轻微淡入，不抖动 | `--wm-duration-replyChange: 150ms` |

短过渡帧点是 0/20/40/60/90/120/150/180ms。截图通过暂停实际动画并设置其时间取样，保留真实程序样式和控件。合成序列位于真实滚动视图中、与宿主拥有的消息列表相邻，调用生产共用 API（应用接口）投影测试消息，不更改真实消息或流式协议。真实 MiMo（小米模型服务）链路另见 `mimo.json`、`mimo-attempts.json` 与 `mimo-*.png`；不能把合成帧序列说成模型逐字交付。

滚动跟随使用 `--wm-duration-replyScroll: 160ms` 和同一缓动曲线。实际页面验证通过：平滑经过中间位置、最终贴底间距 0px，用户上翻后立即停止，减少动态时直接到目标位置。可见消息锚点漂移 0px，动效期间高度漂移 0px。末尾圆点导致原 `:last-child` 边距保护失效的 4px 变化已修复，最后正文子节点的规则忽略布局外圆点。

## 性能

基线固定为 `e85b71228ff4646e41e4f9740fc55fb0b4878c52:src/ui-core/rendering.js`，不随之后提交变化。相同程序、相同页面、相同样张，同页保存旧与新渲染对象，按 ABBA（前、后、后、前）交错测试；旧渲染关闭回复动效，新渲染开启全部回复动效。每轮 120 次 `requestAnimationFrame`（浏览器逐帧回调）累计更新，包含解析、净化、节点更新和读取实际几何。每端前后各合并 240 个更新样本计算 p95（95 分位耗时）。样张为 15,480 字符、20 个代码块、5 个表格；没有强制垃圾回收。所有原样本、堆内存和代码节点身份保留在 JSON（结构化数据）中。

| 界面 | 更新 p95 前 / 后，ms（毫秒） | 帧间隔 p95 前 / 后，ms | 各轮更新 p95 前；后，ms |
|---|---:|---:|---|
| desktop | 8.50 / 3.60 | 10.10 / 10.00 | 8.80、8.40；3.70、3.40 |
| mobile-web | 8.60 / 1.40 | 10.10 / 5.10 | 9.70、7.00；1.40、1.40 |
| android-ui | 7.80 / 1.20 | 10.10 / 5.10 | 8.00、7.60；1.20、1.10 |

耗时改善来自已完成前缀和纯文本末尾段落的增量解析：完成代码、表格与控件保留身份；末尾仍为纯文本段落且前缀可证明不变时只解析末尾。新增 Markdown（标记文本）、列表、代码围栏和引用变化仍完整解析，语义回归测试保护这些边界。标题栏的弹层观察器也只在实际弹层变化时读取主题，正文片段 / 圆点不再触发额外样式计算。`after` 使用完整的新渲染实现，没有通过关闭新渲染来制造性能数字。

UX-5 原报告采用 20 次更新，未给 p95；其历史数字如下，不能和本次 120 次逐帧样本直接混为同一种统计：

| 界面 | 初始 / 更新均值 / 更新最大，ms |
|---|---:|
| desktop | 19.10 / 7.57 / 10.10 |
| mobile-web | 14.40 / 6.25 / 7.20 |
| android-ui | 16.40 / 7.34 / 11.40 |

真实 Electron CPU（处理器）数据来自 `app.getAppMetrics().cpu.percentCPUUsage`。每次调用重置采样区间，等待 1.6 秒后读空闲工作状态，再独立重置并读取同批流式区间。Tab 是 renderer（渲染进程）；GPU（图形处理器）行表示 GPU **进程的 CPU 占用**，不是 GPU 硬件利用率。以下范围保留两个前 / 后样本，没有剔除末轮基线峰值：

| 状态 / 进程 | 前，% | 后，% |
|---|---:|---:|
| 可见、等待新字 / renderer | 0.008–0.828 | 0.563–0.577 |
| 可见、等待新字 / GPU 进程 | 0.021–0.172 | 1.451–1.546 |
| 连续流式 / renderer | 6.768–6.819 | 4.947–5.777 |
| 连续流式 / GPU 进程 | 0.239–0.260 | 1.481–1.518 |

初始基线空闲样本 renderer + GPU 进程约 0.03%，可见工作动效约 2.01–2.12%，增加约 2 个百分点；没有称为零 CPU 开销。普通完成态没有循环，减少动态、页面隐藏与真实窗口最小化会停止动画。CDP（浏览器调试协议）`TaskDuration / elapsed` 的主线程忙碌比例也全部保留在原数据中；它只覆盖页面主线程，不能替代上面的真实进程 CPU。所有页面运行于同一 Windows 主机，手机尺寸结果不代表手机硬件，结果也不是长期浸泡测试。
