## LAN 失败定位

模型完成前四批后，调用 `subagent`（子任务）把第 5–24 批交给后台，显式设置 `run_in_background: true`。主会话没有调用 `job_output` 收取结果，随后自己继续读取并写同一批文件。原生持久日志给出以下顺序：

1. 18:25:00 主会话启动后台子任务，子任务收到逐批读取、写报告且不得覆盖已有报告的要求。
2. 18:25:46.318 子任务用 `write` 创建 `reviews/review-05.md`。
3. 18:26:03.639 主会话再次调用 `write` 写同一文件。
4. 现有 overwrite（覆盖文件）策略触发审批。场景没有声明覆盖审批，评测器保留 pending 并取消；此时仅有 5 份报告，目标和待办未完成。

原目标明确要求「已写好的报告不要重复覆盖」。本轮证据支持归类为模型执行编排失误：后台委派与主会话重复处理同一批文件，发生在任何压缩之前。没有确认 M1-3 范围内的产品缺陷；不据此改审批策略、放行未声明审批、改变场景或挑选复跑结果。此轮未触发压缩，**真实 LAN 模型的压缩后续跑仍未验收通过**。24 份源文件全部保持原样，私有地址/密钥扫描 0 命中。
