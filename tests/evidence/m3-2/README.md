# 同账号多台电脑验收

使用合成账号、随机端口、临时目录和 `synthetic-desk` / `synthetic-laptop`，没有连接生产云、18186 或日用数据。两个程序均启动实际 `src/main.mjs` 与固定 DSH（助手运行时）；测试引导只把 MiMo（云端模型）密钥保留在进程内，并为文件夹对话框返回合成目录。目录发现使用本地合成传输地址；账号、邮箱核对、授权刷新、电脑签名、内容认证、命令、审批和离线领取均走产品代码。没有把直接回环传输称为生产 frp（隧道）全链路验收。

运行器：`tests/integration/m3-2-electron.mjs`；实际闭环与截图清单在 `electron-report.json`。第一台登录后手机保持原界面；第二台登录后列出两台、打开电脑菜单，分别用 `mimo-v2.6-flash` 回复。A 读取独立合成资料目录的文件，B 没有相应执行；A 离线后只为 A 加密排队，稳定身份重启后领取完成；移除 B 的云登录后仍可本机使用。两台电脑的模型、对话与记忆各属于本机，本包没有共享记忆。

`before-phone-web-*` 是添加界面之前的单电脑基线。`single-computer-comparison.json` 逐张记录像素差异：合主线后的四张均仅在既有通知角标的数字（两个合成登录批次为2／3）有26像素差异，360浅色另有欢迎动画差异；没有新增电脑按钮、项目或布局。前一轮合主线前的三张逐像素一致记录由原验收保留，最终以当前差异JSON为准。固定测试同时检查单台目录条目字段不增加、客户端不打开新通道。图像保持原始捕获，未拼接系统栏。

手机网页截图是 360×780 / 390×844、浅 / 深的浏览器内容视口；不包含真实操作系统栏，不能据此宣称通过规则8.10。电脑截图通过只匹配本包原生窗口标识的系统窗口缩略图捕获，包含系统标题栏按钮；目标内容宽度1200 / 480。系统栏可用性检查另列，最终交付明确已验和待补范围。

## 原生客户端接线

1. 云目录先看 `capabilities.multiHost:1`，缺省沿原路径且新路由请求数为0。同名显示 `displayName || name`，关联登录电脑使用 `devices[].hostId`；单台没有新增关联字段，保留旧映射回退。
2. 以 `hostId` 保存选择，按唯一在线、上次在线、项目/旁聊来源规则决定；无电脑保留手机独立聊天。多台才加图标菜单和列表小电脑名。
3. `/sessions` 已有 `hostId`；各电脑内容地址分别认证、列表合并。项目及文件以其来源连接归属，不猜同名电脑；原路由、请求编号、附件标识与审批编号继续沿用。原生端按电脑保存内容会话与证书固定材料，刷新授权族串行更新。
4. 云电脑改名与移除是精确 POST（提交请求）`/personal/v1/cloud/hosts/rename` / `remove`，电脑认证通道是 POST `/personal/v1/auth/cloud-channel`。安卓属于云账号通道，普通业务通道拒绝；已同步 `CloudAppCrypto.kt`、`CloudAppUnitTest.kt` 和 `BusinessRouteUnitTest.kt`。需要新壳版本，版本号由编排统一调整。
5. `cloud-channel` 返回 `token` 和原身份/电脑信任材料，保留在页面内存，旧普通凭据仍不能取得离线副本；电脑原接口继续按认证、电脑归属和请求编号核对。原生可继续使用各电脑原 Cookie（会话凭据）与 CSRF（跨站请求伪造防护）会话，不必复制网页的嵌入传输。
6. S7（离线任务）信封、接收公钥、清理代次和目标电脑不可重写；尚未在线连接取得材料的电脑提示先连接一次。目标移除时正文清除、任务取消，列表可带 `reason:COMPUTER_REMOVED`；执行已开始的任务保留本机收尾，手机说明在本机查看。
7. 多台时显示审批所属电脑，通知/动态可选带 `computerName`，来源保持 `hostId`。移除电脑不退出整个手机账号，不删除电脑本机文件、对话、模型与记忆。
8. iPhone（苹果手机）同样接以上目录、能力、确定地址、默认规则与精确路由；不在本包改 Apple（苹果端）界面。主对话与记忆统一下一包采用记忆所在电脑方案，先补来源命名空间、补交会话回执和删除代次。

云升级：部署新版服务与新增011迁移、按原流程备份数据库并重启，目录和签名撤权回执返回新能力位；无需新端口、配置或域名。S4已合入，本包从010顺延为011，健康响应结构版本为11。具体步骤见 `services/cloud/deploy/README.md`；本包未部署云端。

## 最终验证

完整必过组在合S4前分三段运行：344文件、1961通过、0失败、14既有条件未运行；固定运行时整组35文件、241通过、0失败。合入主线 `4e97e031` 后，云服务109项为105通过、0失败、4既有可选环境未运行；云身份／备份／副本／客户端定向39通过，改名后心跳保留名称及能力回执3通过。手机五文件115通过，安卓JVM（Java虚拟机）80通过，类型、62个共享资源与公开卫生通过。

真实双电脑在合主线前与合主线后均通过，分别13与12次MiMo请求；最终报告为 `electron-report.json`，上一轮为 `electron-before-main-report.json`。`model-request-counts.json` 汇总有准确账本的66次请求（其中已知失败33＋8），早期调试请求没有完整计数，不能把66称为所有尝试总数。早期成功报告的18次统计重复累计了A重启前账本，未纳入准确账本，最终两轮已经改为按电脑差量去重。失败调试包括把程序数据目录误用作文件项目，以及额外写文件请求等待派发而未取得审批；最终用独立合成资料目录，保留原审批固定测试，删掉额外的非必需模型写文件截图步骤。`failure.png` 保留后者失败现场。

手机系统栏整屏、MuMu原生设备页实走与审批带电脑名的真实模型截图没有取得，本包不宣称这些已验收；网页菜单、设备页、离线目标菜单，电脑菜单／改名／移除弹层均有浅深截图。没有新增安卓或苹果原生界面。
