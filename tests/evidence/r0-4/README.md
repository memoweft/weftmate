## 上线与原生配合

云端尚未部署。服务器需配置 `CLOUD_FEEDBACK_REPOSITORY` 与 `CLOUD_FEEDBACK_TOKEN`，最小权限及恢复说明见 [服务器部署说明](../../../services/cloud/deploy/README.md)。没有数据库迁移或反馈内容表。接口见 [CLIENT_API 7.9a](../../../docs/CLIENT_API.md#79a-应用内反馈r0-4)。

Android 原生 `CloudAppCrypto.kt::cloudAppRouteAllowed` 需允许云来源的精确 `/feedback` POST（提交请求），添加允许／拒绝测试并发布新壳；当前壳会拒绝发送，界面保留复制路径，需要新壳版本。Apple 需实现本机评价、相同表单／二次确认／完整预览、云 `/personal/v1/cloud/feedback` 与本机元数据记录。长对话超过发送大小时需取消附对话或缩短说明；网络超时后的人工重试可能产生重复问题单，本包不新增幂等表或自动重试框架。


## 合入 AUTH-1 之后

云账号核心保留主线的本机账户切换／设备管理／登录规则及反馈发送方法，手机副本由脚本重建；更新记录同时保留登录重做与反馈句子。状态页使用主线整页，只替换本人工作包行并保留本人接口契约行。

反馈实拍夹具新增明确的 AUTH-1 模式：用原生窗口私有身份进入本机账户，不再用本地密码登录；手机／远程经真实合成云账号、设备证明、电脑连接与云会话交换后进入。断言本机身份为 `desktop`、远程身份为 `cloud`、账户一致，以及本机会话脱离窗口私有身份后被403拒绝，见 [fixture-auth.json](auth1-merged/fixture-auth.json)。其余历史工作包的夹具模式保留，没有放宽反馈断言。手机等待云账号核心初始化后接入验证过的会话，避免误用聊天核心做登录。

新的三界面主路与54张截图已覆盖本页原路径，默认无正文、二次确认、预览逐字一致、未登录／未开通复制、本机记录均通过。`vendor:dsh` 等共享编译完成后成功复用固定提交与补丁哈希缓存，未手改缓存；合入后的完整测试与最终CI（持续集成）结果另见追加交付报告。
