# DIAG-1 验证证据

所有资料均为合成账户、合成宿主、临时资料目录及随机端口，真实模型请求为零。没有访问本人日用目录、保管库、8081 / 18186，也没有 MuMu（安卓模拟器）或桌面接管。截图没有本机用户名路径或机器名，程序显示合成身份。原生转储内容没有进入仓库。

`tests/integration/diag-1-electron.mjs` 运行真实 Electron（桌面程序框架），每次只开一份：正常退出后重启不出现异常提示；强杀主进程后，先观察 `exit`（进程退出事件），按创建时间、精确可执行路径、命令行中的合成目录三项匹配清理孙进程，再等输出管道关闭；再次启动产生 `host.previous_unclean_exit`，界面出现「查看详情」，系统状态显示上一轮异常。另一次合成未捕获异常只留下技术消息，属性中的合成私密文本没有进入日志。

原生验收先正常关闭一次以持久化 Electron 的合成加密存储，再在下一轮调用 `process.crash()`，随后重启确认存在本地转储、上轮异常及 `uploadToServer:false`。首次尝试在新资料目录首次启动后立即崩溃，下一轮曾触发既有 safeStorage（本机加密存储）解密错误；未改该行为，改为先完成一次正常初始化再测原生崩溃。此边界与环境失败均保留在本地运行器证据，没有称为产品修复。

退出首轮采样：改动前 433 毫秒，增加诊断后 444 毫秒；另三次诊断退出为 464 / 429 / 453 毫秒。采样从退出请求至主进程 `exit`，计时监听器先于外部系统内存取样注册，因此没有把测试留证的 PowerShell（脚本环境）查询耗时算进去。最大差约 31 毫秒，没有出现此前的三秒等待。样本很小，不作为长期性能或浸泡结论；日志里的 `shutdownDurationMs` 与各步 `durationMs` 可以继续排查实用环境。

手机证据是 **viewport-only（仅网页视口）**，每张报告声明系统深浅 / 页面深浅、尺寸和底部导航区域不含原生系统界面。系统版本为测试用 Chromium（浏览器内核），`systemBars:false`；没有原生状态栏 / 导航栏整屏图，也没有系统栏色差值。依据本包禁止 MuMu 和桌面接管的边界，原生系统栏验收保留给实际设备试用，不能把这些图当作第 8 条第 10 项已完成。

前端清单：新内容放在已有系统状态页；按钮复用统一控件且有悬停 / 按下 / 键盘聚焦 / 禁用态；日期不显示秒或原始 ISO（标准时间字符串），窄窗与手机可滚动、不横向溢出；浅深三态及摘要打开状态已截图。手机运行记录与已有组标题保持同一缩进。机械设计检测零命中。原生栏与真实资源管理器 / 卸载选择界面未验收，测试使用替身和合成卸载清理。

本地曾遇到 `ENOBUFS` / `ERR_NO_BUFFER_SPACE`（系统网络缓冲资源不足），并因旧关闭竞态测试的早期错误没有进入清理而挂起。保持原断言与第二次预检查闸门，补齐夹具始终清理；后续完整测试结果另在交付报告列明。测试运行器本地输出保存在 `.local/diag-1-processes` 与 `.local/diag-1-smoke`，不上传其原始数据。

日志字段、脱敏、保留策略、安装位置、备份范围与助手用法见 [本机运行记录](../../../docs/DIAGNOSTICS.md)。BK-1（个人备份）目前会包含 `logs/`，已排除 `Crashpad/`；本包按要求不改备份范围，建议另行排除日志。
