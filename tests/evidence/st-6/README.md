# ST-6 通知与勿扰

新增账户同步的「通知」设置页。桌面、390×844 手机网页和安卓界面包共用 `WeftNotificationsView`；沿 ST-1 设置认证、账户持久存储和逐字段提交。按类型选择「通知 + 声音 / 只通知 / 只进动态不通知」，周报置灰、精灵字段暂不显示；勿扰按账户时区跨午夜、默认审批例外；主动上限 0 / 3 / 5 / 10 / 不限，声音与系统音量同步。Windows（微软桌面系统）提供权限读取、开启说明和通知设置深链。

宿主为每个原生事实持久决定 `notify,sound,decision,reason`。重复观察 / 读取 / 修订不会重复消耗额度，勿扰结束只有一条汇总；原通知不补弹。待办处理后静默，删除的动态不进入汇总。完整字段、默认值、首次决定与同步语义见 CLIENT_API 9.8.1。

所有验证使用合成账号、系统临时目录和随机回环端口，没有连接日用宿主、读取日用凭据库、向 8081 请求或启动模拟器。安卓只编译新壳及验证界面包，未安装本人应用、未改版本号。

## S3a / TB-2 接线

- 获取 `/activity` / `/activity/changes`，或转发相同 `notification` 决定载荷。notify=false 时只进动态；notify=true 时创建原生通知，sound=false 时不响铃。以账户 + activityId 去重，删除增量撤销通知；点击打开该动态。后台周期补发也不得重算宿主勿扰 / 时区 / 每日计数，不能复用旧 `/notifications` 绕过决定。
- TB-2 定时任务继续复用 DSH 调度送达与 `reminder.triggered`；本人创建默认 initiatedBy=user，若后续助手主动创建，提醒提供方保留 `initiatedBy:assistant`。任务完成与审批按真实发起方传入；不要按文案推断。
- S3a 保存设备推送载荷时保留 `notify,sound,decision,reason,initiatedBy,decidedAt`，不要因 important（重要分级）自行越过勿扰。系统权限关闭只提供本机开启入口，不改账户设置。D41后台约15分钟以上延迟仍需说明。
- 安卓业务桥新增设置和测试路由，**需要新壳版本**；原因是旧 Network.kt 不允许 `/settings/notifications` 与 `/settings/notifications/test`。按并行规则未改 versionCode / versionName 或界面发布最低版本，编排合并时统一递增。
