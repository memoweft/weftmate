# AUTH-1 规则、安全依据与兼容

1. **本机原生窗口直接进入。** 复用现有私有 `X-WeftMate-Desktop` 能力与原生桥身份：当前窗口、自己的主 frame（页面框架）、准确本机页面；服务端再要求环回、直接 Host/Origin（来源）、无任何转发头。每次使用 desktop Cookie（会话凭据）都重新检查，网页、子 frame、局域网、中继、公开来源即使持有 Cookie 也不能使用。能力由主进程注入，不进入页面身份返回值或云请求。Windows 用户已经能读取自己的数据目录，本地密码没有增加文件保护；免登只去掉这个重复门槛。零账户在原 legacy owner 补资料并撤销旧 legacy token（历史令牌），保留数据；原密码散列不删，多账户恢复/显式切换已有 owner。
2. **云核对后直接授予内容会话。** 新设备或换密钥的密码登录仍必须邮箱验证码；纯验证码登录证明邮箱控制权并绑定设备号、公钥、当前交互。云实时核对确认记录和 DPoP 公钥后签 `device_verified:true`；宿主检查固定签名、受众、声明、激活绑定、代际、设备持有、挑战、重放。只放宽“必须由另一设备批准”，没有放宽云身份核验。历史 pending（待确认）只在该设备合法重登时转 trusted；denied/revoked（已拒绝/已下线）不恢复，同云设备号换密钥、旧配对均不能绕过。
3. **本机与云会话分开。** 桌面云兑换还要当前本机会话 CSRF（跨站请求伪造防护），且保留其 Cookie；云登录绑定已选 owner，冲突 409，不建空账户。云过期/退出/改密码/注销只清云凭据，保留本机对话、记忆、设置；服务器功能显示重新登录，可关闭登录弹窗。远程云 Cookie 仍随撤权失效。
4. **登录后交付宿主材料。** 已认证宿主响应包含 `hostTrust`，客户端核对收件设备、公钥指纹、主体、宿主、短期签名和旧锚一致性；首次网页材料来自 D24 既定的内容 TLS（加密传输）连接，接受原浏览器域名控制边界。原生仍要求 CA（证书机构）/域名验证与 pin（证书固定）。离线副本继续由宿主用设备 RSA-OAEP（公钥封装）交付内容钥匙，不由云解密；已有明文对话仍在宿主 TLS 终止。取消手工传码不把明文钥匙交给云。
5. **新设备在登录后可查可下线。** 复用动态/通知政策，记录首登、最近使用，首次成功新设备通知同账户已有会话和本机；重复登录去重。宿主本地删除会话立即撤销对应内容信任与全部相关 Cookie；云撤权沿既有最多约一分钟轮询传播，云不可达时不能宣称已取得最新撤权。

本次规则明确把新设备访问的授权依据改为云端邮箱核对及其签名声明，取消了独立的宿主设备批准。它依赖云签发密钥和核对服务正确执行验证；若签发服务被完全控制，恶意声明能够冒充新设备。这一风险不能由 DPoP 或宿主 pin 单独消除，本文不把它描述成仍保留了独立设备批准的保护。云的正常业务仍不接收内容明文或宿主内容私钥。

纯邮箱码十分钟有效、单次消费、五次错误上限；账号和来源持久限速，发送桶达到既有阈值退避十分钟。未知/未激活邮箱和邮件失败同形 202，未知邮箱不发信；请求不等待邮件商响应，避免耗时枚举。确认错误/过期/超次统一 `INVALID_LOGIN_CODE`。交互 Cookie、CSRF、PKCE（授权码校验）、DPoP、刷新轮换不变；验证码/密码不持久化到客户端。

云端继续 schema（存储结构）8，宿主身份日志版本1、账户存储版本3。没有数据库迁移、批量设备历史转换或新建空账户替代。`firstUsedAt` 来自现有确认时间；声明由签发时实时确认，无一次性结构修改，重复部署可重入。

上线必须 **先云端，后宿主与客户端**。旧云或旧未带声明令牌被新宿主明确拒绝远程登录；升级后的云刷新会产生声明，或重新登录邮箱确认。本机免登不依赖云端部署。旧云密码/验证码/批准/配对/应急接口保留；旧云手机和网页通常会直接得到其已能理解的200会话，缺声明提示重登。旧本地 `/auth/login|register` 与 password/legacy-local 会话现在仅直接环回可用；从局域网、公开/中继来源调用或重放返回 `CLOUD_LOGIN_REQUIRED`，明确要求更新为云邮箱登录。旧客户端不能通过兼容接口恢复 revoked/denied。

Android（安卓）仍需下一包升级原生云请求白名单，加入 `/auth/login/code/request|confirm`，在 `cloud.app.configure` 成功支持该能力后返回 `nativeEmailCodeLogin:true`，核对声明并接收 hostTrust、取消 unconnected 的批准投影；本包按边界未改壳与版本号。现有密码＋新设备邮箱核对路线沿旧已登记路径。Apple（苹果端）需同样接纯码接口、严格声明、hostTrust、按需登录/原生机主身份、设备动态及下线；本包未改其代码。Android 与 Apple 的系统栏整屏真机证据留各端配合包，网页内容截图不冒充原生系统栏验收。

多账户免密切换及原数据读取已验证；既有第二账户的执行/项目权限仍按固定 executionOwnerId 隔离，不全局提升对应远程账户。宿主旧二进制不识别新的 authKind=desktop；云 schema8 的前后兼容不等于宿主二进制可直接降级读取新增原生会话。
