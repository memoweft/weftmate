# AUTH-1 宿主云身份验证

全部使用 temporary directory（临时目录）、随机端口、合成账户和本地签名/JWKS（公钥集合）夹具。没有真实邮件、云请求或模型请求。已有账户散列、宿主与账户标识、同步水位、记忆夹具及健康夹具保留验证继续执行。

## 新规则与安全依据

| 改动 | 为什么仍然安全 | 对应验证 |
|---|---|---|
| 激活绑定下不再要求其它设备决定新设备 | 必须先通过云签名 `device_verified === true`，同时验证绑定账户、认证代际及 DPoP（设备密钥持有证明）；云密码本身或任意 Cookie（会话凭据）都不能换取内容 | 缺失/false/字符串声明均 401；未知云账户 403；签名/受众/算法/期限/类型和 DPoP 的方法/URL/nonce/散列/密钥/重放仍拒绝 |
| 历史 `pending` 在同设备重登时转 `trusted` | 只在新鲜云声明与设备持有证明满足后转换，不批量改历史；拒绝与下线状态不可恢复 | 合成历史 pending 重登 200 且记录保持原 id；denied 重启后 403；revoked 更换密钥及旧配对路径均 403 |
| 桌面云登录绑定当前本机账户，不建替代账户 | 账户由已经通过原生窗口能力验证的本机会话选择；邮箱不能选择 owner；绑定跨 owner 或跨云身份冲突 409 | 两账户选择 B 后以 A 云身份登录 409，B 会话仍有效；不同云身份不创建空账户；首次本机 profile 保留原 legacy owner |
| 原生桌面会话可管理绑定及旧应急密码接口 | `authKind=desktop` 每次调用 `requireLocalDesktop`；同一宿主直接来源、环回连接、无转发头、本次启动能力凭据和写入 CSRF（跨站请求伪造防护）缺一不可 | 错能力凭据、Forwarded、X-Forwarded-For、公开 Origin、错误 CSRF 均 403；普通密码 Cookie 加能力凭据也不能冒充原生已选账户 |
| 成功交换直接返回宿主连接材料 | 经现有内容 TLS（传输层安全）边界返回宿主签名、公钥和 SPKI（证书公钥指纹）；浏览器遵循原 D24 接受边界；不发送内容私钥、备份钥匙 | 成功响应包含 `hostTrust.trustToken`；旧材料端点仍只对本账户已信任设备返回；旧配对账户、期限、单用保护保留 |
| 桌面云登录不轮换为云会话 | 原生 Cookie 仍只在严格本机窗口有效，云身份只控制联网功能；云代际变化不削弱远程云会话撤销 | `/auth/cloud-desktop` 保留原本机 Cookie；云会话 epoch/下线关闭活跃流并 401，本地会话仍 200 |

新设备通知采用已有 activity（动态）存储：`system.device.signed_in`，操作指向 `devices` 设置。历史 pending 首次转换产生一条；同设备后续重登不重复。宿主会话与云设备撤销、持久化 outbox（待发送记录）、认证代际、重放日志及旧配对单次期限语义保留。

## 原测试预期逐条对照

| 原测试/保护点 | 原断言 | 新断言 | 原因 |
|---|---|---|---|
| BK-1 恢复云所有权 | 已知恢复云身份进入原 owner；陌生云身份创建另一个 owner | 原生已选 owner 经新认领绑定；陌生云身份 409，账户数仍为 2 | 本机数据身份先选择，云登录不能新建空账户顶替现有数据 |
| 未完成旧绑定的桌面登录 | 新 key 返回 202，无 Cookie，另一设备 allow 后才进入 | 原生已选 owner 可续做原 claim，200，保留本机 Cookie | 当前宿主原生窗口已经证明机主身份，云设备声明与 DPoP 仍必需 |
| 双账户及 pending 内容隔离 | 新设备 202、只能由同账户 allow，然后才可读内容 | 合成历史 pending 只准同绑定账户； verified 登录 200、记录变 trusted、内容仍隔离 | 新设备核对移到云端；跨账户 decision 404 继续保留，legacy deny 重启拒绝继续保留 |
| JWT/DPoP 及重放 | 完整合法证明首次返回 202 | 完整合法证明首次返回 200；同证明再次/重启后再次仍 401 | 仅移除已核对设备等待，其它认证条件保留；新增三种缺少核对声明拒绝 |
| 设备撤销与重叠撤销同步 | 首先 pending → allow → exchange 取得测试会话 | 一次 verified exchange 200 取得测试会话 | 会话建立前置条件变化；活跃响应关闭、旧 epoch、旧 Cookie、同步新鲜读保护不变 |
| FX-9 空宿主首个云身份 | 创建新 execution owner，与 legacy owner 不同；另一个云身份创建隔离 owner | 本机 profile 先进入 legacy owner，云身份绑定该 owner；冲突身份 409，没有账户/权限上下文，原对话可见 | 用户要求本机先用且账户保留，云登录不应换一个空账户；两账户实际内容隔离由独立双账户用例继续验证 |
| FX-9 原账户已有绑定 | 陌生云身份创建第二 owner，原 execution owner 不变 | 陌生云身份 409，原 execution owner 和同步数据不变 | 选中的已有本机账户不允许被其它云身份重绑定 |
| FX-11 手机写入来源 | 首次手机 pending，桌面 allow，然后读写原对话 | 首次 verified 手机登录 200，仍是独立 cloud 设备会话 | 登录后可用；命令来源、文件观察、散列读回与下线后工具来源拒绝验证仍执行 |
| FX-11 桌面写入来源 | 桌面来源设备为 cloud，legacy owner 无命令 | 桌面来源设备为 desktop，legacy owner 即本机 owner | 本机登录与云身份分开；手机来源仍为 cloud，文件工具执行保护不变 |

未删除、跳过或降低旧配对期限/单用、密码登录兼容、账户隔离、撤销与文件来源断言。新鲜本机 GET（读取）请求夹具补充真实原生桥注入的 Origin 与能力凭据，云登录夹具保存现有 Cookie，而非人为每次登录轮换本机会话。
