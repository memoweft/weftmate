## 真实模型验证

遵守并行规则4b，原子取得 `lan.lock`（局域网占用锁），只用 `local-quality`，整批完成已释放。每轮新临时账号上下文与新会话，相同输入；后台模型能力探测不计入前景输入量。未人为清缓存、重启模型或更改推理参数。测试转发统一最多1,500输出 token，仅限制测试回复长度。

| 场景 | 改前3次首字（秒） | 改后3次首字（秒） | 结果 |
|---|---|---|---|
| “你好”：模型端点开始到首段可见文字 | 14.054 / 13.564 / 13.408 | 5.059 / 3.386 / 3.040 | 六次正常问候，无工具调用 |
| 文件任务：宿主收到消息到首段可见文字（整轮含工具） | 23.233 / 25.751 / 23.224 | 12.219 / 8.890 / 11.745 | 六次原生读取成功、准确返回 `PF1_SYNTHETIC_OK` |

任务首个模型进展（思考或工具增量）改前：14.396 / 14.355 / 15.614秒；改后：1.839 / 1.749 / 1.856秒。改前直接 `read`（文件读取），改后均 `load_tools → read → 原文`。首请求实际输入改前[11905, 11904, 11905]，改后[1928, 1927, 1926]。

改前首请求缓存0；改后首次问候缓存0，其余问候和文件任务有约1,292缓存 token。因而首字改善同时包含输入削减与服务自身缓存，不能把全部速度差归因于代码。上述是已加载 LAN 服务结果，不代表本人8081冷切换耗时；这次没有请求8081。工具延迟加载增加一次模型往返，仍已在本组任务中完成全部要求。
