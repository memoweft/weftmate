修复前重新启动真实隔离宿主，`memory-01` **通过 540.88 秒**，见 [修复前时间线](m2c-before-qwen-timeline.json)。首个前台请求 300 秒取消，DSH 重试利用缓存后完成；本次后台拿槽仅 5 毫秒，推理 75.88 秒，完成后前台继续。Core 接受至写入 96.017 秒，`attempts=1`。模型日志记录首轮预填充 4,096 token / 255.18 秒（16.05 token/s，每秒令牌数），后续缓存重试明显更快。因此本次没有重现 M2b 三次后台超时，不能把变化全部归为代码效果；历史超时、持久四次尝试与本次无死锁的时间线共同确定修复位置。

## 改动

- Core [PR #87](https://github.com/memoweft/memoweft/pull/87)：本地形成请求流式返回、包含用量，沿用 **300 秒传输空闲超时**。持续生成分块使请求保持连接，不把健康慢推理因总耗时误判超时后重算。模板参数真正关闭思考；仅内容组装为解释，保留结束原因、用量与实际模型头，中断流在编译前报错。云形成仍为非流式、120 秒。
- 首轮流式复跑暴露相邻片段丢失：Qwen为同一偏好选择`s0/s1/s2/s3`，旧编译只取`slices[0]`，保存成“用户以后给我讲技术问题，”；后台仅15.55秒且一次成功，但新对话召回0条。修复为合并同一Evidence（证据）已选相邻区间，按原话顺序派生命题，不跨未选间隙，也不让待修复的越界占位绕过原校验。命题和支持范围一起保留完整偏好，未从模型概括填事实。
- 同轮称呼两次被模型抄成“小枣”，`entity_name_not_in_span`拒写，保持零错误姓名。形成与反馈提示现在直接显示Unicode（统一字符编码）原文，不展开成`\u...`转义；持久哈希仍使用原规范格式。最终偏好同类输入4,136→3,754 token，名字由模型从可直接阅读的原文抄写，宿主没有猜名或替换名字。
- WeftMate：召回只等待开始时已接受的任务，保持 **330 秒**原等待预算；到期或任务查询超时后读取当前已形成记忆，允许前台继续。后到任务不延长本次等待。传输失败仍交给 Core 原生持久任务重试，没有增加模型白名单、重试限次或新审计层。
- 真实程序测试入口新增后台拿槽／释放时间线与私有 Core 标准错误日志、请求的流式／模板参数计数。公开证据只保留时刻、数量、用量、状态和合成事实检查，不包含完整回复、账号／会话标识、凭据或临时路径。
