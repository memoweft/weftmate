原生 `idleWatchdog`（空闲计时器）在每个有效流式块后重新计时，`thinking_delta`（推理增量）也会转成有效块。因此已接收的长思考会刷新计时，不会仅因总思考超过300秒而中止。服务端长时间没有输出时仍会触发原来的超时；本包保留该判定和预算。

## 实际修改

1. 网页打开只给4096字符以内的原文预览，较长正文在段落边界截取。整个已捕获正文保存在该会话的 `.weftmate-web-sources`，带来源、时间和捕获截断事实。已有快照继续读完整分段；新增 `browser` 的 `query` 可从同一冻结正文中返回匹配段落及字符位置，无须重新联网或依次读整页。没有另调用模型生成网页摘要。
2. 分段读取不重复返回50条导航链接和整份目录。公开目标、HTTPS（加密网页传输）、账户/会话归属与取消边界继续沿用已有实现；原文保存到会话目录，因此只读项目不会被后台网页读取写入。
3. 个人会话在估算输入达到14,000 token（词元）或活动消息达到48,000字符时，提前调用 DSH 原生裁剪及压缩。原生工具配对边界、持久替换和历史保留仍由 DSH 处理，保留约4000词元近期内容，并精确保留 goal（目标）与 todo（待办）状态。没有降低模型容量或输出预算。最终三次 MiMo 实际发生1 / 2 / 1次压缩。
4. 大上下文遇到原生 TIMEOUT（超时）时，先走原生强制压缩，只有持久上下文确实变化后才重试；压缩失败则保留原超时终态，不让普通重试重发原样大请求。取消不转为压缩/重试。合成原生测试覆盖成功压缩、失败压缩、取消、小上下文，以及目标/待办和历史保留。
5. 提示要求先给可见提纲、独立来源成对抓取、只补必要问题、限定比较基准、保留条件/例外、外围不确定细节省略或标注。不是工具次数限制，也没有自动审批。最终记录中有真实并行网页调用；沿用原有两槽，超过两页仍可能收到 BROWSER_BUSY（浏览器忙），没有为该情况增加权限或新限制。
6. 原文存档第一次试验被成果观察器当成产出，并行登记产生不确定回执，使 LAN 后续工具收到 `TASK_NOT_READY`。已排除宿主管理的该存档目录，普通用户成果仍照常登记。这个实际发现和失败保留于 `acceptance/`，没有用修改审批策略的方式绕过。
