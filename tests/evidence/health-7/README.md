# 健康页视觉升级

打开健康页，先看到带小图标和彩色底线的今日解读，再看到大数字和每项独立的彩色图形。手机分数为 44px（像素），电脑为 56px，详情为 64px；数字使用粗体和等宽数字。

恢复用青绿三段色带，睡眠用紫色粗双条，负荷用蓝色建议区间，压力用四段半环，电能用随高低变色的面积曲线，体能年龄用金色数字和对比条。身体指标带各自颜色的图标、个人范围轨道和位置圆点；活动三条彩条对照个人范围，并显示运动月历点阵。

图形均为手写内联 SVG（可缩放矢量图形），八个小组件复用到卡片、头部与趋势；没有新增图表依赖。睡眠分维度、活动分项和电脑使用的现有趋势也映射到同一组语义颜色。

估计说明只在设置 → 健康数据的两个模型开关旁出现一次。卡片、详情、趋势和回执的 `disclaimer` 均不显示说明；「依据」仍可展开方法名称。

## 前后对照与参考自评

`before/` 来自基线 `ac661831`，健康三轮前两轮均已在主线上；`recovery/` 保留先做恢复卡的原图。`compare/` 的 64 张图全部左侧改之前、右侧改之后，直接拼接原始像素，没有重绘或修改数值。对应今日页、六个详情与趋势页，四种尺寸、浅深两套；完整映射见 [index.json](compare/index.json)。

优先看 [手机今日深色](compare/mobile-390-today-six-dark.png)、[恢复详情](compare/mobile-390-recovery-detail-dark.png)、[睡眠详情](compare/mobile-390-sleep-detail-dark.png)、[压力详情](compare/mobile-390-stress-detail-dark.png)，以及对应 `-light` 文件；电脑对应 `electron-1200` / `electron-480`。

参考图逐张只在私人目录查看，没有复制进仓库或证据，也没有转录其中的健康数值。对照参考的层级与密度：数字先被看见，图形从细灰线变成有面积的色带、双条、半环和填充；手机卡片不再有「主要因为」解释，解释移入详情。恢复原型第一遍色带仍细，已加粗并收紧空白；完整首轮后把睡眠时长提到图形前，并拉开压力四段。浅色使用白卡和浅绿灰页面底，深色用更深页面底承托彩色图形。

静态取证启用系统减少动态效果，并逐张断言所有展示数字等于来源值，避免停在计数动画中间。正常进入的计数、条形、弧与曲线动效由固定测试验证；系统和应用的减少动态效果均能关闭，切换时会立刻恢复最终数值。早先八张被滚动容器裁切的长图已丢弃，最终长图由完整可见的组件重新取得。

## 数据、边界与安卓整屏

全部为 HEALTH-2 的 90 天合成生成器和生产第二版投影；不足七天为同一生成器的五天序列。压力、电能、体能年龄与按需分析继续使用 HEALTH-5 已对齐的正式第三版字段夹具，没有执行新算法，没有真实健康数据或真实模型请求。宿主、账号、资料目录和端口均隔离；电脑名称为 `synthetic-host`。

四张安卓原始整屏为 `phone-system-360-{light,dark}-{today,recovery-detail}.png`，来自 [云端 Android（安卓）取证](https://github.com/memoweft/weftmate/actions/runs/38281441248)。系统为 Android 14，系统/页面主题一致，底部导航可见；浅深状态栏色差均 0，底部导航色差深色 0、浅色 1。原始像素、可见文字区域和栏高见 [system-bars.json](system-bars.json)。使用既有独立测试浏览器容器验网页与系统栏，不冒充产品原生业务桥或真实健康算法联调。

首次云端浅色取证遇到初始会话加载把页面切回聊天的竞态；脚本改为等待已有会话就绪，并点实际健康选项卡进入。原有可见性、文字像素与系统栏断言保持，最新一轮浅深全部通过。

## 固定验证

完整必过 1815 通过、0 失败、14 项既有跳过；固定运行时 230 通过、0 失败、0 跳过；手机五文件 114 通过、0 失败。最后的图形/令牌 14 项与共享资产/更新记录 12 项均通过。统计见 [checks.json](checks.json)，原始结果分别见 `required.json`、`vendor.json`、`mobile.json`。完整组完成后的小范围颜色、分期与悬停调整由相关固定测试覆盖。

- 图形与视觉固定测试覆盖八种图形的空、单点、上下越界、32px 实际渲染宽度；断线不补点、单点不造面积；文字颜色浅深各在卡片与自身底色达到 4.5:1。
- 设置唯一说明、回执说明不渲染、系统/应用减少动态效果、明确服务结论才显示红色状态均有固定保护。
- 真实程序与手机网页验六卡、三卡、未接上、不足七天、六个详情、睡眠分期、趋势叠加、触摸按住/键盘选点、依据/分析/月历打开、两个设置开关、加载/错误与重试、360 宽无溢出。
- 共享构建、设计令牌生成与 Apple（苹果端）生成物一致性、类型检查、公开卫生均完成；设计机械扫描未发现问题。
- 第一遍完整必过为 1813 通过、1 失败、14 项既有跳过，发现基线健康包装动作重复注册 `saveHealthSettings`。已改为独立 `saveHealthViewSettings`，原设置写入队列与原函数保留，健康模型仍更新；原动作唯一性断言未改，健康测试增加原函数身份保护。最终完整组统计以 `required.json` 为准。

## 令牌与还需配合的事

完整颜色、浅深底色和 iPhone 引用见 [健康令牌说明](../../../design/tokens/health.md)。唯一来源为 `design/tokens/tokens.json`，网页与 `design/tokens/generated/apple/` 均由原生成器生成；只提交新增健康令牌相关生成物，Android 原生资源、iPhone 原生界面及版本未改。

需要 HEALTH-5 配合：当前契约只有睡眠各分期汇总时长，尚无逐段开始/结束时刻，所以睡眠分期色带明确按时长比例显示，没有编造整晚时序。新三项实际算法、`sleepPeriods` / `referenceRange` 实际回执及真实模型分析仍由 HEALTH-5 合入后联调。红色明显偏离沿回执的明确结论显示，界面没有新增判断阈值。宿主接口、字段和算法均未改。
