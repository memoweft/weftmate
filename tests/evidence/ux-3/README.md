## 契约与模型

见 `docs/CLIENT_API.md` 的 UX-3 小节。宿主偏好同时保存到逻辑对话与当前会话，发送优先逻辑对话，因此接力段可沿用。原生请求钩子在每回合开始固定偏好；当前回合的后续步骤不被中途切换改变，不调用会同时写全局默认的模型选择接口。开关只在模型已声明 / 已知支持较高推理时出现；原生显式不支持优先。关闭使用模型原配置值，不改全局默认。旧受管路由仅补缺失能力字段，既有原生声明与提供方默认保留。

OpenAI（模型提供方）使用 `reasoning_effort=high`；MiMo / DeepSeek（深度求索）通过 DSH 原生兼容映射使用 `thinking.type=enabled`，通义千问使用 `enable_thinking`。二态提供方开启思考，不声称其有独立的数值强度。实现依据为仓库固定 DSH 的配置与适配器；MiMo 参数参见[官方接口](https://mimo.mi.com/docs/en-US/api/chat)，Electron（桌面程序框架）区域捕获参见[官方 desktopCapturer](https://www.electronjs.org/docs/latest/api/desktop-capturer/)。

## Apple（苹果端）接线清单

1. macOS（苹果桌面系统）：「+」菜单提供文件、屏幕区域截图与剪贴板图片；iOS（苹果手机系统）提供系统相机 / 照片 / 文件。复用各端现有附件草稿与回执，取消 / 切账户 / 切对话时不能误附加。
2. 使用模型目录 `deepThinking.supported` 显示开关，模型设置标注不支持 / 未声明。已建对话调用 `/sessions/{id}/thinking`，新草稿在会话创建后、首条发送前保存。响应成功后显示小标记；迟到响应不改变别的账户 / 对话。无需客户端拼提供方字段。
3. 运行中排队用「排队到下一条…」，引导用「引导当前回复…」，没有方式区分时用「补充或跟进…」。沿用D36账户设置。
4. 从原时间线的步骤 `subtask` 和 `subtask.updated` 合并列表；名称、三态、耗时与对应步骤跳转；后台任务不因启动工具完成而结束。显示当前回合 / 尚未结束的后台任务，全部结束隐藏，不把计时当作实际进度。
5. 深浅色、窄窗、键盘菜单 / Esc（退出键）、VoiceOver（系统读屏）名称与开启 / 展开状态；流式更新保留焦点。Watch（手表）不新增输入区，只保持原审批与完成范围。
