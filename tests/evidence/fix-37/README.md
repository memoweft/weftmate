平滑贴底开始后，输入区高度恢复导致浏览器先夹到新底部；旧动画随后重放旧起点，把视口向上拉再向下移。测量同时包含长回复、两个命令、桌面记忆标签、建议胶囊及输入框。静止后没有无限循环重现；确定重现的是布局变动中的上述回弹。无需改变进展顺序或建议胶囊的布局。

修后每一帧读取最新布局，到达目标立即取消旧动画；目标改变时从当前位置继续并保留原结束时刻。上翻滚轮/手势立即取消，回到底部才恢复跟随。回归在模拟浏览器夹位的夹具中先红：`1080 → 1072 → 1080`；修后位置序列恒定。原48px贴底容差曾立即撤销轻微上翻，也已先红后绿。

命令输出在固定DSH（助手运行时）的`subprocess-local`收集器按UTF-8（统一字符编码）读取，而旧原生命令可以直接写GBK（中文代码页编码）字节，PowerShell的UTF-8前缀不会转换这种直接输出。保留有效UTF-8行；其他行按本机控制台代码页（本机实测936）解码，标准输出/标准错误、前台/后台读取共用同一适配。保留原字节偏移、截断与溢出文件，协议管道不参与。无换行的非ASCII（英文基本字符集以外）行等到换行/退出后再解码，以免把可疑前缀提前提交成错误字符。完全有效的UTF-8始终优先；单行内混写多种编码或命令在内部已解坏的文本无法无歧义恢复。

`personal-command-encoding-vendor.test.ts`启动真实固定DSH收集器及PowerShell，合成GBK标准输出/标准错误后再输出英文和UTF-8中文。起点收集器产生替代字符，适配后为“中文命令输出”“English output”“中文 UTF-8”。字节逐个到达、截断/溢出及协议排除另有单测。

输入圈是“背景信息窗口：用量待确认”圆环。桌面1200/480与手机查询均没有旋转动画（`getAnimations()`为空），尺寸稳定。未改样式；建议后续打磨未知用量的静态样子，避免像持续加载。
