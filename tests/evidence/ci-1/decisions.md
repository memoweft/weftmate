# CI-1 evidence and decisions

The fixed 80-run cohort in the [failure table](flaky-table.md) and [diagnostic JSON](flaky-table.json) is the source for these decisions. Every historical attempt is retained, including failures hidden by later green reruns. Distinct run/attempt pairs, not duplicate TAP blocks, are counted. A cancelled run can contain a completed failed job; its failed log is included. Cancellation after an hour is labelled suspected hang, not a proved deadlock.

- Windows: successful job median 2463s, required median 2150s; Linux: successful job median 833s, required median 723s. Both get three file shards. macOS retains one file worker and one shard.
- [One successful Windows sample](file-durations.json), run 38201453268: ROB-1 Electron file 492s, BL-29 rework 236s, desktop UI 222s. A fixed filename SHA-256 seed (`required-v23`) yields measured leaf-time sums 759/750/824s. Dynamic names and runner/setup overhead are explicitly omitted from this estimate; acceptance uses real job times. New files do not move existing files.
- Cloud per-file deadline: 600s, above the observed longest mapped file (492s); job deadline: 25 minutes. Timeout kills the owned tree, prints redacted phase/output/exit/commit-memory evidence, counts failure and proceeds to subsequent files. Cleanup matches the isolated scope or the current checkout and exact Node/Electron/Chromium executable, with creation time after the current file started; this covers ROB-1 controllers that put their synthetic profiles outside TEMP. An exited root's inherited output pipes are also closed at the deadline. Local invocation retains the original whole-suite runner and Windows concurrency 2; cloud files run with concurrency 1. Nightly/schedule/vendor never retry.
- Long-history approval, run 38207958670, is an assertion failure (7 rather than 6 reads), not timing. `reviewEnabled:false` disables review but does not stop the activity observer's forward native history reads. Its fixture now awaits the existing observer disposer before installing the source-read counter; all source-scope and exact-count assertions remain. No product code is changed.
- BL-29 early approval has six Windows failed attempts (five 25s controller timeouts, one historical spawn EINVAL) and one Linux UI timeout. Ensure timeout paths also clean the isolated Electron scope; previously this probe did not put nested profiles in its cleanup scope.
- BL-29 M4/S1 has five Windows failed attempts (four controller timeouts, one historical EINVAL) and one Linux UI timeout. No uniquely established fixture race in current code; preserve synchronization assertions and register as timing-sensitive. Run 38207958670 stops after the first 50ms transport cycle, so unfinished next-cycle/background work remains a follow-up if reproduced.
- Host close (<500ms) and empty-chat wake (<700ms) each have one observed Windows wall-clock assertion failure; desktop motion (zero tasks >50ms) has two. Register exactly these names, not siblings or entire files. Each file may retry only if every failing leaf is listed; mixed functional failures block without retry.
- BL-29 M1 Linux failure in run 38138830162 is `rows.length` 1 rather than 8, a functional assertion. It is **not** in the timing manifest, despite that test also containing recovery budgets. The earlier user-reported NETWORK/2s failure is absent from this frozen 80-run sample, so it does not authorize an entry here.
- Account projection and unrelated-account wake failures were already deterministically isolated on the base branch; do not register them. Native dispose has one functional settled-state failure in a rerun's original attempt, not a wall-clock assertion failure; current base disposer awaits pending waits, and local/cloud originals pass unchanged. Do not register it. ROB-1 has two functional failures: normal initialization exits 74 and a committed-after-interruption restart reports null rather than new. Current logs swallow the read/initialization error, so no established fixture cause and no product patch/retry. Add error name/code only to the synthetic harness for the next reproduction; credential contents never enter evidence. The user-reported 0xC0000409 and other approvals count 3 versus 2 are absent from this cohort.

The first local full gate (1759 passed, 2 failed, 14 existing skips) exposed a separate foreground fixture race: M1 SESSION_ARCHIVED recovery remained `null` with document visible but `core.state.background:true`. The fixture previously forced core foreground directly and slept 150ms, so a late native hidden frame from reload could replace it. It now publishes the actual BrowserWindow visibility, awaits the real production bridge foreground state, stops refresh and awaits its in-flight reads before injecting errors. Budgets/assertions are unchanged; targeted M1 passes all eight cases. This local observation does not authorize a new cloud timing entry. The other failure was the synthetic CI-vendor-selection fixture missing the newly imported policy module; copy that module and synthetic executable dependencies, retaining all original selector assertions (12 targeted policy/selector tests passed).

Fault injection's Windows setup took 4–5 minutes before required tests started. Cache exact package-lock/OS/architecture UI binaries (Chromium and Electron) and materialize Electron before the file deadlines; no version, test assertion or vendor cache changes. Acceptance will report cold/warm real wall time, not claim the mapped leaf estimates as measurements. The complete [fault-injection report](cloud/fault-unlisted-red.json) measured Windows file totals 808/674/928s, so finalize fixed seed `required-v5190` against these actual whole-file timings: 802/804/803s (temporary injections excluded). This tuning occurs before acceptance; the seed remains constant during all six runs and when adding future files.
