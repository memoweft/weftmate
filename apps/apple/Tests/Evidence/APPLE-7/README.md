# APPLE-7 · iPhone 轻量记忆（D63）

叠在 APPLE-6 / PR #273 上，目标 main。只修改 Apple 客户端，未实现电脑或安卓的记忆核心。手机对话是唯一持久的原始资料；轻量条目是可丢弃的派生理解，不与电脑记忆合并或对账。

## 行为与边界

- 助手完成后停顿20秒、离开对话或应用进入后台/回到前台时，一次小请求；最多8条新增使用者消息，通常合计不超过12,000 UTF-16；单条较长时完整包含这一条，已有条目最多8条/2000字，输出最多1200 tokens。更早未处理内容在后续触发重试；不自动循环，不每轮调用。对话原文未截断。只给模型使用者原话，彻底排除助手猜测。每条输入保留完整原文，不截断消息尾部。
- 中文提示词要求个人事实/偏好/正在做的事/约定/避免事项，只依据原话，携带精确引用和消息ID。JSON支持新增/更新/作废；坏结构/HTTP/加密落盘失败不推进已处理记录，也不显示聊天错误。
- 落盘前过滤原话引用、完整来源消息和结果正文。密码/密钥/证件/银行卡/验证码一律拒绝；健康等敏感事实仅明确要求记住时允许。混有秘密的一条原话会保守整体跳过。语义质量仍由使用者选定模型决定，规则不能保证辨别所有自然语言猜测或秘密改写。
- 本机最多200条，每条400字；聊天选最多8条、正文合计2000字，按置顶、关键词（含中文二字片段）和最近使用排序。每条最多3个来源ID带入系统消息，与M3-A共用同一记忆措辞/位置；不声称未选入请求的事已经记住。200条约80k字足够轻量使用，并限制请求/存储规模；满额后保留旧条目，使用者可忘掉后再加。
- 手机记忆页：最近修改优先、改/忘/手动加/置顶/全部忘掉、来源对话与日期。设置→手机模型默认开；提醒小请求花费。删除正文后仅留下来源ID及标准化文字SHA-256，阻止原来源或同样文字再被自动记回；明确手动添加可解除文字摘要标记。编辑同样屏蔽原来源，迟到请求携带账号和记忆操作代次，不能恢复已删除条目。
- 使用APPLE-6同一PhoneChatStore、同一按云地址+subject隔离的AES-GCM文件和ThisDeviceOnly钥匙串，目录排除备份。旧文件缺memory字段兼容。换账号立即清内存并切文件；退出只清当前可见状态，对话与派生内容在原账号加密文件中保留；显式清除本机内容同时删除文件/AES钥匙/模型凭据。
- 电脑接手用既有已验证会话+同账户云授权+匹配generation的M3-A内容就绪。先取消提炼，保存接手状态，再按冻结ID/正文加入原队列；回执丢失原样重试。未确认/部分回执保持轻量记忆可用；全部确认后删除条目、提炼记录和屏蔽标记，原文留在手机。`synced`沿3.19只证明Core持久接收，正式整理/形成由电脑包负责。
- 100轮或256KiB以上先显示估算和现在交/稍后；稍后隐藏全局提示，记忆页仍可选择现在交。小量自动处理。下一次启动仍会核对/重试。
- 电脑接手后所有记忆由电脑管理；离线显示只读内容。设置打开保留的手机对话继续聊天，也只用电脑记忆并在模型调用前后核对M3授权；电脑引用及继承依赖沿既有memoryRefs/dependencyComplete传回电脑，以支持真遗忘。
- 只有成功读取账户目录且电脑列表为空才恢复轻量模式；离线/网络失败不当作移除电脑。清派生内容，记录恢复时刻，只处理这之后的新原话，不翻以前交出的对话。
- 3.19旧队列单条消息最多16,384 UTF-16。新用户消息遵循该上限；已有超长历史/超长模型回复不裁切、不误确认，保留原文及轻量记忆并等待电脑导入契约支持。这是明确的电脑端依赖。

## 固定验证

- Core：PhoneMemoryTests覆盖解析坏结构/引用校验、敏感过滤、增改作废/遗忘屏蔽、选择及上限、接手/移除、加密账户隔离和电脑引用迁移。
- PhoneMemoryModelChecks：直接编译实际iPhone模型，替换账户上下文和内存凭据，本机真实HTTP/SSE合成模型。覆盖触发/水位、无新内容、开关零请求、失败重试、迟到账号/忘掉结果、手动改/置顶、上下文、停止→加入队列→全回执才清理/保留原文、部分回执/重试、移除电脑、100轮先选择、清本机、超长原文不截断、电脑只读记忆引用。
- 十个固定对话：事实杭州、清淡茶偏好、毕业论文、周末练琴、避免长英文应记；天气闲聊、合成密码、证件号、助手猜住北京不应记；明确请记住的诊断可记。合成回复10/10符合预期。这里测试机制，不代表真实模型质量；未提供MiMo凭据，未搜索凭据，也未调用真实模型。
- 生产App没有连接真实账号、云端或电脑。状态检查早期编译失败和测试异常已修复；异常来自独立检查程序，不计为WeftMate App崩溃。

## 电脑端最小配合清单

1. `/offline/sync`的设备公钥登记和记忆就绪应与可同步云模型解耦；手机已有自己的模型，不需要电脑下发模型密钥才能交历史。保持账户、设备、授权generation、加密信封和内容权限核对。
2. 给明确的「接收手机历史并提供记忆」能力/就绪信号，独立于云聊天模型；如果model可空，Apple共享OfflineSnapshot/OfflineChatModel还需按双方定下的可空模型契约接线。本包沿已有非空model信号，不臆造新字段或请求。
3. `/offline/turns`持久接收后才回同generation+id/state:synced；重试相同物理设备/id/正文应幂等。用conversationId/timestamp/messages保留顺序、原文；memoryRefs/dependencyComplete必须送入Core依赖，不将synced宣传为记忆已正式形成。
4. Windows使用既有导入聊天记录机制分批、可暂停、去重、整批撤回；手机不上传轻量条目。若用新的批次ID/进口确认字段，请在CLIENT_API登记后让iPhone按同一冻结队列接线。
5. 既有超长消息完整导入需要更大的消息合同或可重组的分片字段；目前客户端完整保留，绝不截断成假成功。
6. 遗忘/撤权继续推进generation并删除内容及依赖；手机沿现有M3真删除合同处理已交出历史，未交出的独立对话保留。

## 安卓原生照做清单

- 账户隔离、Keystore保护的本机加密对话；条目/已处理ID/屏蔽摘要/接手状态放同一排除备份位置。
- 中文提示词与结构、原话引用校验、敏感过滤、200×400、8条/2000字、来源ID最多3、关键词/置顶/最近使用共用同一原则。
- 完成后停顿/离开/后台触发一次、成功落盘才前进、关闭零请求、账号及记忆操作代次丢弃迟到结果。
- 原生记忆页的增改忘/全部忘/来源日期/置顶；模型设置默认开和小请求费用说明；同一用户措辞不展示内部术语。
- 电脑能力准备好→停轻量→原文冻结队列→全部接收确认才清条目/水位；小量自动、大量选择、离线只读、移除后仅新对话；不合并两套记忆。

最终本机验证摘要见validation.json，截图及启动/诊断记录见screenshots.json。真机Keychain、iOS后台时间、真实模型质量、真实电脑首次接手/Core形成/撤权、触摸与辅助功能仍需本人确认。云端CI由Claude收取，不在本包等待。
