# WeftMate dogfood 协议

Dogfood（亲自试用）由产品所有者完成。工程代理负责形成固定候选和诚实证据，不能替产品所有者宣布体验通过。

## 候选交付前

工程侧只做与当前目标直接相关的有限验证。交付必须说明：

- 候选版本或 commit（提交）；
- 精确启动入口和数据范围；
- 本轮用户能看到、能操作的内容；
- 自动化与内部预验结果；
- 已知问题，以及本候选不能证明什么。

如果一个可见功能仍要求产品所有者手工启动隐藏后端、设置端口、运行仓库脚本或理解内部 Profile/Goal，它还不是 dogfood 候选。

## 交付后停止

候选交给产品所有者后，工程代理停止主动找问题和修改代码，等待以下三种输入之一：

- `PASS`：当前候选达到本轮体验目标；
- `FAIL` + 最短复现：只修这个阻断，再交付新候选；
- 新目标：另起范围，不把它悄悄并入当前候选。

不得把“继续审计直到没有 Bug”作为默认流程，也不得在一次失败后自动扩展成无限修复循环。

## 阻断等级

立即停止当前候选的 `BLOCKING_NOW`（当前阻断）只有：重复真实副作用、身份/设备串线、凭据暴露、伪造成功。

普通 UI 瑕疵、延迟、一次网络或模型失败、可恢复错误和非核心测试缺口记录为 `KNOWN ISSUE`（已知问题）或 `DEFER`（延后），由产品所有者决定是否影响本轮使用。

## 不用任意限制代替可控性

不增加“最多 2 步”、固定动作数或固定迭代次数来让测试容易结束。真实任务通过明确完成条件、等待/退避、无进展检测、暂停、接管和停止保持可控。内部安全上限若确有必要，必须是防资源失控的实现细节，不能缩小用户已经表达的任务目标，也不能被写成产品能力。

## 证据分层

- 测试绿灯不等于界面可用；
- 窗口打开不等于后端受管；
- HTTP 200 不等于模拟器动作发生；
- 有动作不等于目标完成；
- 内部预验不等于产品所有者 `PASS`；
- `PASS` 不自动等于安装包、升级、签名或正式发布通过。
