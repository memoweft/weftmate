## 为什么单开一个隔离实例遛

dogfood 要的是**又脏又真**：乱填、纠错、切来切去、故意惹它编造。这会把画像/记忆搅得很乱，
不该污染你真在用的那份数据。隔离实例的库/配置/密钥全在 `dogfood/data`（`.gitignore` 已忽略），
删了就干净重来。所以放开手遛——搞砸了 `rm dogfood/data` 即可。

首启没有任何预置密钥，自己走一遍「配模型」向导（这本身也是要天天体验的开箱路径）。

## 每天/每次要有意识地遛的六样（独有肌肉）

不是功能验收（那有冒烟测试）。是**当真实用户**，看这些能力在真实使用里**成不成立、别不别扭**。

### 1. 记忆气泡：当场纠错
- **遛**：随口说一条关于自己的事（"我在做一个叫 X 的项目"）。看回复底下有没有织出记忆气泡
  （"记住了：…·把握度档·这条不对/删"）。**当场点「这条不对」或「删」**，走一次纠错 + 二次确认。
- **好的样子**：记住的措辞是你真说过的；把握度用**定性档**（不露 0–1000 原始分）；纠错/删有反馈、误删有拦。
- **要警觉**：气泡把你没说的话"脑补"进去；删了下轮又"我记得你说过…"冒出来。

### 2. 画像：按来源分组看
- **遛**：聊几轮后开「记忆与画像」，看条目是否**按来源分组**（你说的 / 感知来的 / 认知消化的），
  点节点看详情。
- **好的样子**：来源分得清；"感知来的"只在你开了感知、且真有 observed 消化后才有；把握度是档不是裸分。
- **要警觉**：把"猜的"摆成"你确认的"；来源标错；空画像却硬凑条目。

### 3. 人格切换：换人设、同一份记忆
- **遛**：星瑶聊几句 → 切到另一个人格 → 问它刚才那条事。
- **好的样子**：换的是**说话的人设**，记忆是**同一份**（切完还认得你刚说的）。第一人称语气只属星瑶那类人设；
  能力层（MemoWeft）文案不冒出"她"。
- **要警觉**：切人格像"换了个人失忆了"；或反过来，人设没变、只是换了个名字。

### 4. agent 干活 + 快照撤回
- **遛**：开「干活模式」，选个**临时工作区**（别选真项目目录），三档自主度各遛一遍：
  suggest 只出计划 / ask 每个改动先批 / auto 自动跑但命令仍要批。让它写个文件，然后**一键撤回**。
- **好的样子**：改文件前有快照，撤回能还原/删新建；`run_command` 不管哪档都要点头；沙箱把工作区外的路径挡住；
  慢活老实说"要一会儿"，不装秒回。
- **要警觉**：撤回没还原干净；auto 档偷偷跑了命令没批；能写到工作区外。

### 5. MCP：装一个外部工具包
- **遛**：开「⚡技能」，从预置里装一个（filesystem / memory / sequential-thinking 之一），
  看连接状态、工具数；再在干活模式里让 agent 用它一次。
- **好的样子**：第三方代码有警示；装完显示连接/工具数；MCP 的非只读工具**任何自主度都强制批准**；
  连不上时错误信息**能读懂**（说清哪儿不对）。
- **要警觉**：静默失败没提示；非只读工具在 auto 下没批就跑了；密钥类 env 在界面里回显明文。

### 6. 感知开关
- **遛**：默认是关的——确认**默认关**。手动开桌面源，切几个窗口，看"感知来的"证据有没有进审核层/画像；
  再确认**上云默认关**（observed 不上云），只有显式开全局 cloudAllowed 才允许。
- **好的样子**：开关默认保守；采集内容可选 app名/含标题；上云要二次确认；关掉后不再采。
- **要警觉**：默认就在采；关了还在采；observed 悄悄上了云。

## 盯三个真信号（这才是 dogfood 的核心产出）

| 信号 | 怎么盯 | 出现了说明 |
| --- | --- | --- |
| **"越用越懂"的体感有没有真出现** | 用了几天，回它认不认得你的偏好/在做的事/说话方式，是不是**比第一天更省解释** | 有 = 核心价值成立；**没有 = 最该记的问题**（不是 bug，是产品命门，重点记） |
| **有没有编造"我记得"但其实没召回** | 故意问它一件你**没说过**的事，看它会不会顺着编"我记得你提过…" | 有 = 触到红线（人设嘴快盖过真召回）。记下**原话 + 当时该召回什么**。库只存有据记忆，这多半是人设层的问题 |
| **有没有误报打扰** | 挂着用，看主动打断/提示的**频率和相关性** | 打断该只报 P0/P1。冒出无关/过频提示 = 误报，记下**触发场景** |

这三条比"某按钮点不动"重要得多——UI bug 顺手记，但这三条是**产品对不对**的证据，别漏。

## 发现问题怎么记（回流）

就近、当天，别攒。分两路：

- **具体 bug / 小改**：直接开 issue（进仓后走 GitHub issue；repo 还没建时先记到 `CURRENT.md` 底部
  「待作者手动 / dogfood 逮到」一类的行里，一句话 + 复现），保住语境别忘。
- **产品级信号 / 方向判断**（尤其上面三个信号）：写进 `CURRENT.md` 对应块的「dogfood 修/发现」小节
  （仿现有 `commit xxxxxx（dogfood 逮到）` 的写法）。改了代码就在提交信息里点明"dogfood 逮到"。

记的时候顺手带上：**隔离实例 or 真机**、**PORT/日期**、**能不能复现**。一句话能说清就别写长。

## 守口径（naming.md 摘要，dogfood 也要挑刺）

用的时候顺便当"文案审查"，看界面/回复有没有破口径：

- 别吹"真正理解你 / 真懂你"——是**越用越懂**（作者裁定的产品 slogan，可用），不是"理解"。
- **记 ≠ 信**：记住不等于当真；把握度是**定性档**，用户侧**不露 0–1000 原始分**。
- 慢活**诚实说"要一会儿"**，别装即时。
- **MemoWeft（能力层）文案不出现"她"**；**第一人称只属星瑶**（那类人设）。

看到破口径的文案，按上面「回流」当 bug 记。
