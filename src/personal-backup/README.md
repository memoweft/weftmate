# 本地备份（BK-1）

`/personal/v1/backups` 管理整个宿主的数据，只有宿主本地所有者可访问。默认目录是宿主数据目录旁的 `Backups/`，可在设置修改。每日一次只在 DSH 没有活动任务和待发命令时触发；手动操作遇到活动任务返回 `SESSION_BUSY`。普通备份在程序内完成：进入主进程设置/模型队列，排空并暂停文件原子写入；DSH 在自己的事件循环排空原生日志并复制完整字节，短暂排队新的网关请求。主进程复制工作目录、成果、账本与设置，并为 SQLite 固定只读事务视图；立即恢复文件写入，再通过在线备份复制已固定的数据库视图，随后散列/压缩/校验与保留清理。数据库复制可持续超过 2 秒，但不占用文件写入暂停窗口；其他连接继续写 WAL，后来的提交不会进入本次数据库快照。可变文件使用复制，不硬链接；窗口、对话、托盘和进程不关闭。暂停阶段总计最多 2 秒，超时立即恢复写入、不发布本次包；每日每分钟重试，不取消运行任务。备份设置不受恢复影响。

`.wmb` 是 gzip（压缩格式）流：`WMB1 <清单 SHA-256>`、JSON 清单及按清单顺序排列的文件原始字节。清单包含格式版本、时间、原因、每个相对路径、大小和 SHA-256。生成先写私有临时目录与文件，文件落盘后原子改名；列表逐包验证，不信文件名。SQLite（嵌入式数据库）一律使用 `node:sqlite.backup` 在线备份 API（应用接口），覆盖已提交的 WAL（预写日志），不拷数据库页或 WAL/SHM。

账号与设置、DSH 会话/日志、`conversations` 的工作目录/经验、成果、用量账本、健康和 `personal-access/accounts/*/memory-home/memoweft/memoweft.sqlite3` 均随宿主数据纳入。浏览器缓存、会话、凭据保管库、`.credentials.yaml`、云身份/令牌/设备私钥不进包；访问存储中的设备授权撤销，会话校验哈希替换为不可用值；保留历史设备元数据与一次性设置授权清理，维持命令引用一致，账号密码哈希保留用于重新登录。模型配置保留，密钥需在换机后重新输入。用户自行写在聊天或普通成果中的秘密属于用户内容，不是宿主管理的凭据；本地包未加密，必须保存在可信磁盘。云端加密属于 S4。

恢复先验证来源、备份当前状态，旧进程完全退出后，在下次冷启动、任何写入服务打开前提取到暂存目录、验证访问存储、逐个根项改名替换。原机凭据保持本机，换机不携带凭据；目标宿主安装 ID 保持，账号/会话 ID 保持，命令目标及校验值随新安装更新。对话工作目录迁到新数据根；用固定 DSH 原生路径定位器迁移日志目录，只改独立压缩的元数据帧，所有事件帧逐字节保留。包内仅保留发行者/账号标识/原所有者的归属映射，换机须经云端验证和新安装认领才能接回，既有目标安装的同账号绑定转接并清旧会话。恢复事务在每次改名前落盘，原数据直到宿主成功启动才删除；替换失败立即回滚，启动失败关闭所有服务后回滚并重启，进程中断下次启动先回滚。恢复需重新登录。恢复完成后的首次启动会先通过原生 resume（恢复会话）取得恢复会话的生命周期所有权，再检查模型绑定；否则模型只读接口会隐式打开会话，而恢复后删除会话无法取得原生 disposer（释放句柄）。该接线仅在恢复事务标记的首次启动执行，成功启动后清除；普通启动不批量 resume。

默认保留最近七天所有成功包，加上最近四个日历周各最新一份；天数/周份数可改，始终保留最新成功包。坏包不会被自动清理，便于用户辨认。升级安装先完成在线备份，再照原安装流程重启；本机注销在同一次确认中先在线备份，再调用云注销，密码仅留在当次页面内存。只有恢复和升级安装允许重启。远端账号注销不操作远端磁盘。

验证：`node --test tests/personal-backup.test.ts`；Windows 隔离真实桌面/MiMo：`node tests/integration/bk-1-local-backup.mjs`，截图在 `tests/evidence/bk-1/`。测试引导只拦截自动重新拉起，让 Playwright（自动化测试工具）控制下一次启动；在线捕获、打包、校验、恢复时关闭、事务、主程序启动与回滚均为生产代码。
