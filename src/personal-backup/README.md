# 本地备份（BK-1）

`/personal/v1/backups` 管理整个宿主的数据，只有宿主本地所有者可访问。默认目录是宿主数据目录旁的 `Backups/`，可在设置修改。每日一次只在 DSH 没有活动任务和待发命令时触发；手动操作遇到活动任务返回 `SESSION_BUSY`。备份使用现有受管关闭流程，关闭写入服务后制作一致快照，再重启程序；关闭未确认则不产生备份。备份设置不受恢复影响。

`.wmb` 是 gzip（压缩格式）流：`WMB1 <清单 SHA-256>`、JSON 清单及按清单顺序排列的文件原始字节。清单包含格式版本、时间、原因、每个相对路径、大小和 SHA-256。生成先写私有临时目录与文件，文件落盘后原子改名；列表逐包验证，不信文件名。SQLite（嵌入式数据库）一律使用 `node:sqlite.backup` 在线备份 API（应用接口），覆盖已提交的 WAL（预写日志），不拷数据库页或 WAL/SHM。

账号与设置、DSH 会话/日志、`conversations` 的工作目录/经验、成果、用量账本、健康和 `personal-access/accounts/*/memory-home/memoweft/memoweft.sqlite3` 均随宿主数据纳入。浏览器缓存、会话、凭据保管库、`.credentials.yaml`、云身份/令牌/设备私钥不进包；访问存储中的设备授权撤销，会话校验哈希替换为不可用值；保留历史设备元数据与一次性设置授权清理，维持命令引用一致，账号密码哈希保留用于重新登录。模型配置保留，密钥需在换机后重新输入。用户自行写在聊天或普通成果中的秘密属于用户内容，不是宿主管理的凭据；本地包未加密，必须保存在可信磁盘。云端加密属于 S4。

恢复先验证来源、备份当前状态，旧进程完全退出后，在下次冷启动、任何写入服务打开前提取到暂存目录、验证访问存储、逐个根项改名替换。原机凭据保持本机，换机不携带凭据；目标宿主安装 ID 保持，账号/会话 ID 保持，命令目标及校验值随新安装更新。对话工作目录迁到新数据根；用固定 DSH 原生路径定位器迁移日志目录，只改独立压缩的元数据帧，所有事件帧逐字节保留。包内仅保留发行者/账号标识/原所有者的归属映射，换机须经云端验证和新安装认领才能接回，既有目标安装的同账号绑定转接并清旧会话。恢复事务在每次改名前落盘，原数据直到宿主成功启动才删除；替换失败立即回滚，启动失败关闭所有服务后回滚并重启，进程中断下次启动先回滚。恢复需重新登录。

默认保留最近七天所有成功包，加上最近四个日历周各最新一份；天数/周份数可改，始终保留最新成功包。坏包不会被自动清理，便于用户辨认。升级安装先执行备份；本机注销先备份并重启，之后需再次确认注销，密码仅留在当次页面内存。远端账号注销不操作远端磁盘。

验证：`node --test tests/personal-backup.test.ts`；Windows 隔离真实桌面/MiMo：`node tests/integration/bk-1-local-backup.mjs`，截图在 `tests/evidence/bk-1/`。测试引导只拦截自动重新拉起，让 Playwright（自动化测试工具）控制下一次启动；实际关闭、打包、校验、事务、主程序启动与回滚均为生产代码。
