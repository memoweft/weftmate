# WeftMate：当前产品方向与路线（当前有效）

## 2026-10-05 连续交付统一助手的日用版本

用户要求总路线落实为一整段开发，兼顾上下文并防止任务漂移，做到可以大体验收时再停。本轮按 [UNIFIED_ASSISTANT_15](tasks/UNIFIED_ASSISTANT_15.md) 连续推进：Windows/Android 与共同服务端由本侧负责；Mac/iOS/Apple Watch 由另一侧同级总代理独立规划、拆分和验收。两侧复用一个账户、会话、任务和记忆契约，接口变化在既有协作入口核对。

本批交付目标是能日用的完整流程：同账户换设备接着聊，沿用原模型；手机可以派电脑执行目标并查看结果；记忆可查看来源、纠正、停用和删除；支持的附件实际可读、可跨端取回；断线、停止、重开、更新有明确结果。已有实现和本人通过的体验抵扣，不重做界面、流式滚动或账户壳。

内部按六项检查点接续：云模型完整运行 → 同会话与任务恢复 → 双端记忆 → 普通文件附件 → 应用通知、设置与更新收口 → 真实联调与大体验收。每项前后端一起完成。单项测试完成后继续本批，最终版本和真实通过范围由 `CURRENT_STATE` 记录。

### Apple Watch、健康与精灵的后续归属

用户明确手表融入 iOS 端，后续细设计精灵交互、健康数据交互和跨账户共同养宠物。iPhone 承接账户、健康授权、详细记录与设置；Watch 承接短交互、状态、提醒及适合手表的健康入口，共用同一助手和精灵状态。Mac 保留桌面助手与执行能力。当前先做 Apple 聊天与持久恢复，健康和共养设计不作为 Windows/Android 本批的交付前置。

PeakWatch 可参考健康指标呈现、趋势、睡眠/活动与精灵反馈场景；原始健康数据通过 HealthKit（苹果健康数据框架）的实际系统授权读取，增量与删除沿真实查询处理。原始指标和产品自定义评分分别表达；无样本不推断已授权或拒绝。[PeakWatch 官方资料](https://doc.peakwatch.co/)、[Apple 健康读取](https://developer.apple.com/documentation/healthkit/reading-data-from-healthkit)、[Apple 健康授权](https://developer.apple.com/documentation/healthkit/authorizing-access-to-health-data)。

共同养宠物采用双方主动加入的共享对象，分享选定的精灵状态、互动和约定。各自的聊天、记忆与原始健康数据继续归个人账户；同一宠物不使两个账户自动合并。成员加入/退出、双方互动合并、离线与通知细节在该模块开工时设计。

## 2026-10-05 官网集中分发与设备更新

用户要求安装包下载放官网，设备只显示对应设备的更新或扫码安装；官网可使用现有Ubuntu服务器。官网集中维护各平台的实际发布与安装说明，设备内更新按本平台/芯片匹配，跨设备用二维码进入官网平台页。私人会话、记忆、模型配置和执行仍按既有宿主归属保持；服务器界面更新与本人手动安装原生新包继续分层。

本轮为既有官网增加下载子页面并核服务器部署，不把介绍页重做、健康数据或本地模型维护列为前置。实施与实际上线状态见 `CURRENT_STATE` 和 `tasks/PUBLIC_DOWNLOADS_01.md`；Mac构建4与Apple续聊路线保留。

### 数据、同步与执行边界

- 聊天原文和附件引用由 WeftMate/现有会话部分保存；长期理解及来源、纠正由 MemoWeft 负责；目标与步骤状态由任务部分负责；执行尝试、观察和文件由对应设备负责；业务资料留在所属 Mod。通过稳定身份关联，逻辑分域不强制新建多个数据库或服务。
- 手机先可靠保存记录，再补传；同步事件不重新触发模型或工具。同标识重试幂等，同标识不同内容报告冲突。任务/消息/记忆修订保留来源与版本，删除或撤回使索引和缓存失效，旧设备重连不能复活失效数据。
- 首版冲突策略：已同步会话按服务受理序列追加，同一共享会话只有一个权威生成，后续消息排队；手机离线独立生成从最后已知版本分支接回，来源可辨、不静默覆盖。实施前映射正式契约，等价替代须统一说明。保留手机现有本机模型/工具循环，不新建割裂的任务权威。
- 记忆停止使用保留可查看内容但退出召回；删除从有效记录、索引和派生引用移除正文，仅保留必要无正文失效标记/操作元信息，并说明历史备份边界。删除记忆不自动删除原始聊天，旧来源同版本不得静默重新提取；接口只支持停用时不能冒充删除。
- 电脑保存完整资料、手机缓存近期内容和当前任务，成果按需取回。电脑离线时仅在手机具备独立可达模型和授权上下文时继续生成；电脑专属动作等待上线。完全离线的设备无法即时收到撤权，缓存与授权有效期须明确。
- 登录账户、选择模型、授权执行设备分别表达。记忆写入、查询、后台处理和上下文注入都按账户与目的地授权过滤；未分账户的旧自动注入保持关闭。共用模型不授予他人的记忆、文件和电脑权限。
- 已受理、实际动作、结果核验、通知送达分别有证据。关闭界面、停止回复与停止任务分开；失联时显示最后更新时间。副作用结果不明先观察，不盲重放；用户停止意图跨重启保留。

### 愿景保留，当前按可验收主线接入

电脑最终要能处理文档、表格、资料研究、项目与 Mod（能力扩展模块）开发/维护、程序及授权范围内的游戏分析等。优先使用现成能力，缺业务能力才进入开发通道；个人助手首页不变成运维后台。

保留“手机要求 → 家中 Windows 的 WorkBuddy 签到 → 手机实际结果”的首个业务验收目标；核对当前外部账户与动作条件后执行，打开窗口不能代替签到成功。核心链路先用无外部账户依赖的文件目标验证执行、内容、下载、停止与恢复，并检查成果跨账户/撤权访问。外部条件不具备时报告“核心链路通过、WorkBuddy 未验”，不阻止无依赖工作，也不把替代场景冒充原场景通过。第二个完整目标验证复用；Mod 自主创建/修改保留独立专项，不作为首个闭环前置。

圈选、悬浮窗、健康数据、使用时长提醒、手机无干扰执行、电脑反向控制手机、更多设备和更完整自主开发均后加。当前不把五端同时开发、双显卡协同、新品牌图标或图谱列为前置。手机依然是完整聊天入口，未来独立能力按真实设备和系统能力扩展。

具体容器、移动交互和逐阶段体验检查见 [FRONTEND_PLAN](FRONTEND_PLAN.md) 顶部。完整场景、数据规则、每阶段 UI/后端/验收/不做项见本次[实施交接 Markdown 导出](../../References/Deliverables/WeftMate_Codex_实施交接与产品体验基线_2026-09-27.md)及[DOCX 导出](../../References/Deliverables/WeftMate_Codex_实施交接与产品体验基线_2026-09-27.docx)。导出是便于转交的快照，不维护第二份实时状态。

## 2026-09-26：各种设备统一的 AI Agent 助手

**用户最终表述：各种设备统一的 AI Agent（人工智能助手）WeftMate。** 本节保留已确认的跨端能力、技术选择与此前拆分；首版实施先后以顶部 2026-09-27 四阶段为准，动态进度只看 `CURRENT_STATE.md`。

### 用户已确认的愿景

- 同一个助手可以跨设备交流、理解和办事。用户举出的用途包括设置应用、打开应用、完成 DSH 任务、协助 Codex 联调、处理浏览器任务；WorkBuddy 签到只是一项最简单的任务验证。
- 助手接受完整目标后持续推进，并按用户约定跟进、提醒和提出行动建议。约定、任务状态和实际结果需要可查询，用户能够调整方向和停止。
- 本机具备公网条件，后续直接承担个人服务端，手机及其他设备连接。公网入站、域名和实际连接仍需部署验收。
- 手机也需要较完整的独立助手能力。电脑离线时，手机按自身可用模型、网络和本地工具继续工作，联网后再同步；电脑专属动作保留明确的设备依赖。
- 对话、来源事实、长期理解、任务与业务数据连续接续；手机本地形成的资料保留来源与设备身份，再与电脑侧合并或呈现冲突。
- 继续沿用归档 v1.2 的界面方向和现有工程。首期落地 Windows 与安卓，其他设备按共用接口和各端实际能力扩展。品牌图标仍未最终定稿。
- 2026-09-27 账户决定：按`DECISIONS.md`“多账户完全隔离（用户拍板）”，采用多个人、每人多台设备。每个账户独立拥有记忆、聊天、任务、业务数据、模型私有配置和设备；正常登录使用账户和密码，支持新账户注册。此决定替代2026-09-26的个人单账户和仅本机首次建户限制，已有账户与资料须连续保留。
- 2026-09-27 输入区补充：模型使用紧凑文字加箭头的就近弹出菜单，显示当前选中项，底部提供“配置自定义模型”；语音入口与模型选择相邻，发送/停止保持明确。模型来源与执行设备仍分别表达，具体选项来自实际已配置能力。语音输入先回填草稿，再由用户发送。
- 2026-10-03 跨端续聊补充：用户选择“优先沿用手机原来的模型，再考虑同步该模型配置”。根据该对话实际使用的模型身份匹配另一端配置；缺少配置时提供配置入口，旧记录缺身份时明确选择，不静默换模型。账户内私有模型配置同步仍需单独接通并验证，开发测试凭据不自动成为日用配置。
- 2026-09-27 交互质量补充：用户要求借鉴参考产品的控件样式和位置，功能保持WeftMate自身语义；动画、跟手、流畅与便捷属于交付要求。优先复用维护中的原生组件、官方技能和成熟交互实现，按键盘开闭、焦点/草稿保持、快速连续操作和实际帧表现核验；静态截图不代替动态交互通过。
- 2026-09-27 完整App补充：本轮按完整App落实注册/登录/验证、电脑本地和手机直连模型、自定义头像昵称、设置、外观、通知、设备与聊天显示。可能分享给朋友，既有认证、来源校验和设备撤权继续保留；不扩展企业组织、邮箱或短信流程。05直接按多账户实现，账户隔离属于本轮验收条件。

### 实现分工与数据归属

- 个人宿主管理长期运行的能力和连接；需要窗口、截图、输入的电脑动作由登录桌面中的执行部分承担。初期无窗口模式仍是同一用户会话中的 Electron（桌面应用框架）宿主，后续系统级服务化另行验证。
- DSH 保留会话与模型运行基础；MemoWeft 保留来源、长期理解和纠正；Mod 保留自身业务数据与运行回执。跨端接入引用这些真实对象，手机保存本地必要记录和待同步事件。
- 账户是数据和执行归属边界。服务端从认证结果确定`ownerId`，查询、写入、后台回调与同步均沿用原归属；客户端按服务来源和账户隔离缓存、模型私有配置与通知。切换账户不能继承上一账户的记录、在途结果或系统通知入口。旧资料只迁移到已知原账户，归属不明的本机资料不得由新注册账户自动认领。
- 宿主可以明确提供共用模型算力，但私有密钥、提示词、会话和记忆仍各自隔离；使用服务器不会自动取得服务器所有者的电脑、文件、工作区或设备操作权限。尚未按账户接线的MemoWeft保持未接入，不接到共享私人记忆库。
- 网络断开、关闭界面、停止模型回复、取消执行是不同意图。恢复连接先查询原会话和任务；副作用动作不能因为重试而盲目重放。
- SSH（安全外壳协议）可用于开发联调和管理。面向客户端的稳定接入需要认证、加密连接和明确设备身份；已有公网入口只能在接入层与部署验证完成后承载这些接口。
- 初期使用现用固定 DSH rc.5；已取消的 Alpha.2 升级不自动恢复。模型、私人会话、现有数据库和其他运行服务沿用各自边界。
- 主助手负责目标、方案、任务拆分、文档、审查与验收；GPT-6 Sol 负责主要实现与复杂审查，GPT-6 Luna 负责简单修改和机械工作。任务显示名标明实际模型。

第 1 阶段个人宿主与第 2 阶段本机接入已有开发验证，证据见 [UNIFIED_ASSISTANT_01](tasks/UNIFIED_ASSISTANT_01.md)、[UNIFIED_ASSISTANT_02](tasks/UNIFIED_ASSISTANT_02.md)。按用户最新要求，当前先补 [账户登录与多设备管理](tasks/UNIFIED_ASSISTANT_03.md)，再接续安卓端。任务编号不代表安卓完整阶段已完成。源码完成、真实运行、跨公网连接、手机独立使用和用户体验分别报告。

## 目标与已确认边界

2026-09-23 用户看过 Alpha.2 实例后明确：DSH 原生右侧工作区面板可以保留，包含工作区文件、新建终端及其右侧栏操作。WeftMate 自有前端主要负责品牌、左侧导航/会话、中央对话、记忆与 Mods 页面；右侧工作区应复用 DSH 真实能力并做主题、布局和开关衔接，不为了“自有前端”重造文件/终端或遮挡该区域。是否可见与可点以新版实际页面回归为准。

用户随后明确授权可以直接修改 DSH 的前端页面。Alpha.2 版本不再以插件覆盖层仿制原 WeftMate V2 页面；应在独立的固定 DSH checkout 内把已合并的 V2 页面布局与视觉迁入原生前端组件，并复用 DSH 的正式会话、工具与右侧工作区能力。修改后的候选必须标明官方基线提交与 WeftMate 本地前端差异，不能继续把它称为纯官方未修改 vendor；共享脏 DSH 工作树、现用 rc.5 与用户模型任务仍保持不变。

WeftMate 是长期个人助手。普通对话保留原有会话、历史、文件、工具和模型能力；DSH 与 MemoWeft 是基础内置 Mod，业务 Mod 可以是含界面、数据、依赖和模型调用的完整多文件程序。宿主必须能独立启动、控制、诊断和恢复，不依赖正在故障或升级中的基础 Mod 自救。

它可本地部署，围绕同一用户及其相关人物、经历、项目和世界形成连续理解，避免用户向外部 AI 搬运日志与背景。先查并复用现成能力，再按需要创建完整 Mod；创建、接管和维护是三项分别验收的能力。普通聊天无需先选项目；未知、失败、未接入和零记录必须如实区分，不能用样例或“暂无”伪装。数据、用户决定和历史可连续接住，任务可安全暂停、重启和恢复。

所有页面和未来 Mod 使用统一的“织语 Weave”轻量界面。旧星球/记忆宇宙图谱已经废弃，不能恢复天体、亮度、尺寸、引力、轨道或相似度等强制实现语义；记忆的来源、搜索、阅读、纠正和处理状态仍是目标。点边提案仅保留为既有设计成果，是否采用另行确认。

Weave 按需展开必要状态与操作，停止、未保存提示、关键授权和需用户回答的问题必须可见。ThreeUI 仅为可选参考，不是主题或架构前置。跨端目标覆盖 Android/iPhone、Mac 与手表：客户端、感知端、执行端分开授权与验收。旧“永久冻结 DSH”的理解已废弃；可复现固定版本仍可作为受控候选。

MemoWeft 要区分来源、接收/处理/形成、检索和最终采用：资料交接或被送入上下文都不等于模型采用。业务数据、运行进度与长期理解分别归属，不把业务数据库强塞为记忆；普通授权材料可自动处理，关键冲突和有影响歧义才询问。DSH 可维护更新：先比较上游、升级、适配、移植和自研，集中维护兼容与恢复，不以固定版本为永久冻结。
