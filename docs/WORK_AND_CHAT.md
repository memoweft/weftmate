# MODE-1 · 对话与工作

2026-10-14。依据本人当天确认的两种模式，以及现有主对话、旁聊、项目、多电脑、手机独立使用与离线任务实现。

## 产品定义

**对话**用来聊天、问问题和了解自己的记忆、健康及使用记录。在线电脑可回答并保存正式记忆；没有在线电脑时，手机沿现有独立使用路径回答。对话不读取电脑文件、不运行命令、不打开程序或浏览器。

**工作**让一台电脑动手。每段工作对话属于一台确定的电脑，并绑定其上一个已登记项目或文件夹。电脑与文件夹必须在首条发送前选好；工作中不能更换电脑。文件夹沿现有项目对话规则，只能在空闲时更换，从下一回合生效，原文件留在原处。模式转换不授予文件写入、删除、安装、对外发送等权限，原审批继续生效。

界面只称“对话、工作、电脑、项目、文件夹”。侧栏对话区顶上保留“小纬”，其下普通对话；工作区按项目组织工作对话。新建对话直接开始，新建工作进入顶部选择条。多台电脑时先选电脑，只有一台在线时直接使用；离线条目灰显并写“不在线”。再选该电脑已有项目、最近文件夹或“选择文件夹…”。电脑程序复用原生文件夹选择；远程网页若没有电脑目录浏览能力，只列已有项目与最近文件夹，提示在电脑添加。输入区原 M3-2 电脑图标移除。

顶部副标题：对话为“由 <电脑名> 回答”或“手机自己答的”；工作为“<电脑名> · <项目或文件夹名>”。既有工作电脑离线时保留所属电脑与文件夹，不自动换到另一台。

## 已核实的底座

| 实现 | 现状与复用方式 |
|---|---|
| `chat-identity.mjs` / `chats.mjs` | 逻辑 `chatId` 聚合原生 `sessionId`，主对话可接力为多个执行段；项目对话与普通旁聊均为 `kind:side`。模式不能覆盖 `kind` 的原义 |
| `sessions.mjs` / `session-metadata.mjs` | 会话已有 `projectId`、`projectRevision`、分组、置顶、历史、分叉及来源。项目移动只在空闲时生效 |
| `personal-projects/` / `folder-choice.js` | 已有项目、最近文件夹、本机文件夹选择、权限与警示；网页目前没有任意电脑目录浏览接口 |
| `weftmate-personal-desktop.mjs` | DSH（助手运行时）的 `tools/pre-execute` 接入项目边界和权限审批；`approval/request` 桥将原生暂停投影成持久可回答卡片。这里是模式判断的位置 |
| `getApprovalPolicy` | 每步读取当前账号与会话的项目、审批模式、连接器目录；加入会话模式，不能将审批 `mode:auto/ask/...` 改成聊天模式 |
| `ui-core/computers.js` | 手机合并电脑列表与项目；每条既有会话固定来源电脑，发送重试保持原目标。电脑窗口原本只执行本机 |
| FIX-33 | 在线电脑的新聊天在电脑创建；没有电脑或离线时手机自己回答。既有手机独立记录有继续入口，旧电脑缺能力时沿原接口 |

旧旁聊没有“纯聊天”的执行限制，不能仅改名。默认无项目的主对话、旁聊归“对话”；有有效或曾绑定项目的会话归“工作”。已有文件、原生事件和记忆来源不搬、不重新摄取。旧的纯浏览器工作入口需绑定文件夹后才继续执行。来自手机的只读历史归对话。

## 工具归类

归类根据模型实际调用的工具定义和操作类别，绝不根据用户消息关键词猜。内层调用也走同一判断；装载工具不等于执行工具。现有工具目录仍向模型描述电脑能力，使真实请求可以调用正确工具并触发卡片。

| 现有类别 / 工具 | 对话可用 | 只在工作里 | 理由 |
|---|---|---|---|
| 普通回答、自动记忆召回与形成、记忆查询 | 是 | — | 既有账户内容服务，不读取电脑任意文件；来源与许可不变 |
| `health_query` 健康、电脑使用汇总 | 是 | — | 查询已形成的账户数字，不操作电脑 |
| 时间读取、等待等纯时间工具 | 是 | — | 不操作电脑文件、程序或浏览器 |
| `load_tools`、`todo_write`、提问、计划确认 | 是 | — | 装载定义或组织当前对话，不执行电脑动作 |
| `create_goal/get_goal/update_goal` | 是 | — | 目标记录本身不执行电脑；后续工具仍检查模式 |
| `read/glob/grep` 及项目列文件、读文件 | — | 是 | 即使只读，仍读取电脑资料 |
| `write/edit/apply_patch`、成果写入 | — | 是 | 写电脑文件，转换后仍需原权限与审批 |
| `pwsh/bash/shell` 等命令工具 | — | 是 | 运行电脑程序，纯算数也不能绕过模式执行命令 |
| 桌面应用、设备操作、WeftMod | — | 是 | 操作电脑或外部应用 |
| `browser/web_fetch/web_search` | — | 是 | 现有实现使用电脑浏览器、网络及本机来源快照；不伪装成手机查网页 |
| `run_code` | 容器本身可用 | 内部电脑工具逐一判断 | DSH 原生编排容器；每个嵌套调用必须经过模式判断，不能绕过文件或命令限制 |
| `subagent`、作业管理、子任务消息 | — | 是 | 当前子任务继承电脑工作目录与执行能力；先转换，后委派 |
| 连接器只读数据查询 | 是 | — | 仅已登记为只读的账户数据操作；网络许可照旧 |
| 连接器写、删、发送、未知副作用 | — | 是 | 修改资料或应用状态；原连接器审批继续生效 |
| 纯提醒的创建与管理 | 是 | — | 提醒只登记账户事项；执行型定时任务必须工作，且执行时再次检查模式 |
| 未识别的有效执行工具 | — | 是 | 工具目录中有定义但没有纯数据语义的工具不能在对话中操作电脑；无效工具仍返回原未知工具错误 |

## 数据与接口

新增字段遵循 additive contract（加法契约），保留原字段、路径、标识和命令形状。

| 字段 | 语义与现有字段对应 |
|---|---|
| 会话 / 聊天 `mode:chat|work` | 产品模式。旧记录无字段时根据 `projectId` 自动投影；不修改命令中 `mode:queue|steer` 或审批 `mode:auto|ask|...` |
| `hostId` / 工作 `workHostId` | 回答所在电脑 / 工作绑定电脑。工作一旦开始不可中途变更；电脑认证、命令目标仍用原 `targetDeviceId` |
| `projectId/projectRevision` | 工作的项目与修订，复用现有项目登记；文件夹也是项目记录，不增加第二套文件授权 |
| `workDirectory` | 客户端可见的项目标识与名称、既有脱敏 `pathHint`；绝对工作目录仅存电脑，不泄露到云目录 |
| 审批的可选 `intent:work-switch` | 原生工具暂停的产品投影；旧客户端仍看到普通一次性批准 / 拒绝，批准前必须有有效项目，否则不能执行 |
| 审批回答的可选 `workProjectId` | 同意转换时选择现有项目；原 `requestId/outcome/scope` 保留。转换只允许一次，不作为长久工具授权 |

能力采用可选 `personalCapabilities.workAndChat:1`；新版网页只对已声明能力的电脑启用转换字段。新手机对旧电脑保留 FIX-33 路由与原项目视图，不向旧接口发送新字段。最终实现新增路径或字段须同步 `CLIENT_API.md`、安卓精确路由用例与两端照做清单。

## 从对话切换到工作

模型实际发起电脑工具调用时，先于项目执行和风险审批暂停该调用，显示卡片：“这件事需要在电脑上做。要切换到工作吗？”卡片内用 ChoiceList（卡片选择控件）列电脑与项目 / 文件夹，底部“先不用”和唯一实心主按钮“切换到工作”。选择完才能转换。

同一电脑转换保留 `chatId/sessionId`、所有消息、原生工具调用、回执与记忆来源。账号存储在同一次持久更新中写 `mode:work`、电脑、项目及修订，随后原生暂停继续，重新读取项目上下文并处理原来的工具审批；不重发用户原消息，不新开另一段，不重复执行。侧栏按照新字段自动移至工作区。已有来源 `(hostId,sessionId,seq)` 不变；模式转换不是一轮真人话，不作为记忆新来源。新工具和后续回复沿原回合记录。

“先不用”答复原生拒绝，卡片收起，助手用一句话说明这件事需要进入工作才能做。不能改走其他工具完成同一动作；下一轮新的请求仍可再次出卡片。刷新、断线与原生恢复沿现有审批有效性处理，不把旧卡片当作新的批准。

主对话转换时，原逻辑对话改为工作，原 `chatId` 和历史全保留；为对话区的“小纬”生成新的空主入口。原会话不会一份同时挂在两个区。旧主入口的保护语义随新主入口移动，工作聊天恢复普通项目对话的生命周期。主对话多个历史段继续属于原逻辑聊天，原始来源不变。

## 多电脑、离线与独立手机

新建工作列在线电脑；只有一台在线直接选，多台沿用上次，否则第一台。电脑程序使用本机，远程网页使用现有已认证的多电脑通道。项目只从所选电脑读取，不能拿另一台同名项目标识执行。账号切换、目录变化和移除电脑清除尚未发送的选择，发送结果未知时保留原电脑与请求标识。

没有在线电脑时卡片写“需要一台在线的电脑”。曾连接且 S7（离线任务）加密材料可用时，提供现有“交给电脑，上线后做”入口；明确选择才登记，卡片本身不自动排队。没有电脑的账号说明“在电脑上安装 WeftMate，用同一账号登录，就能在电脑上做事”，保留现有添加电脑入口。旧云不支持 S7 时不探测新路由，也不假称已排队。

手机独立使用和 M3-A 离线对话仍为 `chat`。手机的纯聊天模型不能操作电脑；需要电脑的交代只能通过明确的工作卡片 / S7 入口。手机工具能力按原生包后续接线，本包共用网页接入相同模式呈现，不虚构手机电脑工具。

MEM-7 的“来自手机”是已经摄取的只读历史，归对话，不能直接变成可执行原生会话。现有从只读历史继续的入口先建立正常可写对话，并保留来源引用；随后才能转换工作。不能因归位重上传、重新形成、清除手机原文或扩大来源许可。原来未实现的“同一只读历史续聊”不由本包伪造。

## 旧客户端兼容

安卓 0.8.33、现版 iPhone、电脑 preview.6 保留已发布 API（应用接口）形状：`kind`、`projectId`、原 session（会话）路由、历史分页、命令目标和审批回执均保留。新字段可忽略，工作仍是原项目对话。旧客户端对新电脑的普通聊天也受电脑工具模式边界保护；旧审批没有项目选择时不能意外授权电脑动作，给出需要选择项目的人话提示。新版客户端对旧电脑不宣称已有模式保护。

项目移除、项目修订、文件夹更换、记忆模式、共享对话、临时对话保持各自原规则。工作项目被移除后保留 `mode:work` 与电脑归属，重新选择有效文件夹才能继续，不能退为聊天再偷偷使用独立工作目录。

## 待定

以下默认直接实施，不等待确认；涉及新增跨电脑内容搬运的产品选择先保留事实边界。

1. **小纬本身被转换后如何继续聊天。** 默认原聊天连同历史移入工作，新建空“小纬”主入口。理由：同时满足“同一段历史都在工作”和对话区仍有固定小纬；不复制同一轮与记忆来源。
2. **已在一台电脑回答的聊天，转换时能否选另一台电脑。** 默认沿用当前聊天所在电脑；新建工作可任意选在线电脑。理由：M3-2 明确现有会话不跨电脑接续，两台记忆各自独立；跨电脑转换需要传输完整历史、附件、来源及撤销信息，不能仅换 `hostId`。卡片保留电脑身份，其他电脑说明需新建工作；跨电脑原段迁移为后续独立包，不能冒称已经支持。
3. **工作能否切回对话。** 默认本包只做对话→工作。理由：本人明确了此方向；工作返回纯聊天涉及已有任务、文件与历史如何处理，不能把仍在运行的工作改成对话。
4. **联网查资料是否纯聊天。** 默认本包现有电脑 `web_fetch/web_search/browser` 都触发工作卡片。理由：它们真实使用电脑网络、浏览器及本机文件快照；未来可以增加无需电脑的纯数据联网查询，但不将现有副作用工具伪装为纯聊天。
5. **普通提醒与执行型定时事项。** 默认纯提醒可在对话登记；要电脑执行的定时事项触发工作选择并绑定文件夹。理由：不破坏日常提醒，同时不让未来自动任务绕过电脑模式。
6. **电脑项目默认写权限。** 默认保持现有项目权限，新文件夹沿现有只读默认与可读写选择。理由：模式切换表示想工作，不等于批准覆盖、删除或扩大文件范围。
