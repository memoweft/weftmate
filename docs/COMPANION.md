# 精灵、健康与记忆

> 依据：本人 2026-09-28《AI 健康宠物精灵 · 概念总结》（原文存于 `WeftMate/References/`）与 2026-10-06 对完整使用画面的描述。本文件是精灵 / 健康 / 相关记忆的产品规范；排期见 `PLAN.md` M4。

## 1. 精灵是什么

精灵是 WeftMate 的**可视化载体**：同一个账号、同一个助手，在电脑、手机、手表上以一只精灵的样子出现，负责陪伴、提醒和反馈。它有记忆、会互动，背后是 WeftMate + 本地模型 + MemoWeft。

> 已定（本人 2026-10-07）：精灵是**同一个助手的另一种呈现**——共用记忆与账号，说话的就是 WeftMate，语气可以更像精灵。

## 2. 核心：双向闭环，不是单向镜像

- 精灵的身体状态映射你的身体与情绪状态。
- 单向镜像会形成死亡螺旋（你蔫 → 它蔫 → 你看了更难受），所以精灵**同时是干预手段**：你抚摸它、跟它说话、安慰它，你的状态回升，它也跟着回升（照顾者效应、表达性倾诉）。
- **共情 + 可执行的出口**：先共情（「咱俩今天都蔫了」），再给一个小行动（「出去走十分钟吧」「今晚早点睡？」），不只复读情绪、不扣分。
- **不做死亡、不做惩罚**：只会「蔫」，并且可恢复（本人 2026-10-07 确认）。

## 3. 精灵状态

| 维度 | 含义 | 来源 |
|---|---|---|
| 能量 | 身体电量 | HealthKit / Health Connect：睡眠、HRV、静息心率、活动量 |
| 压力 | 紧绷程度 | HRV、心率、呼吸频率 + 对话 |
| 情绪 | 效价 × 唤醒度 → 平静 / 愉悦 / 焦虑 / 低落 | 对话文本（为什么难过）+ 自评 |
| 舒畅度 | 短时互动效果 | 抚摸、聊天后回升 |
| 成长 / 亲密度 | 长期维度 | 相处时长、互动、共同经历 |

外在表现：表情、动画、说话语气。

**分层原则**：规则 / 小模型 + 个人基线算数值；LLM 只做解释与归因。分数是游戏化表达，不是医疗诊断；情绪是推断，要标注不确定性。

## 4. 三路输入

1. **身体（HealthKit / Health Connect）**：心率、HRV、静息心率、睡眠、呼吸频率、步数与活动、锻炼。手机/手表本地汇总后上传**摘要**（如「昨晚睡 5 小时 40 分」「今日 HRV 低于个人基线 20%」），不上传原始流。擅长判断身体多累多紧绷。
2. **对话**：当天与近期对话中的情绪与事件，按时间对齐身体数据，回答「为什么」。
3. **自评**：少量主动询问「现在感觉怎么样」，作为个体校准，对抗咖啡、缺觉、运动等干扰。**频率由用户在设置里调**（含关闭），默认克制。

## 4b. 健康指标、统计与建议（本人 2026-10-07，参考 PeakWatch）

定位仍是**陪伴**，但功能上提供实打实的数据。指标计算与「随时瞄一眼」的呈现参考 PeakWatch（基于 HealthKit 的恢复 / 身体电量类应用）；表达方式是精灵与对话，不做成以数字为中心的教练仪表盘。

| 指标 | 含义 | 主要输入 | 计算原则 |
|---|---|---|---|
| 身体电量 | 一天里还剩多少电，随时间变化 | 睡眠恢复充电；活动、压力、清醒时长消耗 | 早上由恢复度定起点，白天按消耗与压力扣减、休息回升 |
| 恢复度 | 今天适合发力还是休息 | 夜间 HRV、静息心率、睡眠时长与质量、呼吸频率 | 与**个人基线**（近 14–30 天）比较，而非人群标准 |
| 消耗 / 负荷 | 今天和近期身体承受了多少 | 心率区间时长、活动能量、锻炼；近 7 天 vs 近 28 天 | 急慢性负荷比，提示「最近练多了 / 动少了」 |
| 实时压力 | 此刻的紧绷程度 | 静息状态下的心率与 HRV（手表采样） | 在设备上计算；采样稀疏时给区间与不确定性 |
| 睡眠 | 时长、规律性、阶段（有则用） | HealthKit 睡眠分析 | 与个人基线和作息规律比较 |

- **计算位置**：指标在 iPhone / Watch 本地计算（与 PeakWatch 一致，原始样本不出设备）；向服务端上传每日摘要与**白天按小时的聚合**（身体电量、压力区间），供精灵状态与 MemoWeft 使用。
- **统计**：健康页提供今日卡片与 7 / 30 天趋势（身体电量曲线、恢复度、睡眠、负荷）；简洁，不堆图表。手机小组件、手表表盘复杂功能与手表 App 可随时瞄一眼身体电量 / 压力 / 恢复度。
- **AI 分析与建议（由精灵说出）**：结合指标 + 近期对话 + 长期记忆给出解释与建议，例如「这周恢复度一直偏低，你提到连着加班——今天别跑间歇了，散步 20 分钟更合适」。建议覆盖运动（练 / 歇 / 强度）、睡眠、喝水、久坐、放松；精灵规则（第 6 节）可把建议变成提醒。
- **记录**：系统自动记录的数据之外，可在对话里随口记录（「今天跑了 5 公里」「喝了三杯水」「心情一般」），作为自评与补充数据写入；健康页可查看与修正。
- **边界不变**：分数是游戏化与陪伴表达，不是医疗诊断；明显异常（如静息心率持续偏高）只提示「留意、必要时咨询医生」，不下结论。

### H3 设备端计算口径（`weftmate-h3-v1`）

实现位于 `apps/apple/Packages/WeftMateCore/Sources/WeftMateCore/HealthDeviceMetrics.swift`，全部是无 HealthKit / 网络依赖的纯函数；iPhone 与 Watch 的只读适配器提供已启用且已请求授权的数据。没有人群标准或医学阈值。原始样本和睡眠区间只存在设备计算内存中；本地文件、上传队列和本人电脑只保存日 / 小时摘要。H3 强制 `cloudModelAllowed=false`，包括旧 H1 选择允许云模型的账号；宿主拒绝带云许可的 H3 摘要。AI 建议、对话记录、自评、小组件与表盘另包。

**依据与差异**：参考 [PeakWatch 恢复度](https://doc.peakwatch.co/en/recovery.html)、[身体电量](https://doc.peakwatch.co/en/battery.html)、[实时压力](https://doc.peakwatch.co/en/stress.html) 的个人基线、活动消耗和离散采样口径。其公开文档未提供完整计算公式；PeakWatch 当前公开恢复基线是 60 天，身体电量跨日累计。WeftMate 按本节要求使用 14 天个人恢复基线、7/28 天负荷窗、主睡眠起床时重新设定电量；系数是本项目可审查的陪伴估算，不宣称数值与 PeakWatch 相同或临床验证。HealthKit 使用 [SDNN](https://developer.apple.com/documentation/healthkit/hkquantitytypeidentifier/heartratevariabilitysdnn)，不将 SDNN 当作 RMSSD。

| 指标 | H3 v1 公式与缺数据行为 |
|---|---|
| 睡眠 | 保留 H1 的 asleep 并集与最后起床日期归属；最长已完成睡眠为当日主睡眠，白天睡眠同等处理。阶段重叠按 deep → rem → core → unspecified 取唯一归属，阶段合计不超过睡眠时长。连续度 = 主睡眠 asleep 时长 / 首段入睡至末段起床跨度 × 100（不宣称医学睡眠效率）。时长分 = clamp(当天总时长 / 前 14 个本地日历日个人均值 × 100)。规律性 = 主睡眠时间中点与前 14 天有数据主睡眠中点的平均圆周时差（0–720 分钟），夜班不因白天睡觉扣分。 |
| 恢复度 | 主睡眠内 HRV / 呼吸率样本均值、当日静息心率、睡眠时长与连续度。HRV 分 = clamp(70 + 100 × (今天 / 基线 − 1))；静息心率和呼吸分符号相反；睡眠分 = clamp(70 + 时长分 − 100 + 连续度 − 100)。权重 HRV .40、静息心率 .25、睡眠 .25、呼吸 .10，缺项按剩余权重重归一化。基线为此前 14 个本地日历日的有效均值，夜间指标只比较已记录睡眠内样本；无正基线则该项省略，全部缺失则不输出分数。`inputs/baselineDays` 显示依据和最少有效基线日数。 |
| 消耗 / 负荷 | 相对单位 = 活动能量(kcal)/100 + workout 活动分钟/10 + 心率分区加权分钟/10。分区以自身当日静息心率倍数 <1.2 / 1.2–1.5 / 1.5–1.8 / 1.8–2.1 / ≥2.1 分配 0/1/2/3/4 权重，不使用估计最大心率。只计真实心率样本覆盖区间，瞬时样本计 1 秒，重叠区间取最大权重，不跨稀疏样本插值。能量、锻炼和心率是组合贡献，数值不是卡路里、TRIMP 或 PeakWatch 负荷分。急慢性比 = 此前完整 7 天均值 / 此前完整 28 天均值，排除当日未完成数据；要求各日输入组成一致且慢性均值 >0，缺失日不补零，否则省略比值并显示实际日数。 |
| 实时压力 | 在未记录睡眠 / 锻炼 / 附近 ±5 分钟步数活动的 HRV 样本处，匹配时间差 ≤5 分钟的最近心率；同一 HRV 只计一次。分数 = clamp(30 + 100 × (HR / 个人静息基线 − 1) + 100 × (1 − HRV / 个人睡眠 HRV 基线))。每小时样本最小 / 最大分向外扩展：少于 3 组各扩 20 分（sparse），其余各扩 10 分（sampled），裁切到 0–100。区间是可审查的启发式不确定性表达，不是统计置信区间；没有记录活动不证明静止。没有配对样本或必要基线则没有压力值，不沿用旧小时到当前；展示实际最近采样时间。 |
| 身体电量 | 首次有效主睡眠起床以恢复度为起点，之后跨午夜保留；当日主睡眠实际起床再次重设。每小时积分：睡眠每小时 +8，清醒每小时 −1.5，观测压力均值 /20 每小时扣减，能量/100 和 workout分钟/30 扣减；压力均值 <20 的休息小时 +2。小时中途起床只对起床后部分积分，小睡充电不重设；裁切 0–100。未读取活动 / 压力时只计已知贡献和清醒基础消耗，始终标为估算；没有任何恢复起点则不输出电量。 |

小时用绝对 UTC 开始 / 结束时间，按汇总时区日历分桶；夏令时一天可有 23 / 25 桶，部分当前小时截止实际汇总时间。换时区按当前日历重新计算，主睡眠仍按起床日期归属，不把跨午夜和白天睡眠拆成两个恢复日。刷新读取 30 个展示日期加 28 天负荷历史和一个跨日睡眠边界日，回填最近 30 天；首次回填最早记录可能没有完整基线。

iPhone 在健康页激活 / 刷新时读取、计算并重放 H1 账号与宿主隔离队列；离线、404/501、服务器失败均保留队列。一次上传一个日期的完整日与小时摘要，仍是 H2 的幂等 upsert / 撤权删除。Watch 健康入口显式请求只读授权并本地计算；手表不持有宿主 Cookie，也不另起重复上传队列。HealthKit 已同步到 iPhone 的 Watch 记录由 iPhone 重新计算后上传。没有新增后台采集权限、实时锻炼会话或持续传感器采样，小时聚合不等于每小时保证后台执行。某次查询失败时暂不产生新的复合指标，H1 原始日均值仍可保留并标 failed；应用内关闭输入会立即丢弃依赖它的复合指标并重算，不留下旧电量 / 压力。

## 5. 与 MemoWeft 的结合

- 健康摘要作为 **observed（观察到的）证据** 写入 MemoWeft，带设备与时间来源，与「用户说的」「助手推断的」分开。
- MemoWeft 趋势模块从多次出现的同类状态归纳规律（「这周三天没睡好」「加班后 HRV 都偏低」）。
- 召回时把三类结合：**长期理解**（你说过熬夜后容易头疼）+ **近期对话**（这周提了几次加班）+ **健康趋势**（睡眠与 HRV 下降）。精灵和对话都用同一份召回。
- 说的是「从你的数据里长出来的话」，例：「你这周三天没睡好，HRV 也掉了，咱俩今晚都早点睡？」以及「你上次丧的时候是散步缓过来的」。
- 回复用到健康或记忆时，显示依据标签（「参考了你这周的睡眠」），可点开查看、纠正。
- 健康数据能否交给云端模型**由用户决定**：首次授权健康数据时询问，之后可在设置中随时更改；用户选择前只给本地模型使用。

## 6. 交互

| 交互 | 说明 |
|---|---|
| 抚摸 | 手机触摸 / 手表点按 + 触觉反馈，提升舒畅度（双方的） |
| 聊天 | 与精灵聊天就是与 WeftMate 聊天，记得你、看得到当天健康 |
| 精灵规则 | 用户在对话里说「提醒我喝水」「久坐一小时提醒我」，生成一条规则，精灵在合适时机提醒；规则可在对话中改和删 |
| 任务反馈 | 任务完成 / 需要审批时，手表震动 + 精灵提示 |
| 主动关心 | 健康明显变差、情绪低落、有建议时主动出现；频率由「活跃度」决定（见第 7b 节） |

## 7b. 精灵是信息传递的载体（本人 2026-10-07）

- 精灵是 WeftMate 在手表、手机、电脑上**传递信息的统一载体**，只是各端表现形式不同（手表：表盘 / 震动 / 一句话；手机：小组件 / 通知 / 对话页头像；电脑：桌面角落小窗 / 气泡）。
- 经精灵传递的信息包括：任务完成、需要审批 / 回答、精灵规则提醒（喝水、久坐…）、健康变化与建议、主动关心与问候、共养伙伴的状态变化。
- **任何时候都可以提醒**；不预设安静时段（用户可自行设置免打扰时段）。
- **活跃度由用户决定**，一个滑杆从「关闭」到「拉满」：

| 活跃度 | 行为 |
|---|---|
| 关闭 | 不主动出现；只在你找它、或任务需要你审批 / 回答时出现 |
| 低 | 加上：任务完成、你设的精灵规则提醒 |
| 中（默认） | 加上：健康明显变化、每日一次简短问候或建议 |
| 高 | 加上：更频繁的关心与建议、发现值得说的事就说 |
| 拉满 | 尽可能陪伴：随时互动、主动搭话、实时反馈状态变化 |

各端可单独覆盖（例如手表只要震动、电脑拉满）。

## 8. 共养

- 和好朋友、伴侣**一起养一只精灵**，可以互相查看对方的状态（共享范围由各自决定，默认只共享精灵状态，不共享原始健康数据和对话）。
- 退出共养后记得过去、知道关系已变化；结束关系与删除记忆分开（见 `VISION.md`）。
- 后续：会员共享（开通会员可共享给伴侣）。

## 9. 边界

- 健康陪伴，不是健康教练，更不是医疗器械；分数是游戏化表达。
- 它是情绪练习场，不是终点，不替代真实人际连接。

## 10. MVP 顺序（来自概念文档，按 WeftMate 主线调整）

1. 只读 HealthKit → 设备端计算身体电量 / 恢复度 / 压力 / 负荷（第 4b 节）→ 精灵表情 + 健康页今日卡片与趋势 + 小组件 / 表盘（验证镜像有效）。
2. 加入聊天（本地模型）+ MemoWeft 召回（近期对话 + 健康趋势）；精灵给出运动与健康建议；对话中随口记录。
3. 加入抚摸与舒畅度（验证双向闭环）。
4. 精灵规则（喝水、久坐）与任务反馈（手表震动）。
5. 自评校准；共养。
