# 同账号的多台电脑（M3-2 / M3-4）

每个端注册后都完整可用（D61），电脑是可选的添加项。第二台电脑登录同一账号，直接使用自己的对话、模型设置和记忆；**本包两台电脑的记忆暂时各管各的**。不搬文件、不接力正在执行的任务、不实现 Mac 执行电脑。

## 查到的现状与实现方向

云 `host_memberships` 的主键是 `(host_id,account_id)`，已经允许一个账号多台电脑；`cloud_hosts` 保存安装公钥，电脑 `rootState.hostId` 与安装密钥持久保存。中继 `host_relays`、独立域名、凭据、控制和内容连接均按电脑登记，可以同时连接多台，没有账号广播。`GET /sessions` 已带 `hostId`，命令的 `targetDeviceId` 必须等于本机。S7 的信封、领取、回执均绑定账号与目标电脑，不能改目标后转发。缺口：`CloudAuthClient.config.hostId`、`core.accessBase`、手机当前身份与离线副本只有一个当前电脑；设备页用同名匹配电脑与登录设备，网页“连接”会跳转整页，列表只读当前电脑。

保留现有身份与中继，不重造执行队列。已有云目录响应增加 `capabilities.multiHost:1`，签名撤权回执也带此位；缺省不启用、不探测新接口。迁移最初编号010，合入S4后顺延为011，只新增移除状态与取消回执两张表；原表不改。新目录带明确电脑关联和区分后的显示名称。只有一台电脑，原响应条目与界面保持原样（能力字段为可选扩展）。各电脑认证与内容 TLS（加密传输）仍分别终止在该电脑；浏览器通过电脑同源的小型认证消息通道访问，云不汇总内容。

电脑程序的对话列表与默认执行始终属于这台电脑，设置里可管理同账号的电脑；手机和远程网页才合并列表与选择执行位置。避免电脑窗口在后台刷新时因另一台的新对话而自动换执行电脑。电脑认证通道凭据只在页面内存保留，离线副本接口只接受原 Cookie（会话凭据）或同样已核对的云设备内容凭据，原普通接入凭据不取得副本权限。

## 身份、状态与选择

电脑名默认操作系统电脑名，合成测试使用 `synthetic-desk` / `synthetic-laptop`。设置 → 设备可以改名、移除；同名按稳定身份顺序附加“(2)”等后缀。移除撤掉云登录、成员与访问，不删除本机文件、对话、模型或记忆；本机继续可用。换账号保留各自本地账户映射，旧账号不再拥有这台电脑的远程入口。

目录分别显示哪台在线；手机合并各在线电脑的对话，只有登记电脑确实多于一台时显示小电脑名。离线条目保留当前页面最近列表；已有 M3-A 加密副本能提供只读历史，未缓存内容明确说“这台电脑不在线”。会话、项目、文件、审批及工具都归属原电脑，打开后不能切换这段对话的执行电脑。新对话：一台在线就选它；多台在线沿用上次使用的一台，否则用目录第一台；项目会话、分叉和已有普通对话继承来源电脑。输入区复用模型菜单风格的纯图标电脑按钮，仅多台出现，选中底色表示当前选择。助手在措辞有歧义时在对话里问要用哪台，不弹配置页。

消息的电脑身份随发送意图固定，重试不重新择机；继续使用原命令 `requestId`（幂等编号）账本，一条消息只会到一台。离线派发选目标电脑，复用 S7 已缓存的该电脑接收公钥与代次，缺少材料时说明先连接一次。目标移除后取消尚未完成的离线任务并清除密文，手机显示“电脑已移除，任务已取消”。执行中的本地任务保留在本机继续完成，撤销远程控制与通知，不假称撤权可以撤销已经发生的文件操作。多台时审批、动态与通知标出所属电脑。

## D42 主对话与记忆：下一包方案

| 方案 | 好处 | 工作量与坑 |
|---|---|---|
| (a) 每台各管各的 | 现状即可运行；离线完全独立 | 同账号两个主对话、两套记忆，跨端承诺不完整；本包临时行为 |
| (b) 电脑互相同步 | 任意电脑离线时仍有完整记忆 | 最大：MemoWeft 来源、认知修订、遗忘级联与任务账本要双向冲突处理；不能简单复制数据库 |
| (c) 一台保存正式记忆，其余取副本、补交 | 复用 M3-A / S6 加密副本与上交边界；符合 D63“有电脑就全部交给电脑” | 中等：现在副本按电脑/账户/设备隔离，需让第二台电脑成为获准接收设备；不能把召回或副本伪装为本人新话；主对话需要账号级目录与本地执行片段关联 |

推荐 (c)。下一包先把第一台电脑作为默认记忆所在电脑（设置中可明确换），账号控制面只存其身份；扩展现有设备副本协议给电脑端，保持同样的删除代次和密钥撤销；非记忆电脑的本机执行对话保留本机，真人/助手新回合按稳定来源 ID 上交原 `ingest_boundary`，正式记忆只在记忆电脑形成。D42 主对话的显示身份统一，执行片段仍指向实际电脑；离线只用已获准的加密只读副本。先补 `/offline/turns` 的会话映射回执，再做主对话接续；选择/更换记忆电脑需明确迁移流程、旧来源去重与真正遗忘，不能静默选另一台或合并两份已有记忆。记忆电脑移除前提示另选一台并迁移；未迁移期间各端仍聊天与本机执行，正式形成等待原电脑或迁移完成。

FIX-33 版本交叉兼容：先读目标电脑自己声明的 `cloudChannel`、`offlinePhoneFirst`、`modelServices`；缺字段完整使用旧会话凭据、旧模型目录和旧同步正文，不先探测新路再回退。云端 `multiHost` 只说明目录支持多电脑。连上且在线的新对话默认由电脑执行；手机既有独立对话保留其来源，能力操作从新电脑对话开始。
