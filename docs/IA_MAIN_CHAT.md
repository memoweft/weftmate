# 逻辑对话、执行接力与页面结构

本文说明仍在使用的逻辑身份、历史分页、执行接力，以及聊天、动态、目标、成果库的职责。产品入口以 [DECISIONS](DECISIONS.md) D92 和 [WORK_AND_CHAT](WORK_AND_CHAT.md) 为准；接口字段与兼容错误见 [CLIENT_API](CLIENT_API.md) 第 9 节，安装验收结论见 [项目地图](../PROJECT-MAP.md) 第 4 节。

## 1. 对话与工作入口

- 侧栏以「对话／工作」切换同一块列表；工作按项目分组，新建跟随所选模式。程序打开进入可发送的新对话。
- 工作首条发送前选好电脑和文件夹，工作开始后不换电脑，不能切回对话。对话实际需要电脑工具时，在原回合选择「切换到工作」，随后仍执行原项目权限与审批。
- 不再提供置顶的特殊主对话、消息菜单「从这里开旁聊」、输入区「开旁聊」或模型建议的专用开聊入口。普通新建、临时对话、原生分叉及助手重新生成各保留自己的语义；已处理的用户消息不得编辑或重发（D49）。
- 原主对话以所属模式中的普通历史项呈现，保留标题、全部分段历史、记忆来源和后台投递目的地。`kind:main`、`mainChatId`、`/chats/main` 及底层生命周期保护为兼容保留，不能因入口取消而删除。

实现入口：[work-and-chat.mjs](../src/personal-access/work-and-chat.mjs)、[会话列表](../src/personal-access-ui/components/sessions.js)、[共用会话功能层](../src/ui-core/sessions.js)。

## 2. 身份与来源

| 实体 | 现行语义与实现 |
|---|---|
| 逻辑对话 `chatId` | 账户内稳定导航与历史身份；不复用同步／共享的 `conversationId`。由 [chat-identity.mjs](../src/personal-access/chat-identity.mjs) 关联原生会话 |
| 兼容主聊天 `kind:main` | 每账户一个；可有多个执行段，空记录尚无原生会话。界面普通显示，底层仍限制删除、归档、分叉及组织移动 |
| 其他聊天 `kind:side` | 原有普通会话与项目会话的一对一逻辑映射；底层父级仍为主聊天或项目，不表示界面还存在主／旁聊层级 |
| 执行段 `segmentId` | 归属一个 `chatId`，指向确定的 `(hostId,sessionId)`。新输入发当前段，旧任务、命令、回执与来源保持原段绑定 |
| 项目与分组 | 项目承载工作目录、说明与权限；分组只分类。移动项目从下一回合生效，不搬文件、不改旧来源 |
| 来源 | 保留原 `(sessionId,seq)`、`requestId`、`commandId`、`receiptId`。摘要引用与结果卡是派生资料，不成为新的真人消息或记忆证据 |

`mode:chat|work` 是产品模式，不能覆盖 `kind:main|side`、审批 `mode` 或发送 `queue|steer` 的含义。历史身份迁移不重放命令、不重新摄取原话、不为旧完成任务补发通知。共享会话仍按原成员授权读取，不因逻辑归类而扩大个人来源范围。

逻辑主聊天跨段复用同一工作目录；项目绑定按当前实际工作上下文生效。其他会话保留自己的工作目录与经验。长期记忆按账户共享，项目、会话与模型只是来源和上下文，不能各建独立记忆世界（D11、D37、D80）。

## 3. 历史、日期与分页

实现：[chat-timeline.mjs](../src/personal-access/chat-timeline.mjs)、[原生历史投影](../src/runtime/dsh-adapter/sessions.mjs)。

日期是显示边界，执行段是上下文边界。日期使用账户时区；一天可以有多个执行段，一个执行段也能跨天。午夜不强制开新会话、不产生消息。改时区会重新分日，不改事件身份和原生顺序。

- 初次读取尾页，默认最近 50 个公开条目，`limit` 为 1–200；向前、向后和锚点读取分别使用返回的游标。
- `eventId` 从原生来源或产品记录身份确定，重建索引保持不变；按 `revision` 合并更新，按宿主返回的 `orderKey` 排序，不按设备时钟重排历史。
- 历史页不覆盖已建立的增量水位。增量只续传 `nextCursor`，包括旧段迟到事件、更新与不含正文的 `removals`；空页也可推进。
- 日期查询返回有记录的日期及条目数；定位无记录的日期时返回空锚点和相邻日期。搜索只查可见用户／助手消息与结果摘要，不搜索隐藏推理和原始工具输出。
- 游标绑定账户、逻辑对话、索引代次、用途与过滤条件，客户端原样续传。409 `CURSOR_RESET_REQUIRED` 后清旧缓存，再取尾页或保存的锚点。
- 较早内容渐进建立内存索引，`indexState:building` 时日期和搜索是部分结果，不能说没有旧历史。工具详情仍按原 `sessionId/seq` 读取。

页面保留视口附近的正文；展开、高度、选择与焦点按稳定消息身份保存，上翻插入时用首个可见消息和像素偏移保持位置，读旧历史时新消息不强制拉到底部。共用窗口管理见 [chat-window.js](../src/ui-core/chat-window.js)，呈现规则见 [UI_SPEC](UI_SPEC.md)。

公开历史投影缓存由 [history-cache.mjs](../src/runtime/dsh-adapter/history-cache.mjs) 管理，存于宿主的 `weftmate-history.sqlite`。读取先核原生修订，缓存命中可以范围查询；源日志改变或首次未命中仍需原生解码重建。逻辑接口返回有界页，不代表 DSH 原生冷读取已有物理范围保证，不能据此宣称首次打开任意长历史都达到固定耗时。

## 4. 执行接力

实现：[main-chat.mjs](../src/personal-access/main-chat.mjs) 协调持久命令与段切换；[personal-access-backend.mjs](../src/personal-access-backend.mjs) 调用内部网关；[chat-handoff.mjs](../src/runtime/dsh-adapter/chat-handoff.mjs) 复用 DSH 的容量测量、压缩和会话生命周期。

接力保留在兼容主聊天，不为其他聊天启用自动多段接力。取消特殊入口不改变这项机制。

1. 使用实际模型上下文容量、对应压缩阈值及已发生的压缩事实记 `relayPending`，不按消息条数或费用累计词元切段；容量未知时不猜压力比例。
2. 在下一发送的空闲边界检查：原生回合结束、收件队列空、无待审批／待回答、未确认副作用、活跃后台任务或未结束长期目标。执行中只由 DSH 自身压缩，不以停止任务换段。
3. 复用原生 `compactNow`，按模型可见上下文节点组织交接资料、来源引用及未完成事项，排除旧记忆召回与特定插件注入。交接文字超过目标窗口的 20% 或容量未知时拒绝发布。
4. 持久保存已分配的新段身份，创建原生会话并安装带来源水位的交接资料，复用逻辑目录、模型及审批设置；安装可按同一来源水位核对重放。
5. 新段就绪后原子更新 `activeSegmentId`，旧段封存。已受理请求保留旧绑定，尚未派发的逻辑命令只绑定一次，不能同时发往两段。
6. 重启按保存阶段恢复：未发布仍用旧段，已发布用新段；未完成的新段复用原分配身份。准备摘要失败时保留旧段并记录失败，不循环创建新段。

定时规则保留原生 `(sessionId,id)` 管理身份；以逻辑聊天为目的地的触发，通过同一命令队列选择当时当前段。未来定时触发不永久阻塞接力，长期目标不跨段复制。旧段后来的管理事件仍进入统一历史增量。

## 5. 记忆、临时内容与清理

记忆规则以 [MEMORY](MEMORY.md)、D16 和 D33 为准。接力本身不是新的真人输入，不重复形成；下一真人输入按原流程召回。近期尚未整理的原话桥最多 4 条／900 字符，与正式召回共用预算，不用整条历史替代召回。

临时对话 `memoryMode:off` 不形成新记忆，已有记忆的召回开关独立。临时原话不进入近期原话桥或全局成果库；显式保留与分享须沿临时内容的确认契约，不因换段或逻辑归类自动变为普通内容。

[chat-erasure.mjs](../src/personal-access/chat-erasure.mjs) 与 [memory-erasure.mjs](../src/runtime/dsh-adapter/memory-erasure.mjs) 按原来源清理交接资料、结果摘要、分段索引和公开历史缓存，并提升 `contentRevision`。客户端丢弃旧正文、搜索与增量缓存，再按新代次读取；离线副本先应用删除／撤权水位，再补交原允许的内容。遗忘和聊天原话删除是两件事，原话删除默认不勾选；不能从保留原话、旧摘要或备份自动重新形成被忘内容。

这里说明清理契约，不作为彻底遗忘已验收的证明；实现与安装验收的缺口见项目地图第 4 节及 [问题 #334](https://github.com/memoweft/weftmate/issues/334)。

## 6. 聊天、动态、目标与成果库

这四类职责继续有效（D43）；手机按 D56 在聊天与目标之间增加「健康」，为「聊天／动态／健康／目标／成果库」五项。设置从头像进入，不以旧四项布局覆盖 D56。

| 页面 | 职责与动作 | 实现入口 |
|---|---|---|
| 聊天 | 当前模式的会话列表、消息、输入、审批与提问；步骤和成果仍在原对话查看 | [sessions.mjs](../src/personal-access/sessions.mjs)、[chats.mjs](../src/personal-access/chats.mjs) |
| 动态 | 提醒、任务终态、待审批／待回答、记忆周报等既有事实的投影，打开原来源或处理原动作 | [activity.mjs](../src/personal-access/activity.mjs)、[activity-store.mjs](../src/personal-access/activity-store.mjs) |
| 目标 | 进行中／排队任务、定时任务、长期目标；停止、暂停、恢复按各自原生状态与回执处理 | [tasks.mjs](../src/personal-access/tasks.mjs)、[schedules.mjs](../src/personal-access/schedules.mjs)、[goals.mjs](../src/personal-access/goals.mjs) |
| 成果库 | 跨对话文件索引，按名称、项目、类型筛选，打开、预览、下载／分享与回原出处 | [library.mjs](../src/personal-access/library.mjs)、[resources.mjs](../src/personal-access/resources.mjs) |

同一个事实在原对话、动态、通知和手表中共用来源与稳定身份。读到或标已读不代表批准，不把停止写成成功；实际动作重新核对审批／提问／任务状态。动态已读在账户内同步，全部已读只到已取得的快照，新内容仍未读。

有来源的提醒和后台任务继续投原会话；无指定来源而原本默认投主聊天的内容继续投账户原逻辑聊天，并更新普通历史项的未读／状态。该聊天已转工作也不另造空主聊天，纯提醒不因此取得电脑执行权限。

旧旁聊创建、结果回写及 `side.result` 仍是兼容接口与历史记录，细节见 CLIENT_API 第 9.4 节和 [side-chats.mjs](../src/personal-access/side-chats.mjs)。结果引用不伪造原生助手消息、不启动主聊天模型、不重复形成记忆；这不要求新版界面恢复专用开旁聊入口。

目标总览不建立第二个执行器；长期目标与一次任务不同，不凭空计算完成百分比。成果保留产出时的项目与原来源身份，移动会话不移动旧文件，归档保留成果，删除沿原授权边界。通知遵守账户类别开关、设备设置、勿扰与宿主决定，系统通知送达能力不能从动态条目存在推断。
