# WeftMate 产品边界

## 一句话定义

WeftMate 是用户在 Windows 上使用 DSH，并在能力成熟后统一使用 MemoWeft 与 AI-GAME 的唯一桌面产品入口。

成熟的 Android 能力从一句自然语言结果开始：DSH 在原对话中自主追问到信息充分并形成用户可控的任务单，AI-GAME 随后在模拟器中自主观察、思考、聊天、操作、等待和恢复，MemoWeft 保存用户允许长期复用的个人偏好。用户不需要操作端口、执行器或内部运行模式。

## 所有权

| 组件 | 权威职责 | WeftMate 的职责 |
| --- | --- | --- |
| DSH | 会话、消息、输入、Agent、模型、工具、权限、审批、计划、工作区、`userQuestions` | 固定版本组合、Windows 外壳、生命周期与安全凭据 |
| AI-GAME | Android 模拟器 Task、Profile、观察、动作、验证、等待、恢复和执行经验 | 启停与健康管理、产品语言设置、原对话结果与控制入口 |
| MemoWeft | 个人长期记忆与共同世界 | 在稳定接口存在后接入、展示与管理 |
| WeftMate | 产品窗口、配置、安装、更新、诊断和跨系统交互 | 不复制其他组件的内部状态机 |

## 不变量

- “功能按照 DSH，只换外壳”：官方 DSH client graph（客户端插件图）是对话功能的唯一来源。新增能力使用 additive seam（增量接缝），不 fork（分叉）官方前端、不另写第二套会话或审批系统。
- WeftMate 是唯一面向用户的聊天界面。AI-GAME 和 MemoWeft 不建立第二个普通用户工作台。
- 外部系统故障必须局部降级；普通 DSH 对话始终可启动。
- 密钥只在 Electron main（主进程）的受保护存储和最小 IPC（进程间通信）边界内出现，不进入 renderer（渲染进程）、普通配置、URL、日志或诊断。
- 设备工作只面向用户选择的 Android 模拟器。
- 产品状态来自后端事实；未知就显示未知，不用假数据、固定百分比或成功文案补齐界面。

## 当前公开面

当前正式可见的是 DSH 官方工作台、WeftMate 原生窗口/主题/凭据能力，以及原对话中的 AI-GAME 工具结果和安全详情投影。

当前不公开 Android 模拟器设置和全局任务中心。原因不是放弃方向，而是 WeftMate 尚未拥有 AI-GAME 的安装、启动、健康、停止和退出收口。任何依赖用户先手工启动 4310 的入口都不满足产品边界。

底层 V2 Task、模拟器 Profile、通用执行器和任务中心组件可以作为工程基础保留；“代码存在”不等于“产品入口已交付”。

## 授权边界

WeftMate 自有代码、二进制、视觉资产和文档受本仓库 `LICENSE` 专有授权约束。DSH 按 MIT 与上游许可证执行；AI-GAME、MemoWeft 和其他第三方组件继续遵循各自许可证。

WeftMate 不 fork 官方前端，也不复制或长期分叉维护 DSH 官方客户端。缺少桌面接缝时只增加小型、可独立测试的官方扩展。
