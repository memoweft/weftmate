# WeftMate 产品定义

> 本文件只回答“产品是什么、边界是什么”。
> 当前进度看 [`../CURRENT.md`](../CURRENT.md)，阶段顺序看 [`ROADMAP.md`](./ROADMAP.md)，代码审计看 [`../PROJECT_ANALYSIS.md`](../PROJECT_ANALYSIS.md)。

## 1. 三层关系

| 层 | 定位 | 负责什么 | 不负责什么 |
|---|---|---|---|
| MemoWeft | 完全开源、社区驱动的个人 AI 记忆能力层 | 证据、经历、认知、画像、召回、导入导出标准 | WeftMate 的 UI、人格表达、Agent、商业产品体验 |
| WeftMate | 面向普通用户的专有桌面个人 AI 产品，也是 MemoWeft 的官方产品验证 | 对话、人格、桌面常驻、感知、协作型 Agent、隐私控制和交付 | 重写 MemoWeft 内核、训练基础模型、制造数字生命；不承诺开源 |
| 人格 | WeftMate 中可选择、可分享的体验外壳与能力配置 | 语气、提示词、形象、声音元数据、主动度、模型建议、工具与知识配置 | 独立拥有用户记忆、复制用户、成为独立数字生命 |

必须始终保持：

- MemoWeft 是内核，WeftMate 是产品，人格是外壳。
- 人格默认使用同一份用户记忆；用户可以单独禁止某个人格读取记忆。
- 人格包可以导入、导出和分享，但绝不能携带用户画像、证据、聊天、密钥、文件路径等私人数据。
- MemoWeft 的源码、协议和社区治理属于 MemoWeft 仓库，本仓库只通过公开依赖接口使用它。
- MemoWeft 的开源属性不延伸到 WeftMate；WeftMate 自有代码、二进制、视觉资产和文档采用专有授权，MemoWeft 与第三方组件仍按各自许可证执行。

## 2. 产品一句话与第一体验

**WeftMate 是一个越用越了解你的桌面 AI 伴侣。**

用户第一次打开看到的是对话，而不是控制台、图谱或 Agent 面板。第一感受应当是：

> 它能自然记起我说过的事情，不需要我每次重新解释；它还能用我选择的人格与我长期相处。

Agent、MCP、工作区和感知是重要能力，但它们首先服务于“更贴合这个用户地帮助”，不是产品的第一句卖点。

## 3. 核心闭环

```text
相处（聊天 / 一起做事）
        ↓
用户主动表达 + AI 交互 + 用户授权的设备状态
        ↓
MemoWeft 形成可修正的事实、推测与动态画像
        ↓
WeftMate 在下一次对话、建议和协作中自然使用
        ↓
继续相处，并根据新证据和用户反馈更新理解
```

记忆不是事实认证，画像不是对人的定义。系统可以推断，但必须标明不确定性、允许用户修改或指正，并随时间和新证据变化。

## 4. 产品能力边界

### 4.1 长期记忆与用户控制

- 对话、协作结果和用户授权的感知数据可以进入 MemoWeft。
- 用户可以查看简化画像、记忆图谱、来源和原文存档。
- 默认界面保持简单，以自然语言反馈和按钮/开关为主；图谱与证据链属于按需深入的高级入口。
- 用户拥有最高修改权，产品要区分两种操作：
  - **修改**：用户重新定义当前画像，确认后覆盖当前产品层理解。
  - **指正**：用户指出 AI 推断有误，保留原始证据并通过 MemoWeft 的公开能力调整认知。
- 记忆包导入导出是用户的数据迁移权，不等同于人格包或会话导出。

### 4.2 初次认识

新用户可以选择进行一段可跳过、可中断后继续的自然对话，让 AI 初步认识：

- 职业与当前生活阶段；
- 兴趣和长期目标；
- 做事、学习与沟通偏好；
- 用户愿意提供的性格测试参考，例如 MBTI 类问题。

采访结论只能作为低把握度初始假设，不能把测试标签当成人格事实，也不能把用户一次回答永久写死。

### 4.3 人格外壳与能力配置

一个人格包可以包含：

- 名称、描述、系统提示和表达风格；
- 头像、桌面形象、声音等资源或元数据；
- 陪伴主动程度；
- 建议使用的模型；
- 可用工具、技能和专业知识引用；
- 是否允许读取 MemoWeft 记忆的用户选择。

简单陪伴人格可以只有表达与形象；工作型人格可以带工具、知识和工作方式。用户全局模型、隐私和权限设置始终可以覆盖人格建议。

当前产品把一个可切换人格呈现为一个 **Soul**。桌面宠物是 Soul 绑定的本机外观资产，不是新的记忆主体：用户可以创建、修改、删除宠物并更换绑定，但这些操作不能复制、切分或改变该人格能访问的用户记忆。宠物资产与严格 Persona Manifest 分开演进，避免为了桌面外观扩大人格包或混入本机状态。

人格资产与用户资产必须分开：

| 资产 | 内容 | 能否分享 |
|---|---|---|
| MemoWeft 记忆包 | 用户证据、经历、认知与画像 | 仅由用户主动导出和授权 |
| WeftMate 人格包 | 人格表现与能力配置 | 可以，不含用户数据 |
| 会话导出 | 某段聊天及附件引用 | 单独能力，不混入前两种包 |

### 4.4 桌面伴侣与感知

- 桌面端是当前根基：常驻、随时呼出、角色切换、理解当前设备状态。
- 感知按来源逐项授权；当前优先设备状态，手机、手表和健康数据等到对应生态接入后再做。
- observed 数据默认不上云；开启云端处理必须由用户明确授权。
- 陪伴主动度由用户调节，例如安静、轻提醒、陪伴交流。
- 宠物使用独立管理页；“唤醒宠物”是可反复切换的显示/隐藏开关，“自由活动”另行由用户开启，不能因为唤醒或感知已授权就自动开启。
- 自由活动可以响应鼠标靠近、用户在 WeftMate 输入、窗口位置和空闲状态，适时注视、靠近、避让或休息；只使用短暂的坐标和状态信号，不读取按键内容，也不把这些交互自动写入记忆。
- 移动应有与角色一致的动画和节奏，不能用生硬平移冒充生命感；角色挡住内容或被拖到屏幕边缘时应能主动避让或恢复到可见区域。
- 主动打断只允许真正重要的 P0/P1，不能因为记忆变多就变得唠叨。

### 4.5 协作型 Agent 与工作流

- 当前产品目标是单个协作型 Agent：用户提出目标，AI 规划并执行部分步骤，关键权限由用户控制。
- 未来可以演进为长期代理型 Agent，但不会因为使用更久或“更懂用户”而自动提升权限。
- 文件、工具、感知和设备权限只能来自用户明确授权。
- 基础工作流可以做；当前不做多 Agent 协同系统。
- **执行自主度**与**陪伴主动度**是两个独立设置：前者控制能否动手，后者控制是否主动说话。

### 4.6 模型策略

- WeftMate 模型无关，允许用户添加云端或本地 OpenAI-compatible 模型。
- WeftMate 的竞争力来自记忆、关系、桌面体验和协作闭环，不来自绑定某一个基础模型。
- 如果未来有官方模型服务，它只是更简单的默认选择，不能取消用户自选模型的能力。

## 5. 数据、云端与多设备原则

- 长期方向是官方云同步优先，降低普通用户门槛；这不代表当前已经有官方云端记忆服务。
- 数据控制权属于用户，MemoWeft 标准数据可导出、迁移并由其他兼容 AI 使用。
- PC、Android、iOS、watchOS 最终是同一个 MemoWeft 核心的不同终端，不是各自维护互不相干的用户记忆。
- 用户决定是否开启设备间共享，以及每个来源、终端和人格可以访问什么。
- 官方云最终保存哪些资产尚未决定，必须到多端阶段单独完成隐私与架构设计，当前不能写死。
- 邮件、日历不是近期重点；健康与活动数据属于未来设备感知范围。

## 6. 默认产品形态

- 对话是第一入口。
- 普通用户默认只看到简单选项、开关和自然语言解释。
- 画像、图谱、来源、原文和高级模型/工具配置按需打开。
- 人格在聊天入口与桌面入口都应能够快速切换。
- AI 的理解要自然出现在对话中，不要求用户每天维护一套数据库。

## 7. 明确不做

- 不在本仓库修改 MemoWeft 源码或复制其核心实现。
- 不做用户数字分身、人格复制、数字生命或替代用户作决定。
- 当前不做多 Agent 协同。
- 当前不做 Android、iOS、watchOS 客户端和官方云同步。
- 当前不做企业权限、企业 SaaS、邮件/日历生态。
- 当前不训练自有基础模型。
- 不把用户记忆打进人格包。
- 不因使用时长、画像丰富度或所谓“信任增长”自动扩大权限。

## 8. 贯穿纪律

1. **工具定义延迟加载**：上下文只放工具名和极简签名，用到再展开完整定义。
2. **主动打断只报 P0/P1**：少而准，不把陪伴做成骚扰。
3. **记忆不等于相信**：不说“真正理解你”，慢活如实说明需要时间，用户侧不露 0–1000 原始把握度。
4. **隐私可控**：observed 默认不上云；API key 用 Electron `safeStorage`；导入包和分享包明确分型。
5. **能力不等于权限**：AI 更聪明、记得更多，都不能自动获得更多文件、工具或设备权限。

## 9. 已拍板决策摘要

| 决策 | 定案 |
|---|---|
| MemoWeft | 完全开源、社区驱动，不以它本身盈利 |
| WeftMate | 面向用户的专有官方产品与最佳实践，不承诺开源 |
| 第一价值 | “这个 AI 比普通聊天助手更了解我” |
| 第一入口 | 对话 |
| 人格 | 可选、可分享的外壳/能力配置，共享 MemoWeft；可由用户禁止读取记忆 |
| 模型 | 模型无关，支持本地与云端 |
| Agent | 当前协作型，未来可代理型；目前不做多 Agent |
| 主动性 | 用户可调，执行自主度与陪伴主动度分开 |
| 多端 | 一个 MemoWeft 核心、多个终端；当前只做桌面根基 |
| 云端 | 长期官方云同步优先，但隐私可控、数据可迁移；具体云数据范围待后续设计 |
