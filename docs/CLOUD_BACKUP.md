# 云端备份 · S4 / D20 / D25

电脑把自己的数据先加密再上传；新电脑登录同一账号，进入应用后可用恢复码找回。登录无需另一台设备批准。服务器没有备份钥匙、恢复码或重置途径。恢复码和所有保存钥匙的设备都丢失，旧备份永久无法恢复。

## 钥匙与恢复码

启用在本机用 Node `crypto.randomBytes` 生成独立的 256 位主钥匙，连同恢复码存入已有系统凭据保管库，按云账号隔离；不写普通配置、日志、页面持久存储。恢复码包含 8 组，每组 8 个随机 Crockford Base32（去掉易混字符的编码）字符和 2 个 SHA-256（安全哈希）校验字符，组序号参与校验，指出输错的组。共 320 位随机熵；空格、连字符和小写可规范化，易混字符不自动猜测。校验位用于发现抄写错误，不承担密码认证。

HKDF-SHA-256（标准密钥派生）从恢复码随机字节、独立随机盐和固定协议域生成包裹钥匙；AES-256-GCM（带认证的对称加密）用独立 96 位随机数包裹主钥匙。附加认证数据绑定版本、账号和钥匙标识。云端只收包裹后的主钥匙。更换恢复码保留主钥匙，原子替换云端包裹记录后才更新本机保管库；旧码不能解开当前记录，但无法撤销攻击者已经复制的旧记录和备份。

点开启后同一弹层显示恢复码及「换电脑时要用它；我们没有它的副本，丢了就找不回备份」。提供复制、保存文本、打印；随机选一组要求输入确认，确认前不启用。再次查看／更换要求重新输入云账号密码，沿已有敏感操作账号认证；本机身份和云会话仍须有效。已登录手机取钥匙只保留后续协议建议，本包不依赖它。

## 内容、格式与节奏

以 BK-1 在线一致性捕获和恢复事务为基础：对话及原生日志、记忆数据库、账号设置、目标、定时任务、健康、用量、连接器配置、模型配置。加入属于该账号的模型 API（应用接口）密钥与连接器授权值，由同一主钥匙加密；启用处明确「包含你保存的密钥，同样只有你能解开」。安装私钥、云登录令牌、设备会话凭据、系统缓存、诊断日志不进。成果库／附件／桌面导出的文件正文、项目原地文件、工作目录用户文件不进；这些是使用者自己的文件，需在原处另行保管。保留必要的对话工作目录运行元数据与经验，恢复后文件引用可能提示原文件不可用。记忆 Core（核心运行时）工作进程租约和 SQLite（嵌入式数据库）的活动旁文件精确排除，不复制运行锁；旧包的这些条目仍须通过完整性核对，再跳过安装。

协议 `wm-cloud-backup/1`：整包快照，不做增量依赖，任意保留的一份独立可恢复。内部为已校验的 BK-1 `.wmb` 加凭据映射；内部清单、条数、设置和源程序版本都加密。外部仅随机备份 ID（标识）、版本、时间、总大小、块数、密文哈希和随机数。每块最多 1 MiB（兆字节）明文，AES-256-GCM 独立加密；附加认证数据绑定账号、备份 ID、协议、完整块数、顺序。全部块齐全、认证通过、整包哈希与 BK-1 清单通过才交给恢复事务。新于当前协议或程序版本的包拒绝并提示升级；旧格式未带程序版本的包继续按既有格式和存储校验。

官方模型配置使用固定运行时自己的 YAML（配置文件格式）解析器，依次从资料目录、开发运行时、安装包资源目录读取。三处不可用时明确失败，不省略模型配置或复制未过滤的全局配置；不产出新包、不导出凭据，保留已有备份供下一次重试。安装包资源路径与账号归属过滤另有固定运行时测试。

原生压缩会话的头部单独占一个 Zstandard 压缩帧。备份归属筛选、内容摘要和恢复迁移先定位这个帧的完整边界，再交给 Node 解压并校验；不依赖不同 Node 版本解压连续帧时的消费字节数。迁移只重写头部，后续事件帧逐字节保留；云备份头部仍受原有 1 MiB 大小限制，损坏或不完整的头部仍拒绝。

上传前在本机持久保存密文块与待传清单。云端重复开始返回已收块索引，重复同块同哈希幂等，不同内容冲突；断网、睡眠、退出后接续，不重复捕获或加密。仅确认完成后清理本机待传密文。默认每日一次，忙时推迟，不停止对话／任务；内容摘要未变化则不上传。大上传要求接电、系统网络为私人网络；无法确定时保守推迟，手动操作同样遵守。保留最近 3 份完整备份，覆盖短期误操作并避免占用小云盘；未完成上传保留 7 天，完成包不因电脑长期离线过期。

## 云接口、限额与删除

云 schema（结构版本）10 新增包裹钥匙、备份清单、分块、配额记账和清理代次表，以及现有代次增加时的删除触发器；已有表结构不变。账号登录与已有 DPoP（设备持钥证明）验证；账号从认证身份取得，不能由请求指定。全部使用精确 POST `/personal/v1/cloud/backups/{key/read,key/write,start,chunk/upload,complete,list,chunk/download,delete,clear}`；正文只含密文和最少状态。每账号默认 300 MB，全站默认 6 GB（可用盘约 12 GB，留数据库、日志和临时空间）；环境配置可收紧。开始时预留整包额度，保证并发上传不能超额；删除／过期事务同步释放。最多 512 块、每块 1 MiB + 认证开销，最多 3 份完整包及 1 份待传；沿已有数据库限速每账号每分钟 120 次，块上传／下载 600 次。明确返回账号／全站空间不足及当前占用，界面给出删除旧备份或改用本机备份的建议。

遗忘／权限清理推进已有代次时删除该账号全部旧云包和未完成上传，保留包裹钥匙并递增备份清理代次；旧待传清单被拒绝，本机下次备份丢弃旧密文并捕获当前数据。删除一份删除对应块与额度；「删除云端备份」删除全部清单、块、包裹钥匙、记账，本机停用并删除本机备份钥匙及待传密文，回执核对各表计数和剩余额度均为 0。账号注销按同一真删除合同处理；SQLite `secure_delete=ON` 与 WAL（预写日志）检查点清理应用可访问残留，服务备份／系统磁盘和攻击者已有副本不声称物理擦除。维护任务清理 7 天未完成包及多余历史包。云日志仅请求状态、大小、数量、耗时，无恢复码、包裹内容、密文正文或文件名。

## 恢复、兼容与威胁边界

只有现有云签名控制回执明确 `capabilities.cloudBackup:1` 才请求新接口；`healthz` 同时声明能力。结构 9／缺字段下设置显示「暂不可用」，新接口请求为 0，不按 404（未找到）探测。能力仅进程内保存，登录／已有状态刷新重新读取。桌面新增 `/personal/v1/backups/cloud` 状态及 `/backups/cloud/{prepare,enable,run,reveal,rotate,restore,delete,remove,dismiss}` 操作，远程客户端没有密钥／恢复操作入口。

登录后在应用内给可关闭的提示，列出最新备份日期和大小，不阻挡聊天；之后设置可恢复。输入恢复码后下载到临时位置，先解密和校验，失败不替换数据。恢复只替换匹配云账号，保留目标电脑其他账号和原处文件。替换前明确范围并沿 BK-1 自动本机安全备份；成功重启后核对对话、记忆和设置。凭据先暂存为本机保管库密文，与恢复事务一起提交／回滚；安装身份保持新电脑自己的，必须重新登录云账号。错误分别提示输错组、码不匹配、包损坏／缺失、网络中断可重试、需升级。

服务器／数据库被拿走：攻击者知道账号、时间、大小、份数，不能读取内容。账号密码泄露：攻击者能下载或删除密文，不能解密；应立即改密码、退出其他设备。恢复码泄露：结合可取得的对应包裹记录与备份可以读取全部内容（含保存密钥），应换码、删除旧云备份并更换泄露凭据；换码不能收回已复制的旧包。已解锁电脑或恶意同源脚本可取得页面正在显示的恢复码；系统凭据库保护静态存储，不承诺抵抗系统管理员或已控制的电脑。手机／Apple（苹果端）后续可只读电脑备份状态，并经已认证的设备信封交付主钥匙，不能增加服务器托管或用设备批准阻塞登录。
