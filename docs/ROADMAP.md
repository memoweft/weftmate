# WeftMate 路线

## 已完成：项目修复阶段

本阶段不是新增产品功能，而是恢复一个干净、可解释、由产品所有者控制的起点。

完成条件：

- 愿景内代码保留并按仓库形成清晰的本地提交；
- 偏离愿景的旧真机、Companion、固定页面执行器、单次验证限制和历史治理材料退出活动树，并保存在可恢复归档；
- 当前文档只描述现在，不再携带线程流水和逐次事故指令；
- WeftMate 不展示依赖用户手工启动 AI-GAME `4310` 端口的功能入口；
- 两个仓库的相关自动化门通过，最终工作区干净；
- 本阶段结束后停止，等待产品所有者决定下一阶段。

## 修复后的产品基线

- WeftMate：固定 DSH 官方客户端的 Windows 产品外壳；普通对话、模型、工具、审批和工作区继续可独立使用。
- AI-GAME：面向 WeftMate/DSH 的 Android 模拟器任务后端；保留 V2 权威任务、稳定 owner pair、模拟器 Profile、常驻调度、通用 `android_ui_agent/1`、证据与恢复基础。
- 当前不发布：WeftMate 的 Android 模拟器设置页、全局任务中心，以及任何要求用户先手工维护 4310 服务的入口。
- 当前不是 AI-GAME dogfood 候选，也没有阶段整体 `PASS` 声明。

## 当前决定：首个完整候选的验收标准

产品所有者已经指定首个代表性 black-box acceptance（黑盒验收）：只说“帮我在 Soul 上匹配，然后找到合适我的女朋友”，系统随后自适应追问、形成可修改任务单，并作为自主智能体在模拟器中自己观察、思考、筛选、聊天、操作、等待和恢复；任务过程持续形成经过验证的经验，第二次相似任务必须实际复用经验并可复核地更快或少走弯路。

Soul 只是第三方 Android 测试环境，不是新的专用产品或硬编码路线。完整标准以 `D:\AIProjects\AIGame\Repository\docs\product\ACCEPTANCE.md` 为准。标准已经冻结不代表实现、真实账号结果或产品所有者 `PASS` 已经存在，也不自动启动无边界施工。

## 待实施：宿主生命周期与首个完整候选

只有产品所有者明确开始后才进入。

目标是让一项模拟器任务真正成为 WeftMate 内部能力，而不是开发者拼接的两个程序：

1. WeftMate 管理 AI-GAME 的安装/定位、启动、健康、停止、退出收口和错误恢复；端口是内部实现，不是用户前置步骤。
2. 后端就绪后才发布模拟器 Profile 和任务入口；后端不可用时给出产品级恢复动作，不让用户操作隐藏服务。
3. 从一句自然语言目标完成自适应澄清和任务单确认，不把模型、Profile、runner 或端口选择交给普通用户。
4. 通过 DSH 官方工具路径提交长期 Task，让通用 agent 自主处理真实页面、候选人与未预录聊天回复，并验证观察、动作、等待、恢复与结果回到原对话。
5. 完成至少一次经验写入、证据升级、下一次兼容任务检索和实际复用，给出可比较的改善指标。
6. 完成一次有限的内部预验，形成固定 candidate（候选），明确能证明和不能证明的范围。
7. 把候选交给产品所有者 dogfood，然后停止。

这里没有“最多 2 步”或固定迭代次数。可控性来自暂停、停止、退避、等待、无进展检测、幂等和证据门，而不是削弱任务目标。

## 后续方向

- 长期任务的修改、插队、接管和事件/时间唤醒；
- 可靠的跨任务执行经验复用；
- AI-GAME 随 WeftMate 安装和升级；
- MemoWeft 在稳定接口存在后接入；
- 已签名 Windows 发布与受控更新。

每个方向都必须单独形成候选并由产品所有者决定是否足够，不自动串成无限施工链。
