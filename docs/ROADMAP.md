# WeftMate 大阶段路线图

> 本文件只定义大阶段、模块范围和退出标准，不记录逐提交进度。
> 当前正在做哪一阶段，以 [`../CURRENT.md`](../CURRENT.md) 为唯一事实源。产品边界看 [`PRODUCT.md`](./PRODUCT.md)。

## 状态口径

- `complete`：阶段退出条件全部验证通过。
- `in_progress`：当前正在推进。
- `partial`：已有底层能力，但产品路径或验收尚未完成。
- `planned`：已纳入路线，尚未开始。
- `deferred`：明确延期，不属于当前阶段。
- `blocked`：存在清楚的外部或技术阻塞。

不再使用“完成 90%”一类没有稳定分母的数字。

## 阶段 1：核心 Alpha 闭环

### 目标

证明 WeftMate 不是普通聊天壳，而是一个有长期记忆、能感知桌面并能协作干活的个人 AI 桌面产品原型。

### 包含模块

- Electron 常驻、托盘、单实例、自绘窗口和本地 loopback 服务。
- 云端/本地模型配置与切换，密钥使用 `safeStorage`。
- MemoWeft 记忆、画像、图谱、记忆气泡、来源、失效、删除与记忆包导入导出。
- 三个内置人格及共享记忆的切换。
- 桌面活动窗口感知，observed 默认不上云。
- 统一对话与协作型 Agent：工作区、文件、命令、附件、图片、MCP、审批、停止和文件撤回。
- 基础会话列表、切换、软归档、工作区绑定和图片历史。
- 中英文应用界面基础、本地 typecheck 和核心契约测试。

### 退出标准

- 在开发机上能稳定完成“聊天 → 召回 → 回答/执行 → 结果回写 → 画像更新”的闭环。
- 用户能查看和控制核心记忆、切换内置人格、开启桌面感知并授权 Agent 在工作区执行任务。
- 本地 typecheck 与核心测试通过。

### 边界

本阶段完成只代表技术 Alpha 闭环成立，不代表干净克隆、CI、安装包、签名或陌生用户产品路径已经可用。

## 阶段 2：可交付产品 v1

### 目标

让一个不了解 MemoWeft、也不懂开发环境的用户可以独立安装，并在首次使用中理解和体验“这个 AI 会逐渐了解我”。

### 模块 A：工程可交付底座

- 使用公开、精确版本的 MemoWeft 依赖，移除 sibling `file:` 依赖。
- 干净克隆能够独立安装、typecheck、测试和启动。
- 激活真实 CI，建立有效公开仓库、Issue 和下载入口。
- 完成安装包、空用户数据首启、升级前备份、卸载和安装冒烟。
- 修复发布前安全与可靠性问题：loopback 鉴权/Origin、感知开关绕过、MCP 名称与信任碰撞、Agent 任务清理、配置原子写入和默认权限。
- 清理旧聊天路径、旧首启向导等双路径，再继续扩展新产品流程。

### 模块 B：首次认识与记忆控制

- 可跳过、可中断后继续的聊天式初次认识。
- 职业、兴趣、目标、习惯和交流偏好；MBTI 类问题只能作为参考证据。
- 采访结论以低把握度初始假设进入 MemoWeft，后续由真实使用验证。
- 产品层区分用户“修改画像”和“指正推断”。
- 区分“只清记忆”和“删除全部本地数据”。
- 默认界面保持简单，图谱、来源和原文存档按需深入。

### 模块 C：人格包与桌面角色切换

- 定义有版本号的 Persona Manifest 与本地 Persona Store。
- 内置人格和用户人格统一读取，但保留来源和只读边界。
- 人格创建、复制、编辑、删除、导入和导出。
- 聊天入口与桌面助手入口快速切换，当前选择可持久化。
- 人格可以配置提示词、风格、形象/声音元数据、陪伴主动度、模型建议、工具/技能和知识引用。
- 用户可禁止某个人格读取 MemoWeft；这一权限与“是否把新对话写入记忆”分开。
- 人格导出包不含用户记忆、聊天、密钥、路径或权限凭据。

### 模块 D：v1 产品收口

- 中英文核心流程逐屏真机验证。
- 首次模型配置、采访、聊天、记忆纠错、人格导入切换和 Agent 授权形成连续路径。
- 错误、离线、无 keyring、模型不支持视觉等状态有普通用户可理解的反馈。
- 完成首个可下载版本和最小发布说明。

### 退出标准

- 陌生用户能从安装包独立安装、配置模型并开始聊天。
- 用户可以选择是否参加初次认识，并能修改或指正初始理解。
- 用户能创建或导入一个人格，在聊天和桌面入口切换；跨用户导入不携带任何原用户私人数据。
- Agent 保持协作型，高风险操作与扩权都来自明确授权。
- observed 仍默认不上云，API key 不明文落盘。
- CI、干净安装、核心测试和安装冒烟通过。

## 阶段 3：可靠桌面伴侣与协作工作流

### 目标

从“能聊天、能调用工具”发展为可以每天依赖的桌面伙伴和单 Agent 工作台。

### 包含模块

- 桌面形象、状态、声音和全局快捷呼出。
- 桌面入口直接切换人格。
- 陪伴主动度：安静、轻提醒、陪伴交流；主动打断只报 P0/P1。
- 执行自主度与陪伴主动度保持独立。
- Agent 任务持久化、重启恢复、历史任务、可读 diff、操作审计、危险命令提示和任务级授权范围。
- 可保存和复用的基础单 Agent 工作流模板，不引入多 Agent。
- 历史搜索、会话重命名、归档恢复和单会话导出。
- MCP 可靠性、权限摘要与可管理性增强。
- 记忆纠错、时间变化、变淡提示、周报或时间线等更自然的产品呈现。

### 退出标准

- 长任务在应用重启后能够恢复，或清楚标记为中断并给出后续操作。
- 用户能看懂 Agent 做了什么、改了什么、在什么范围内得到授权。
- 主动度设置真实影响提醒频率；主动提醒不会自动执行高风险动作。
- 会话和任务都可以搜索、恢复和导出。
- 产品仍是单 Agent + 工作流，不以多 Agent 数量制造复杂度。

## 阶段 4：官方云同步与多终端

### 目标

让 PC、Android、iOS、watchOS 成为同一个用户记忆核心的不同终端。

### 开工前必须重新设计

- 官方云保存哪些资产：记忆、对话、人格、设置或其他 AI 资产。
- 加密、权限、冲突合并、离线缓存、删除和迁移模型。
- 官方云与本地/自带模型的边界。

这些问题尚未拍板，当前路线只保留阶段，不提前写死实现。

### 包含模块

- WeftMate 账号与官方云同步。
- PC 负责复杂聊天、文件与工作任务。
- Android/iOS 负责移动聊天、语音、图片与快速记录。
- watchOS/穿戴在授权后提供健康与活动状态。
- 设备级同步开关、来源授权、人格访问和记忆共享控制。
- 标准数据导出和离开官方服务的迁移能力。

### 退出标准

- 同一用户授权后，至少 PC 与一个移动终端能读取同一份 MemoWeft 状态。
- 任一终端或来源关闭共享后，不再上传或读取对应数据。
- 人格同步与用户记忆同步可以独立控制。
- 穿戴数据只有在明确授权后进入记忆系统。

## 阶段 5：开放生态与代理能力演进

### 目标

在产品可靠后开放可分享资产，并把协作型 Agent 逐步发展为受控的长期代理。

### 包含模块

- 人格包公开分享、版本兼容和人格市场。
- 第三方工具、知识包和工作流生态。
- 长期任务的暂停、恢复、撤销授权和审计。
- WeftMate 消费 MemoWeft 标准数据并与第三方兼容。

### 退出标准

- 公开人格包、工具和工作流都带 schema 版本、权限摘要和隐私检查。
- 跨用户安装的人格包不包含私人数据。
- 长期代理只能在用户一次明确授权的范围内运行，不因使用时间自动扩权。
- WeftMate 不在本仓库重新实现 MemoWeft。

## 明确延期或不属于本仓库

- 多 Agent 协同：当前不做。
- Android、iOS、watchOS 和官方云同步：阶段 4 之前不做。
- 邮件、日历、企业权限、企业 SaaS：当前路线不做。
- 自研基础模型：当前路线不做。
- 数字分身、人格复制、数字生命：产品边界外。
- MemoWeft 内核、协议和社区治理：属于 MemoWeft 仓库。
