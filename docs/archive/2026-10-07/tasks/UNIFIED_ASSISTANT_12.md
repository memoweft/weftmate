# UNIFIED_ASSISTANT_12：手机开始，电脑在原对话续聊，成果回到手机

日期：2026-10-03。状态：候选已发布、待云验证。用户讨论电脑/手机同步后明确“好，那继续吧”，本轮收口产品第3阶段的日用跨端流程；11候选的本地模型收尾未通过和本人待验状态保留。

## 用户结果与范围

手机先完成一段普通对话，联网后电脑打开原对话，优先沿用手机实际使用的模型继续真实生成；电脑实际带入此前手机文字历史，生成一份文件，回复/任务/成果回到手机原对话。两端侧栏只显示一条产品对话，换页、断线重开、丢回执后按原编号核对，避免重复生成。手机关闭应用后离线仍能看已缓存的电脑回复，已保存文件仍可打开。

电脑采用此前已同步记录，当前设备的手机交接先等本机回合结束、事件/图片上传回执齐备；手机在采用后到达的新记录保留为待并入段，能查看来源，不静默覆盖电脑上下文。手机独立对话与模型继续保留；完整离线分支自动合并、同会话任意换模另收口。用户已明确默认模型策略为“优先沿用手机原来的模型，再考虑同步该模型配置”。本轮补实际使用模型的非秘密身份记录，只有确切、唯一匹配现有电脑配置才预选；旧记录无法识别、缺配置或有多个匹配时，让用户明确选择或配置，不能静默改用列表第一项。私有模型配置同步作为后续收口，不自动复制手机密钥或把开发测试凭据登记给正式账户。

## 已核缺口与方案

- 当前手机本机对话与电脑DSH（对话运行时）会话没有持久映射；电脑追加手机对话文字只写同步日志，不运行模型。手机选“电脑模型”时现有推理循环仍在手机，不能把它记为电脑执行。
- 保留原手机对话身份，在账户账本建立一对一电脑会话绑定，冻结模型与采用时的已受理同步序号。旧消息/图片留在原同步记录，后续真实电脑回合留在DSH；双端在原对话中接上两段，不建立第二个同名对话，也不逐条重发旧消息。
- 用固定版本的`agent/pre-step`（模型步骤前扩展点）和单用途IPC（进程间通信）向首个电脑回合提供有界、带校验值的历史上下文。历史是资料；真实用户消息/回执/正文哈希保持原义。上下文在发送前准备并核验，父进程按确切回执与当前会话/账户核对，不在阻塞扩展点反查DSH造成自等待。失败时保留原命令和原目标，核对实际原生状态，不无上下文生成或自动重复派发。
- 采用与同步写入沿现有串行队列线性化，固定请求编号查原创建回执；后续沿共享消息/任务出站账本排队。只按身份与序号去重，不按文字相等去重。绑定信息公开产品对话与任务关系，内部会话身份不成为第二张会话卡。
- 联网手机本机生成先同步本轮用户消息和图片，再取得该对话的短期生成预约；预约与电脑采用在同一顺序中仲裁，运行中续约、真实终态后释放，超期为待核状态。采用与本机发送共用原生原子门。若电脑采用先发生，当前明确发送的手机消息可用`sourceSyncEventId`准确关联到原共享命令，两个显示段只按该身份关联，不把同步补传当新的生成触发器；离线独立结果保留为迟到段。
- 安卓增加绑定/采用意图及电脑历史的持久缓存，原生发送入口核交接状态，切号与迟到回调核当前账户；旧手机记录、图片和草稿保留。因此预计原生0.6.0/versionCode11与匹配服务器UI（界面），延续既定签名和服务器更新机制。
- 账户store V3可增加经验证的可选绑定；同步V1原事件不迁改。旧程序不理解新交接状态，恢复使用配套采用前副本。原生SQLite（本地数据库）只做新增表/字段迁移，保留原内容。固定DSH rc.5和日用模型不升级、不切换；官方`session.selectModel`会保存全局默认，本轮不把它开放为已验证的任意换模。
