# 安卓逐页原生化

电脑配对使用 v2 六位核对码：设备页扫描二维码或粘贴 `wm1.` 配对码，手机核对同一云账号、目标电脑、公钥和期限，先承诺再公开，独立计算六位数字；两边一致后由人在电脑上确认，手机才兑换会话。每次请求经原生专用认证传输，取新的 nonce（一次性随机数）并签 DPoP（设备密钥持有证明）；`host.business` 不开放配对认证路由。二维码中的电脑 HTTP 环回来源仅作核对材料，真实手机请求走已校验的 HTTPS 连接；合成环回测试使用 HTTP。取消或过期后显示说明和「重新扫码」。临时证书固定在失败后撤回，成功才保存电脑信任。首次升壳切回内置新页，缓存文件和账户资料保留。需要新壳版本；本包不递增版本号，由合并时统一更新。协议见 [PAIRING.md](../src/personal-cloud/PAIRING.md)，固定向量由 Kotlin 和共享界面代码共同验证。

iPhone 沿同一手机同步合同：`phoneFirst:true` 取加密副本，核对云账号、宿主与 `control.generation`，`memoryAuthority.ready` 决定何时上传原话，与 `model:null` 或空记忆副本分别处理。原话和交接编号在手机加密冻结，每次最多 50 轮、完整请求不超过 256 KiB；丢回执或部分确认重发同一正文，全部收到后推进下一批，最后一批才标记 `handover.complete`。100 轮或 256 KiB 仍可选择「现在交／稍后」。超过单条 16,384 UTF-16 单元或单轮放不进请求时，把冻结整轮 JSON 的 UTF-8 字节及 SHA-256 摘要加密保存，每片最多 96,000 原始字节，经 Base64 编码走同一个 `/offline/turns` 的 `turnFragments`；实发完整 JSON 仍核对 256 KiB。只有同代次、同编号、同索引的 `fragmentReceipts state:received` 推进分片，整轮 `receipts state:synced` 才确认原话；手机重启继续未确认的原请求。末片回执丢失先重试末片，只收到分片回执时再从首片重放；电脑可能用已存的末片提前重组，只有此前已提交过末片才接受这种整轮确认。分片进度随副本清理、换号或代次变化一起删除。手机保留完整原话与原附件，上交仍只带正文和附件占位。`synced` 只表示电脑收到，整理继续由电脑自动进行。已配对手机重启后即使没有电脑会话，也可用上次成功绑定的身份核对云授权再恢复副本；聊天使用手机已配置模型。

全新安装按 D93 直接进入手机聊天。原生初始化创建持久的本机归属，复用手机模型库和加密对话容器；它没有云凭据，不能调用电脑、同步、云设备管理等接口。账户与设备页提供可关闭的云登录入口。登录后使用真实云账号的独立资料，本机资料不自动迁入或归给新账号；退出云账号后恢复原本机空间。已有电脑或云账号身份的启动恢复逻辑继续使用原身份。需要新壳版本。

初始化同时报告是否只有手机本机资料，动态、目标、健康和成果库据此沿用缺电脑或缺健康来源的说明，不发送电脑请求。手机界面包仍由已认证的电脑分发，尚无独立公共来源；没有电脑时更新页说明此限制，并保留官网安卓安装包链接。本机检查只返回来源不可用、未执行检查，不把它当成登录失败、网络故障或已经最新；已有签名包的缓存、校验和回退保持原机制。

外观以 0.8.31 安卓壳内的手机网页为基准。浅色取实际内置页 `surfaces.mobile.themes`：墨色 `#252722`、强调 `#30332d`、软底 `#f5f4f1`，保留当前手机网页值。深色按 2026-10-13 控件规范改为中性灰：页面 `#1c1c1e`、卡片 `#2a2a2c`、正文 `#f2f2f4`、次字 `#c4c4c9`、主按钮 `#e6e6e8` / 字 `#1c1c1e`，输入底 `rgba(120,120,128,.26)`、浮层 `rgba(44,44,46,.74)`；透明度以最接近的 8 位 ARGB（带透明度色值）生成。所有原生色彩取 `android.colors / android.darkColors`，包括旧兼容登录页与系统栏。输入胶囊 26、展开卡片 24、气泡 26、审批／提问 16、触控区 44、工具图标 22 / 线宽 1.75、工具间距 4，正文与输入默认 15、正文行高 1.65；字号与代码字号直接读取现有网页外观偏好（不另存一份），控件标签 15；保留系统字体缩放。切页短淡入，输入高度变化取令牌时长。

Android 12 以上使用系统 RenderEffect（图层模糊）处理固定输入区、导航、浮动圆形按钮、菜单及侧栏的背景；只在 GPU（图形处理器）上复用消息列表的显示指令，不读取截图或模糊文字／按钮，不给随消息滚动的卡片开模糊。滚动过程中固定面板也退为同色实底，停止后恢复磨砂，避免持续重绘模糊纹理。旧系统使用透明色叠在 canvas（页面底）上的实色：输入 `#343437`，浮层 `#28282a`。列表伸到固定面板下方，但可读区域的上下留白随顶栏与输入／导航实际高度变化，待办提示和回到底部也避开这些区域。实现沿用现有 Compose 1.7.6，没有增加依赖，帧统计见本轮证据。

停放的网页保持连接状态引擎、停止绘制；进入网页页面时恢复可见。侧栏在同一个活动窗口中覆盖安全区，返回先收起侧栏，读屏不会穿到后面的聊天页。背景采样先铺页面底色，再模糊内容并叠规范透明色，防止下方清晰文字透出。测试包可用 `-PweftmateQaProfile=true` 关闭运行时调试，仅允许 `com.memoweft.weftmate.mobile.and4qa` 与 `com.memoweft.weftmate.mobile.and12qa`；原调试桥只服务隔离夹具，常规构建与发布检查保持原配置。该临时测量变体不跑发布专用 lint（静态检查），不新增离线依赖。它与普通调试样本分别记录，不称作正式性能基准；正式性能需接近发布配置并控制编译状态，见[安卓官方测量说明](https://developer.android.com/topic/performance/benchmarking/macrobenchmark-overview)。

验收使用 `tests/integration/mob-4-phone.mjs --native-entry`；实际 MiMo（云端模型）配置与流式单独计数，后续 `--fixture-model --comparisons` 使用可停止的合成流式。浅色在同一个隔离安装、同一个账号和同一份会话中切换 `HybridActivity / NativeActivity`，记录空状态、内容、模型菜单原图；深色核对指定灰色令牌及预览，不与旧绿色网页比较。逻辑宽度只调整测试包配置，网页使用同一配置的初始缩放，截图没有浏览器视口缩放替代整屏。其它四页与设置继续嵌入，侧栏的「完整对话列表」保留搜索、项目与归档入口。

AND-4 使用 Jetpack Compose（安卓声明式界面）1.7.6、Material 3（原生组件底座）1.3.1 与 Activity Compose（界面生命周期）1.9.3。Kotlin（安卓语言）及 Compose Compiler（界面编译器）插件固定为 2.0.21；Gradle（构建工具）8.9、JDK（Java 开发环境）17、SDK（安卓开发工具）35 保持现有版本。布局、触控区、字号、圆角和颜色取生成的 `DesignTokens.kt`，图标取 `design/icons/` 的安卓产物，组件不使用系统默认蓝色。选型按[官方 Kotlin 2 配置](https://developer.android.com/jetpack/androidx/releases/compose-kotlin)接入，未引入第三方 Markdown（标记文本）或图片库。

新增直接依赖及界面测试依赖 `ui-test-junit4 / ui-test-manifest:1.7.6` 只通过现有 `google()`（Google Maven）与 `mavenCentral()`（Maven Central）解析，版本全部固定。首次联网执行 `gradle :app:assembleDebug :app:assembleDebugAndroidTest`，文件进入 `D:/AIProjects/AIGame/Repository/runtime/toolchains/gradle-user-home`，随后用同一进程激活脚本执行 `gradle --offline`。不复制或改写共享 DSH（助手运行时）vendor（依赖缓存）。云端沿原安卓构建步骤在线解析相同版本。调试包大小与启动／滚动实测见 `tests/evidence/and-4/README.md`；Compose 增加界面运行库，预计调试包增加约 6–10 MB（兆字节），发布压缩尚未启用，不用估计冒充测量。

`NativeActivity` 为默认入口，`NativeChatModel` 管展示状态与前台轮询，`NativeTimeline` 合并正式事件及累计正文快照；界面只发动作，不保存另一份业务数据库。`HybridActivity` 保留原网络调度与账号代次检查，原生和网页调用同一层 `PersonalApi / SharedChat / ModelClient / SseMessageCollector`。认证、TLS pin（证书公钥固定）、网络路由白名单、未确认发送账本与附件受理仍在原层；审批重试保留同一请求体／编号，登记与最终消费分开。`AttachmentStore / LocalStore / SecureSettings / OfflineVault` 与通知继续复用，未新增业务接口或权限。草稿按账号与对话保存，退出／切号清空展示；生成时前台按 250 ms（毫秒）读取现有事件／变更接口，暂态水位不替代历史游标。

MOB-4 的手机独立模式复用 `WeftPhone / WeftOffline` 的现有账号检查、流式／停止／重生成和首次电脑同步引擎，由窄展示适配器交给 Compose；正文仍由原生 `phone.complete` 网络层请求，模型保存在 `SecureSettings`，会话与原生草稿保存在同一个 `OfflineVault` 加密容器，不另做数据库。未迁完页面所用的 WebView（系统网页容器）暂时也运行该状态引擎；最后删除网页依赖前须迁移该引擎，保持现有容器与同步协议。首次电脑出现沿 MOB-4 上传原消息供记忆摄取，原生侧栏保留手机原对话只读查看；自动映射到电脑普通会话的回执仍缺，不能宣称无缝会话接力。网页继续服务手机浏览器远程访问，也承载未迁完页面。原生聊天默认启用，设置里不再提供界面切换开关；构建参数 `-PweftmateNativeUi=false` 设旧入口为默认。旧入口要等四页、设置、复杂消息操作、手机独立模式全部迁完且浅深／窄屏／真机回归通过后，单独一包删除。需要新壳版本，版本号留给合并时统一更新。

配对模式在电脑不可达时也读取当前账户的加密记忆副本，显示上次同步时间；电脑恢复连接后回到电脑记忆页。原生手机对话在路由层确认可以由手机回答、但电脑不可达时，使用手机当前账户配置的模型直接请求；失败状态从本机记录恢复，在对话里显示说明并提供重试，保留正在编辑的下一条草稿。
