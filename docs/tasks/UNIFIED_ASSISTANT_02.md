# UNIFIED_ASSISTANT_02：可信多设备接入

日期：2026-09-26。状态：本机候选开发验证通过，公网发布被系统防护拦截。用户已明确继续第二阶段；总体目标和阶段顺序见 `PROJECT_DIRECTION.md`，当前进度见 `CURRENT_STATE.md`。

## 用户可得到什么

个人宿主提供给手机等设备使用的受控接入基础：设备可以被登记和撤权，合法设备能接续属于同一用户的会话，重试请求不会无意重复派发，断线后能按历史游标继续读取。

本轮实现接口与真实宿主接线。安卓完整客户端、手机独立执行与同步仍在下一阶段；双客户端验证不代替真实手机产品验收。

## 核心决策

1. 在现有 Electron（桌面应用框架）宿主内增加窄 API（应用程序接口），共用同一数据目录、单实例锁、凭据桥和退出流程。服务只监听显式配置的回环端口，固定端口冲突要明确失败。
2. 设备登记和撤权经本机管理通道完成。设备令牌只交付一次，服务端只保存哈希；网络接口每次认证并核对设备权限、同一用户的会话绑定与执行目标。旧会话须本机显式接管。
3. 请求以稳定标识和内容摘要去重，先持久保存再确认受理。相同标识而内容不同返回冲突。模型、执行设备与能力缺失时如实报告，不能默认改派。
4. DSH 新会话可预分配固定标识；创建前检查模型和凭据。普通消息不具备原生客户端去重键；进入派发后若回执丢失，记录 `uncertain`（结果待确认），不盲目重发。受理、交给 DSH、观察到持久结果分别表示。
5. 聊天历史仍以 DSH 为来源。接入层只保存设备身份、会话绑定和必要的待投递/对账请求记录；事件分页使用正式持久序号，不使用旧网关的内存序号。
6. 已有 AI-GAME 的幂等任务契约只能用于实际配置且能力匹配的执行器。本轮不将手机、Codex 或浏览器等未接入执行器标成可用。
