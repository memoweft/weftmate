## 冻结方案

1. 网页捕获最多256KiB UTF-8（文本编码），保存为同账户/任务/回合/确切回执的不可变捕获版本；超过上限明确本次捕获未覆盖全文，不将捕获SHA-256（内容校验值）叫整页哈希。独立于实际已读段，未读捕获不能被引用成已阅读。浏览窗口读完仍按既有生命周期清理，不为后续读取保留活窗口。
2. 初次open/follow交给模型标题、有限目录、版本/覆盖信息与至多8KiB首段；单段最大8KiB，最多32段。新增`personal_browser_read_segment({snapshotId,segmentIndex})`从同一冻结捕获按需读，返回本段独立来源ID/字节范围/段哈希；不每读一段重新渲染并混用动态版本。打开/跟随仍仅用户原目标网址或已观察链接，不扩大浏览范围。来源落持久账本后才可引用，保存工具核同回合确切已持久工具结果；旧32KiB来源格式兼容，新捕获版本和段身份新增不回写旧记录。
3. 模型看过的段才进入引用/覆盖集合，两端按同一捕获分组，显示读过的段和未覆盖全文。Native12现ID式来源桥可复用，预计仅服务器页面更新；必要新增原生动作必须说明，不为本轮默认重包。
4. 个人保存工具成功且回读证明齐备后，对下一模型步骤给简洁确认成果的提示，同时继续用户明确的剩余要求；不按“文件存在”强制结束，不用小token（词元）截断/假终态。请求、首响应/首输出、最后输出/结束仅记录元数据与时间，范围限定个人受管会话/既有模型目的地，避免记录正文和密钥，不改D:\AI日用采样/模型缓存/全局默认。
5. 与目标确切回执关联的只读回复证据区分等待、实时生成、正常结束、中断、失败和未知；只有真实原生终态可写结束。仅持久start、无当前活跃回合证明的重启状态为未知；文件验证独立一行。停止/补充/恢复继续原task身份，新回合必须重新读取其来源并重新证明，旧段历史仍可见但不冒充本回合新读。
