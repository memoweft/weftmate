# Mac 原生检查更新与官网下载接线

当前任务：2026-10-05，用户在官网下载与二维码交付后明确“继续下一阶段吧”。本轮让 Mac 自己识别适用更新，并进入真实官网下载；Apple 共享会话发送、停止与恢复仅核前置，不在本轮展开。

## 用户结果

- Mac 登录前能从标准应用菜单或独立更新窗口检查官网；登录后设置页复用同一入口。个人电脑宿主离线时仍能检查官网。
- 显示当前 App 真实版本/构建、官网适用版本和检查结果。只匹配 macOS 与真实运行架构，版本/构建按数字比较，不用浏览器信息猜 CPU（处理器）或把不兼容包当最新版。
- 有新版时进入对应官网 DMG（安装磁盘映像）下载，用户手动安装/覆盖。其他设备只通过官网入口或二维码进入各平台页面。
- 检查中、已最新、本机较新、没有适用架构和失败分别表达；失败不假报成功，重复点击和迟到回包可控。

## 归属与范围

- Mac侧 Codex 拥有 `apps/apple/` 和本任务卡实施记录，按实际模型安排子 Agent（子智能体）编写/测试；保持既有 Weave 原生样式。
- Windows主助手负责拆解、独立审查、源码整合、官网下载发布和全局状态。共同正式依据只回 `ARCHITECTURE` / `site/downloads/README.md` 与发布器，不另复制一套协议。
- 专职GPT-6 Luna继续只读跟进Mac；Windows只读前置复用原QA请求，无注册/生成/模型维护。首位GPT-6 Sol因容量失败未执行，已由实际Luna接手并核实。

当前Windows主仓为 `408c2a1`；Mac独立Apple历史最新文档回执 `8e45e1928f69b427b329cdaa8869d4da34e0c1cf`，实际工程仍build4。官网当前公开Mac0.1.0/build4/Intel包；Android0.7.0/12、Windows网页及iPhone/Watch未分发状态保持。

## 验证与发布

1. Core（共享核心）测试覆盖数字版本/构建比较、等值/本机较新、无适用架构、无效清单/链接、网络失败和重复请求；保持旧账户/会话21项。
2. 正常URLSession（原生网络会话）真实检查官网一次；确有不同原因才进行最多一次针对性重验。网络/证书与原私有账户独立，不启临时开发隧道。
3. Mac桌面与较窄窗口同批检查更新控件、状态和真实Bundle（应用包）信息；必要一批修正、最多一次确认。旧钥匙串许可阻塞独立保留，更新验证使用新测试命名空间及未登录入口，不读取或清除旧测试凭据。
4. 可保留一份带新功能、真实构建号4的开发测试App；最终Release（发布构建）候选升0.1.0/build5。Windows核同一DMG的来源/版本/字节数/SHA-256（文件哈希）后发布官网build5，保留当前build4安装文件；再观察真实开发4显示有新版与下载、最终5显示已最新。不能用假当前版本代替真实观察，也不把开发4冒充原发布4。
5. iPhone/Watch不扩构建，共享构建号变更与最后实际构建分开记录；不把未公证包、旧签名登录保留或官网成功当真机安装通过。

## 已核前置与停止点

私有QA4 MiMo原请求一次查询仍 `pending/RUNTIME_BUSY`、`configured=false`；这只表示该私有配置未生效，不能推断宿主默认不存在。正式 `weftmate-settings.json` 中 `models.activeId` 仍 `personal-local-occamy-miniplus-v21`，profile（模型配置档案）存在。本轮不维护本地推理、不清旧队列或重发注册，续聊真实模型前置仍待收口。

停止点：形成实际可试用Mac更新候选、官网新包和明确证据后交付，待用户体验；原生跨签名覆盖资料保留、Apple续聊与真机均保持未验边界。出现具体系统许可或签名条件缺失时保留产物和精确步骤，不按经过时间当批准。
