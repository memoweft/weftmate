# UNIFIED_ASSISTANT_01：个人宿主持续运行

日期：2026-09-26。状态：第一段开发验证通过，跨设备整体未交付。产品目标来自 `PROJECT_DIRECTION.md` 页首；本卡负责第一段宿主实现和验收。

## 用户可得到什么

WeftMate 新增无窗口模式，为后续手机和其他设备接入提供持续运行的宿主。它沿用原有运行时所有权和安全凭据桥；实际验证使用隔离资料，未启用真实记忆或设备执行。

这是跨设备统一 AI Agent（人工智能助手）的第一块基础。完整目标包括手机独立运行、同步、统一设备能力和主动跟进；本卡交付不代表这些后续能力已经完成。

## 现有事实与本轮选择

- 开工前，`scripts/run-dogfood-backend.mjs` 最终仍启动 Electron（桌面应用框架），`src/main.mjs` 的运行时启动和窗口加载存在直接依赖。本轮新增 `scripts/run-personal-host.mjs` 入口。
- `DshWebRuntime` 已管理固定 DSH、动态回环地址及安全凭据桥，优先复用。
- 桌面操作依赖登录桌面的窗口与输入能力；本轮采用同一登录用户会话中的无窗口模式。
- 既有单实例锁必须继续约束同一数据目录，防止桌面版和无窗口版同时启动两套基础服务。
- 第一段先在隔离数据中验证。公网接入、设备身份、手机独立执行和同步属于后续明确切面。

## 本轮实现范围

1. 明确的无窗口启动模式：继续运行 Electron 主进程、DSH、Mod、MemoWeft 和安全凭据桥，但不创建或导航主窗口。
2. 宿主启动、就绪、失败和退出具有明确反馈；后续调用方能够定位实际回环地址，输出不包含凭据。
3. 保持同目录单实例与有界子进程退出；用户主动退出仍结束本次宿主。
4. 保持现有有窗口运行与关闭到托盘的行为。
5. 提供要求显式隔离数据目录的开发验证入口。

## 下一切面的必要边界

- 当前 `resume` 证明同一空会话历史可恢复，没有证明未知模型归属的会话可以继续发送。内部 Gateway 的 `/messages` 未经过 Electron 主进程的同等模型归属判断；远端入口必须补明确门控和测试。
- 此版 DSH 的空会话创建可能异步保存。实施者观察到返回 201 后立即退出，重启列表为空；等待保存后重启可恢复。本轮未修改此机制，远程任务接入必须区分已受理与已持久。
- `noOpen` 通过安全启动流程的环境字段传入，再由内部 CLI（命令行入口）构造 `--no-open`；操作系统进程命令行没有此参数。证据为实际参数接线复核与无主窗口启动，撤回早期“操作系统命令行含参数”的误述。
- 无窗口宿主仍依赖登录用户会话；模型推理、真实记忆、真实设备动作、公网接入、手机通知、手机独立运行和同步均待后续验证。
