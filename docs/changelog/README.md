# 应用内更新内容

`*.json` 是更新内容的唯一来源，随程序和手机界面包一起打包。每个版本在应用里只出现一条；桌面与手机版本号可以不同，共用这份给使用者看的中文说明。

每个改变用户行为的工作包，由该包的执行 Codex 在开 PR（合并请求）前给当前待发布文件加一句「新增 / 改进 / 修复」。Claude 合并时核对实际已经合入的功能、去重和修正文案；发布时由 Claude 统一确认日期和两个版本号。已经发布的记录保留，下一次发布新建日期文件，版本号不能重复。不要把包编号、提交记录或运行时内部名称写进条目。

维护步骤：

1. 编辑数据文件：`date` 使用有效日期，`versions.desktop / versions.mobile` 使用实际发布版本；`added / improved / fixed` 都是句子数组，没有该类变化时填空数组。
2. 运行 `node scripts/build-release-notes.mjs`，生成 `src/ui-core/release-notes.js`。桌面程序与热更新清单从现有公共资产清单打包它。
3. 运行 `node apps/mobile-ui/src/build-ui-core.mjs`，手机网页与安卓界面包带同一份生成数据，不在手机副本里修改。
4. 运行 `node --test tests/r0-5-help.test.ts tests/mobile-ui-core-assets.test.ts`。校验日期、版本、分类、内部编号、生成文件和版本重复；发布前沿用完整必过单测。

`2026-10-10.json` 的第一批内容来自当天已经合入的消息呈现、建议与补全、搜索、文件夹选择、轻动效、连接恢复、安卓系统栏、手机打磨、记忆恢复与新建对话改进。使用仓库当前真实版本：桌面 `0.1.0`，手机界面 `0.8.25`；本包不自行递增安卓原生或界面默认版本。

更新提示只保存账户、层名称和已见版本，在首次安装建立基线；后续已安装版本变化时显示一次，展示时即记住，关闭或打开说明后重启都不再显示。桌面版本来自既有更新组件，安卓来自原生 `updates.status`，远程网页使用随当前资源一起加载的记录版本。手机壳发布版本不作为桌面程序更新来提示。
