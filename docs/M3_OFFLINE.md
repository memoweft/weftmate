# M3-A · 电脑离线时继续聊天

依据：D13、D20、D23、D25、D39、S6；本文定义各客户端共用的 `/personal/v1` 契约。A14 已接 iPhone（苹果手机）与作为远程客户端的 Mac 原生离线链路。电脑仍是内容权威，MemoWeft 仍是唯一正式记忆系统；手机不得将副本直接写回 World（世界理解）。

## 内容与上限

副本包含当前有效、允许云模型读取与推理的正式 cognition / entity / relationship / event（认知／实体／关系／事件）、来源标识和有界来源摘要。读取现有 Core（记忆核心）查询接口及其来源权限；没有依据、失效、停用、遗忘或任一来源不允许云读取的条目不下发。上限为 500 项，每项正文 2,000 字、来源摘要 240 字，整个副本最多 2 MiB；超出明确报告截断，不声称拥有全库。

近期对话仅选择已使用云模型的会话，最多 10 段，每段最近 20 条可见用户／助手消息，单条最多 4,000 字。工具输出、隐藏推理、系统提示、文件、健康原始样本不复制。离线期间的新对话单独加密保存，不算正式记忆。模型每轮仅收到与问题相关的最多 8 条记忆（总计 6,000 字）及当前对话最近 20 条消息，不发送全部副本，不提供电脑工具。

## 设备加密与模型

选择通过已批准设备的 end-to-end encryption（端到端加密）下发账户云模型配置与密钥，减少在手机重复填密钥的步骤，并落实 D39。使用账户默认模型（若为云模型），否则选账户已配置的首个可用云模型；没有云模型时明确提示在电脑配置，绝不静默调用本地模型。

设备生成独立 RSA-OAEP-256（RSA 最优非对称加密填充，SHA-256）密钥。宿主只在已有受信认证会话里登记公钥，将随机 AES-256-GCM（带认证的对称加密）内容钥匙封装给该设备；账户、宿主、设备、公钥指纹和协议版本作为 authenticated additional data（附加认证数据）。每包使用新内容钥匙与 96 位随机 nonce（随机数），密文包含模型凭据、内容和同步版本。中继转发密文，无私钥、内容钥匙或模型密钥托管。

安卓使用 Android Keystore（系统密钥库）中不可导出的 AES 主密钥包裹设备 RSA 私钥及本地内容，密钥不进入页面；这样兼容旧安卓与部分模拟器不支持 OAEP 的 SHA-256 掩码参数的实际差异；网页使用不可导出的 WebCrypto（浏览器密码接口）密钥并保存在 IndexedDB（浏览器结构化存储）。网页遵守 D24 的同源脚本信任边界；浏览器配置文件被整个复制或系统管理员获取设备的情况不声称硬件隔离。

## 同步、删除与不可复活

已批准手机在线时自动登记并经原内容中继同步；前台周期检查、回到前台及重连都触发同步。请求携带已应用的 revision（版本）和内容哈希清单，宿主只返回新增／变化条目及删除标识；游标失配时返回完整替换。宿主不另存记忆正文，仅保存设备同步元数据。每次发送云模型请求前必须核对云控制面的当前设备授权和清理 generation（代次）；控制面只保存账户／宿主／设备身份和代次。

遗忘、权限撤回、删除对话先推进清理代次，再清除派生副本和离线对话。为避免模型回答、来源摘要或补交片段形成间接副本，M3-A 使用保守的整份副本与离线对话清理，再从电脑重新同步仍允许的内容。客户端删除旧密文与旧本地数据钥匙，清空内存、输入上下文及待补交队列；新副本使用新钥匙。旧代次补交返回冲突，不能形成记忆；去重账本只留随机标识与摘要，不留正文。删除对话不会从手机近期窗口恢复原文。

**可证的边界**：断网设备不能即时收到远程删除。手机每轮必须先连云核对，核对失败暂停读取副本／向模型发送，不使用缓存的授权继续聊天；收到撤权立即清理，宿主上线后先清理再补交。界面不能在尚未送达时称所有设备已删除。文件字节扫描证明应用存储中没有明文残留；闪存磨损均衡、系统备份及恶意导出的密钥不属于应用可保证的物理擦除。安卓关闭系统备份；网页删除 IndexedDB 中旧钥匙和密文，不把敏感数据放 localStorage（网页本地键值存储）、Cache API（缓存接口）或 service worker（后台网页工作线程）缓存。静态网页离线壳仅缓存公开界面资产。

## 离线对话补交

手机为每段对话及每轮生成稳定随机 ID（标识），加密保存用户与助手正文、时间及当前清理代次。电脑重新可达后，先同步授权／删除状态，随后补交。宿主绑定当前账户和设备，按受信物理设备身份（不随 Cookie〔会话凭据〕续期改变）＋轮次 ID 幂等核对摘要；相同重试返回原回执，不重复形成，不同正文复用 ID 返回冲突。补交转换成现有 `ingest_boundary` 的真人／助手来源，召回提示和副本正文永不进入该来源数组。MemoWeft 原有持久任务负责形成；没有形成成功证据时只显示「已同步」，不称「已记住」。

M3-A 聊天不会执行电脑任务；D17 / D40 的加密任务接收由下方 S7 承担。离线顶部与输入区显示「电脑离线，可以继续聊，也可以记下要做的事，等电脑上线后去做」。重新在线补交完成显示「已同步」，正常状态保持安静。

助手回复额外保留实际召回与近期回合继承的记忆标识，补交时映射到 Core 原生 `model_context_dependencies`（模型上下文依赖）。这样已同步的助手回复也参加 FG-1 / FG-2 遗忘级联；只有原始新对话进摄取，标识不被伪装为真人说过的内容。近期电脑窗口无法完整追溯的依赖明确标记为 `unavailable`（不可得）。真实 Core 的补交→遗忘→上下文消失与文件字节扫描见 `core-forget.json`。

## 验证与交付边界

测试使用合成账号、临时目录、随机端口、本地云与中继；不触碰日用宿主、8081 或生产云。覆盖密文篡改／错设备、权限过滤、增量、遗忘／撤权清理和旧补交拒绝、补交幂等及只发送相关记忆。真实桌面宿主、手机网页、MuMu（安卓模拟器）和 MiMo 走在线同步→宿主关闭→记忆问答→新偏好→上线补交形成→新对话召回→遗忘流程。实际通过项、未通过项及用量以本包证据和结果文件为准。

实现参考：[Android Keystore MGF1 参数](https://developer.android.com/reference/android/security/keystore/KeyGenParameterSpec.Builder#setMgf1Digests(java.lang.String...))说明旧平台参数差异；本包用 Keystore AES 包裹设备私钥，保持线上的 RSA-OAEP-256 格式。

## A14 Apple 原生接线

iPhone / Mac 复用 3.19 契约，原生 Security / CryptoKit 解包，RSA 私钥和本机 AES 内容钥匙保存在 ThisDeviceOnly Keychain，普通文件仅保存密文并排除备份；稳定宿主 / 账户隔离、云 DPoP 前后核对、删除清理和幂等补交见 [A14 验证与边界](../apps/apple/Tests/Evidence/A14/README.md)。Watch 离线投影不包含审批。离线新对话与现有普通草稿 / 时间线缓存分开保存；未新增服务端接口、恢复码或服务器代管钥匙。

## S7 · 记下来，等电脑上线后去做

云端未升级时这个功能不出现：手机保留原离线聊天，菜单没有电脑事项，目标页没有空等待组；电脑不领取，也不刷错误。只信现有状态／签名回执中的 `capabilities.offlineTasks:1`，旧云字段缺失即不支持；不探测404、不永久缓存负结果，下一次登录／状态刷新重新判断。已有设备加密材料可先通过原副本预备，云升级后手机刷新即可显示入口，电脑在原撤权状态刷新后开始领取。

任务接收不依赖云聊天模型。云端明确支持任务后，新客户端在 `/offline/sync` 声明 `taskSupport:1`，没有云聊天模型时仍取得加密的电脑接收公钥、授权代次和 `taskReferences`（仅已允许的对话／项目标识与标题，不复制其正文），`model:null`。界面直接进入「记下来」方式；聊天入口不可用，但电脑上线仍按自己的模型处理任务。旧客户端不声明该字段，保持原来的 `OFFLINE_MODEL_REQUIRED` 契约。移除云聊天配置不会取消独立的电脑任务，真正的遗忘／删除仍沿清理代次处理。

每次电脑启动，未派发的已领取任务先暂停，只有云端撤权同步和原领取回执重核对成功后才进入原排队。这个授权水位只在当前进程内保存，不能从旧磁盘快照直接恢复，避免重启时用缓存的设备批准抢先执行。

离线对话「+」菜单保留「继续聊聊」，新增「交给电脑，上线后做」；选择后发送键为「记下来」。不用模型猜测任务意图：当前离线模型不提供电脑工具，也不能提交任务，明确选择可避免普通聊天被自动执行。只接受文字，最多 8,192 字；可引用副本里的近期电脑对话及其原项目，不提供附件入口。没有引用时进入目标电脑的主对话。已批准且曾连接的多台电脑，从各自本地加密副本读取接收公钥，在同一菜单明确选择电脑；默认当前／上次连接的电脑，只有一台时无需选择。未连接过的电脑先沿既有设备页在线连接一次，不能向未经认证的公钥发送内容。

设备加密沿用 M3-A 的 RSA-OAEP-256 + AES-256-GCM 信封，没有新的算法或密钥托管。电脑接收钥匙只存在 `personal-access/cloud-identity/offline-task-recipient.json`，沿私有宿主存储保护，并随既有 `cloud-identity` 排除规则不进入便携备份。公钥只经已认证的 `/offline/sync` 加密副本下发。手机用新内容钥匙加密 `{text,sessionId,projectId,createdAt}`，AAD（附加认证数据）固定绑定账户、目标电脑、物理手机身份、清理代次、随机任务 ID（标识）和接收公钥哈希。手机自己的状态摘要与重试信封仍保存在原设备加密保管库中。

云 schema（结构版本）9 仅增加 `offline_tasks`：密文、账号／设备身份、目标电脑、代次、创建／过期时间、大小、顺序、领取回执和状态。无对话／项目／正文／附件字段。单信封最多 64 KiB，每账号同时最多 100 件尚未终结事项，默认 7 天；维护轮次和每次访问都删除过期正文密文，保留「过期了，没做」的最小状态至另一周后删除；领取回执保留到执行终结，终态再保留7天。账号接口每分钟最多 120 次，电脑领取接口每分钟最多 600 次，沿既有数据库限速计数保存。新接口只走原云 DPoP（设备持钥证明）或宿主安装签名；旧客户端原接口不变。

领取使用 30 秒 lease（领取租期），同电脑已有未确认的领取时后一个连接不能越过它。电脑按云序号，先用原账户持久命令存储登记 `mode:"queue"` 与稳定任务来源，再确认领取；确认前命令不能派发。云确认事务立即删密文，回执重试返回同一结果。取消先完成则确认失败，电脑删除刚保存的正文且不执行；确认先完成则手机显示已交给电脑，取消返回 `TASK_ALREADY_RECEIVED`，此后沿原任务停止接口。重启继续确认已持久保存的命令，重复领取沿任务 ID 查找原命令。DSH（助手运行时）仍负责原生执行、恢复与审批；此处不承诺外部副作用严格恰好一次，原生结果不明仍待确认，不能另起任务重放。

执行权限依赖原本已批准的物理手机、账号执行权、当前对话／项目与清理代次。已登记意图不依赖创建时 Cookie（会话凭据）的剩余寿命；撤权、账号退出和授权版本改变仍拒绝执行。普通工具审批及手机审批推送路径不变，来源不增加任何允许规则。对话删除／遗忘沿 M3-A 保守推进整份清理代次，云触发器删除该电脑旧代次任务；未派发的本地任务同步删除，手机下次核对时清除摘要、密文与旧钥匙。退出手机账号删除该设备所有云端任务。

目标页在「进行中」内显示「等电脑上线」：摘要、交代时间、原对话入口和菜单内取消二次确认。对话消息下显示「已记下，等电脑上线」→「电脑已开始」→「做完了／没做成」，以及「已取消／过期了，没做」。电脑消息沿原回执显示「在手机上离线交代，X 时上线后开始」，执行记录仍为原任务。通知沿 S3a（既有通知通道）使用原动态和通知决定；离线任务通知标题／正文固定通用文案，云与推送提供方只收到 `{eventId,type}`。现有 NoopPushProvider（未配置的推送提供方）仍明确未配置，不能把提供方受理或前台读到状态称为系统已显示。

Android（安卓）四条手机云接口已在 `CloudAppCrypto.kt` 按固定云来源、精确 POST 放行，属于云账号原生通道；电脑 `claim/ack/result` 不向手机开放。`0.8.42/code55` 起原生声明 `nativeOfflineTasks:1`，接通保管库 `seal/targets/clearAccount`：只使用已认证副本中的电脑接收公钥，原生核对账号、电脑、代次及物理设备；同账号各电脑的本地加密任务记录随撤权／退出清理，手机独立原话保留。任务输入不等待已断开的电脑内容通道，排队卡显示状态并提供确认取消；执行与通知仍沿原 S7/S3a 路径。旧壳不声明能力时继续隐藏任务入口，原有聊天可用。iPhone（苹果手机）仍需增加同格式保管库加密、四条云接口与对应界面。实际部署和候选验收结果按各次 PR 证据记录，不由代码能力推定。
## MOB-4 无电脑账号

手机初次登录不再以电脑／副本为前置条件。手机自填模型复用安卓安全模型库，网页自填密钥只在当前打开期间有效；对话仍使用上述加密容器和轮次结构，账号切换／退出沿原清理规则。尚无电脑时每轮核验当前云设备，不虚构记忆；系统提示明确无法操作电脑。

首次加电脑后，`phoneFirst:true` 允许没有电脑云模型也先取得清理代次、登记加密设备，再沿原 `/offline/turns` 上传。已存在的正式副本仍服从原代次／删除规则。电脑未启用记忆时保留原手机对话与待传队列，继续重试；原回执没有普通电脑会话标识，完整接力尚待后续支持。


## D63 / MEM-7 · 手机原始对话与派生数据的删除方向

手机单独聊的原对话是独立原始资料。电脑批次遗忘、记忆副本移除或清理代次变化只清派生副本，不能删除这些原始手机对话，也不能误删尚未交出的新独立对话。原电脑副本派生对话仍沿上面的保守清理规则；手机独立原文不得带旧记忆理解重新摄取。电脑接手后轻量条目不上传，全部持久接收回执后清条目、水位和摘要屏蔽，不合并。

手机删独立对话：未交轮次退出本机队列；已交／部分交轮次的删除ID加密排队，经既有 `/offline/turns` 的forgetConversations送到电脑。电脑核对该物理手机提交归属，持久登记删除墓碑，禁止旧ID复活；用同一个MEM-1来源遗忘／清理机制清电脑历史、原来源和派生记忆，再沿原云控制面推进清理代次。回执表示删除请求已接受，清理完成状态必须看forgotten，断网手机不能声称电脑已经清完。电脑整批忘掉保持手机原文。

长历史通过CLIENT_API的turnFragments完整重组，部分接收标识不等于整轮确认。待重组正文在电脑私有内容目录，完成即移除；遗忘、撤权代次变化清未完成片段，旧代次片段拒绝。没有新云正文仓库或密钥托管。
