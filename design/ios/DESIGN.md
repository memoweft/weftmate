# iPhone 设计约定

## Overview

本文件只约束 `design/ios/`，产品规则以仓库根文档为准。模式为 Operate（完成日常操作），代码原型优先。采用本人已指定的 D124 视觉方向：紧凑、顺手、过程回答分开、切换不闪；设计者按推荐选择三标签，无额外方案审批轮次。

首屏承诺：393×852 内看见一段真实样式的合成对话、明确的过程行、可输入的对话框、三个有文字的标签。看见的是在用的助手，不是宣传页。本人已认可整套设计，指定浅色系统纯白、深色系统黑；保留石墨操作色，健康页只用健康语义色。密度由统一文字起点和轻分隔控制，不依赖堆叠大卡片。

标志性交互是「随时离开，原处继续」：三个标签保留各自页面和输入；侧栏覆盖当前页而不清空内容；流式在阅读历史时停止追随；回到最新由人主动决定。边缘手势和下拉弹层提供自然返回，按钮为每种手势保留可访问的替代方式。

范围、各页 Swift 对应、全部功能和参数以 [README.md](README.md) 为实现交接。只有浏览器原型验证，原生系统动画、文字/键盘、权限和设备接受度留给 Mac 与本人 iPhone。原型的系统栏、取景框和合成数据都是示意，不当作产品能力证据。

## Colors

颜色的规范来源仍是 [tokens.json](../tokens/tokens.json)；局部映射和已认可的 iOS 增量在 [ios-prototype.json](../tokens/ios-prototype.json)。后者只进入 Apple 生成器的 iOS 条件分支，不改变电脑、安卓或手表的主题。[generate-assets.mjs](prototype/generate-assets.mjs) 将两份令牌生成到 [tokens.css](prototype/tokens.css)，生成文件不作为第二份可手改的色板。

画布、分组背景、卡片和文字采用下表 iOS 增量，不再映射电脑端的暖色 `controlCanvas`。系统原生实现用语义颜色，浏览器用固定值展示默认深浅色。遮罩与栏背景半透明色仅属于本原型。健康指标继续使用已有 `apple.colors.health*`，错误和状态使用 `danger`、`status`，不借健康颜色替换应用强调色。

| 令牌 | 浅色 | 深色 | 对应用途 |
|---|---|---|---|
| `canvas` | `#FFFFFF` | `#000000` | `systemBackground`（系统背景）：聊天、阅读页 |
| `grouped` | `#F2F2F7` | `#000000` | `systemGroupedBackground`（系统分组背景）：设置、分组列表及其系统栏 |
| `surface` | `#FFFFFF` | `#1C1C1E` | `secondarySystemGroupedBackground`（次级系统分组背景）：卡片、菜单、弹层 |
| `soft` | `#F2F2F7` | `#2C2C2E` | 气泡、搜索框等次级底 |
| `line` | `#C6C6C8` | `#38383A` | 系统灰分隔线 |
| `ink` / `secondary` / `muted` | `#1C1C1E` / `#48484A` / `#6C6C70` | `#F2F2F7` / `#D1D1D6` / `#AEAEB2` | 正文、次级文字、说明 |
| `accent` / `on-accent` | `#2C2C2E` / `#FFFFFF` | `#E5E5EA` / `#1C1C1E` | 石墨操作及反色文字 |

深色分组采用黑底上的 `#1C1C1E` 卡片，保留系统层级；浏览器固定值不代表系统提高对比度等辅助功能下的全部色值。

**The Family Rule.** 保持 D124 电脑家族的文字层级和石墨操作色；平台差异通过导航、触控和系统组件表达。

## Typography

正文沿用 `shared.fontFamily.body` 的系统中文字体栈。常用层级为说明（11–13 px）、列表（15 px）、回答（16 px）、导航标题（17 px）和页面标题（28 px）；这些是浏览器 CSS 像素，不是设备测量。页面标题和导航标题字重为 650；列表主文为 500。一般正文行高为 1.65，列表为 1.4，回答正文为 1.8。

健康恢复分数的 52 px 和画框外导览标题的 32 px 是局部展示，不扩成全站字号档。原型的「较大」文字只放大部分正文与列表，不等同于 Dynamic Type（动态字号）完整适配；系统字体替换、中文换行和读屏需原生验收。

## Layout

画框和原型专用尺寸来自 `ios-prototype.json.layout`：画框 393 × 852 px、页面左右留白 20 px、状态区 54 px、导航 52 px、标签区 60 px、底部示意安全区 24 px。普通列表最小高度为 52 px，侧栏宽 328 px，底部弹层最高为画框的 88%。宽度不超过 800 px 时隐藏外部导览，画框宽度取可用宽度与 393 px 的较小值，高度取可见视口且不超过 852 px。

这些尺寸描述浏览器预览；原生状态区、安全区、键盘占位和弹层尺寸由系统提供。原型保留三个标签各自的导航栈和已创建页面节点，局部表单与草稿随页面保留；刷新会清空合成状态。

## Elevation & Depth

日常内容靠背景层次和轻分隔线组织。`frame` 阴影仅服务于画框展示；`sheet` 阴影用于底部弹层和「回到最新回复」浮动按钮；`popover-shadow` 用于按钮旁菜单，背景不变暗。半透明导航栏与标签栏提供轻覆盖感，没有额外模糊材质；原生系统材质不由浏览器效果定义。

## Shapes

间距和圆角取自 `shared.space` 与 `shared.radius`。列表组使用 16 px 圆角，主要按钮和表单使用 12 px，输入容器使用 20 px，弹层顶角使用 26 px，侧栏右侧使用 24 px。胶囊形状用于标签选中底形、开关和浮动提示；不能据此禁止系统原生控件的形状。

## Components

主要按钮使用石墨底与反色文字，最小高度 44 px；图标按钮和分段选择也提供 44 px 触控高度。键盘焦点使用强调色描边，禁用状态降低透明度。输入容器、按钮、列表和弹层的可访问名称与状态以实际 HTML 为准，不把画出来的控件当作系统能力。

过程行与回答分开，回答直接落在画布上；侧栏和弹层覆盖当前页并隔离背景焦点，关闭后恢复原控件。图标由 `design/icons/ui/` 生成到 [assets.js](prototype/assets.js)，应用标志引用仓库已有资源。

短选择使用按钮旁菜单：加号、模型、对话/消息更多、筛选排序、现有分组/项目选择。日期和短确认使用锚定浮窗，窄屏保持浮窗。宽 276 px，离按钮 8 px，按可见空间上/下翻转，屏幕边缘横向避让；菜单项最小 44 px，圆角 16 px。仅输入表单或长内容使用底部弹层。分组/项目的「新建」进入独立表单，不把整个选择菜单扩大成上拉栏。

小菜单从按钮方向以 `dur-2`（220 ms）缩放 .92→1 并淡入，关闭反向；点击外部或 Escape 收起，方向键/首尾键选择，关闭回原触发按钮。原生使用 `Menu`，日期与短确认使用 `.popover` 配合 `.presentationCompactAdaptation(.popover)`；系统控件动效优先。完整规则与 SwiftUI 示例见 README「小菜单、浮窗与底部弹层」。

动画继续使用共有五档时长和四条曲线。原型通过 CSS 和浏览器动画模拟推进、返回、弹层与过程展开；流式调度、跟随阈值和手势阈值取自 iOS 增量。原生弹簧数值是移植建议，浏览器未运行 SwiftUI 弹簧；主动回到最新由帧回调按 `dur-3`（320 ms）与 `ease-out` 曲线计算滚动位置。运行中的过程展开，结束或停止后收起。减少动态效果时把动画与过渡缩到 1 ms，主动滚动即时完成。

## Do's and Don'ts

- **Do** 保留「随时离开，原处继续」：标签切换和外观变化保持页面、滚动和已收到的文字；手势有按钮替代入口。
- **Do** 以当前令牌文件和实际原型为取值依据，以 README 的功能表区分已演示交互与下一包原生实施建议。
- **Don't** 把合成账号、消息、健康测量、权限说明或文件示例当成真实服务已接通；本包不修改 Swift 或安卓实现。
- **Don't** 把浏览器 CSS 像素、安全区示意、字号开关、焦点模拟或动画曲线写成 iPhone 系统的验收结论。
